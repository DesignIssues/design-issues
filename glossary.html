Glossary

the words this book could not avoid

Every definition here is written for somebody meeting the term for the first time, and avoids leaning on the others. Where a chapter treats the idea properly, it is named.

URIUniform Resource Identifier
A name for something, written so that it works anywhere in the world. Web addresses are the familiar kind. The point of a URI is that it means the same thing to everybody it is given to. Chapter 2
URLUniform Resource Locator
An older word for the same thing as a URI, still in common use. This book follows its source in mostly saying URI, and treats the distinction between a name and an address as a mistake: see Chapter 3. Chapter 3
HTTPHypertext Transfer Protocol
The rules a browser and a server follow when one asks the other for a page. It says how to ask, how to answer, and what the answer means. Chapter 20
HTMLHypertext Markup Language
The format web pages are written in. Text, with tags around parts of it saying this is a heading, this is a link, this is a picture.
XML
A general way of putting tags around things, from which many formats were built. Related to HTML, and more strict: a document is either well formed or it is rejected. Chapter 17
media typealso called a MIME type
A short label saying what kind of thing a file is: a web page, a photograph, a sound recording. It travels with the file and tells the receiving program how to read it. Chapter 11
fragment identifierthe part after a #
The piece of a web address after the hash. It names a part of, or a view of, whatever the rest of the address names. It is never sent to the server: the browser that already has the page works it out. Chapter 11
schemethe part before the colon
The first word of a web address, such as https. It says which set of rules applies to the rest of the address. Chapter 4
DNSthe Domain Name System
The system that turns a name like example.org into the machine that answers for it. It is also how the Web decides who is responsible for what: owning the name means answering for what is served under it. Chapter 6
dereference
To look something up. Given a name, go and fetch what it names. Chapter 49
opaque
Something that may be used but not looked inside. A path in a web address is opaque to a browser, which passes it on without trying to work out what it means. Chapter 2
namespace
A set of terms owned by one group, so that two groups can each use the word “title” for different things without colliding. Chapter 17
vocabularyalso called an ontology
An agreed set of terms for talking about some subject, published so that anyone can use them and mean the same thing. Chapter 51
schema
A description of what a document or a set of data is allowed to contain. Used to check that something is well formed before relying on it. Chapter 17
RDFthe Resource Description Framework
A way of writing data as a pile of simple statements, each of the form “this thing has that property with this value”. Because every statement stands alone, data from different places can simply be put together. Chapter 32
triple
One statement in that form: a subject, a property and a value. “This page · was written by · Ora”. Chapter 32
graph
What a pile of such statements makes when drawn: things as dots, relationships as arrows between them. Chapter 32
Linked Data
Data published so that the things it mentions have addresses that can be looked up, and so that it points at other people’s data. Four rules, set out in Chapter 49. Chapter 49
Semantic Web
The name for the whole project of putting data, rather than only documents, on the Web. Not artificial intelligence: see Chapter 31. Chapter 30
ontology
A vocabulary, usually one with some structure saying how its terms relate to each other. Chapter 88
inference
Working out something that follows from what is already known. If every cat is an animal and this is a cat, then this is an animal. Chapter 40
Turtleand N3, its larger relative
A way of writing those statements down that a person can read. N3 adds rules and logic to it. Chapter 42
SPARQL
A language for asking questions of data written as statements, the way a database query language asks questions of tables. Chapter 30
OWLthe Web Ontology Language
A language for saying how the terms in a vocabulary relate: this kind of thing is a kind of that, no two things share this value, and so on. Chapter 34
reification
Describing a statement as a thing, so that something can be said about it. “Jane said that”, where “that” is itself a statement. Chapter 44
monotonic
A system is monotonic when adding new information never withdraws an old conclusion. It matters because on the Web anyone may add information at any time, without asking. Chapter 42
same-origin policy
The rule that code on a page from one site may not read data from another. It is what stops a malicious page raiding somebody’s bank, and what makes combining data from several places difficult. Chapter 68
CORSCross-Origin Resource Sharing
The permission a server gives so that pages from other sites may read its data, relaxing the rule above. Chapter 70
TLSand the https prefix
The encryption that protects a connection, so that nobody in between can read or alter what passes. Chapter 67
PKIpublic key infrastructure
The arrangement by which a handful of companies vouch for who owns a web address, which is how a browser decides a site is what it claims. Chapter 66
poda personal online data store
A place on the Web that holds one person’s data under that person’s control, which any application may read or write with permission. Chapter 54
Solid
The project to build that: a person’s data in one place they own, with applications kept separate from it. Chapter 54
content negotiation
The exchange in which a browser says what forms it can handle and the server picks one. It is how a single address can serve a page in the reader’s language, or a picture in a format the device supports. Chapter 10
idempotent
An operation that can be repeated without further effect. Asking for a page is idempotent; buying a book is not. Chapter 2
specificationoften shortened to spec
The document that defines a format or a protocol precisely enough that two people can build things that work together without meeting. Chapter 21
W3Cthe World Wide Web Consortium
The body that publishes many of the Web’s specifications. Founded in 1994 and directed for most of its history by the author of these notes.
RFCRequest for Comments
The numbered documents in which the Internet’s protocols are published. The name is a relic of when they really were requests for comment.
TAGthe Technical Architecture Group
A small group at the Consortium that rules on questions about how the Web fits together. Several chapters here record arguments it settled.
