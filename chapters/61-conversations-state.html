Chapter 61

Conversations and State

2000

Source Conversations and State, a Design Issues note by Tim Berners-Lee, 2000-11-01. read the original

The short version

A screen shows the current state of things, so a person can look around. A conversation only has the messages exchanged so far. The Web was built on the first model. Phones, voice and online transactions pull towards the second. We know how to check that a single message is well formed, but we have no way to check that a sequence of messages makes sense.

The question

Written for a talk to W3C’s Advisory Committee (its member body) in November 2000, this note says user interfaces and the Semantic Web were both pointing away from the Web’s founding model. Its sentence on the Semantic Web breaks off unfinished, so only the interface half survives.

Often, we notice that Web technology is now entering a field new to the Web but old of itself. In these cases, we can view the process we need to go through either has extending web technology into this field, or of Webizing the field. Conversations and state, 2000

Webizing (Chapter 26) means rebuilding a field on Web foundations. The field here is the formal specification of protocols.

61.1 What a screen is for

In theory, the note says, the Web is a mapping from URIs to representations; in experience, a space a person can navigate. What is special about a screen is not resolution but simultaneity.

A screen with a window system presents a large amount of informatoin at the same time to a person. In practice, more or less everything which a person is concentrting on at one time can be presented in its current state. Conversations and state, 2000

A window system is the familiar desktop of overlapping windows. Past roughly VGA resolution (the note says “640x320”), direct manipulation arrived: folders one could open, and drag and drop. Why it worked:

The essential things about this is that the computer is at every instant presenting the current state, whether it or the human is manipulating it. The communication betwen personand machine is in terms of the mutual manipulation of a shared state. Conversations and state, 2000

The Web was meant to extend that to remote interaction between people, in a shared space that human memory can navigate.

61.2 The other model, and its return

On terminals of 24 rows by 80 characters, work went through a command line. The user typed ls and got back a list of files, then typed the next command. The note calls this conversational: small exchanges of messages, with the state never displayed. The person imagined the folders; the computer held them unseen.

His sharpest practical point: scaling a page down to a phone screen might be choosing simply the wrong interface metaphor.

The models convert both ways. A bank balance is an agreed state computed from the transactions so far; the Paper Trail idea (Chapter 62) defines agreed state formally as a function of messages to date. Conversely, a phone-browsing service delivers a shared space as a conversation.

61.3 Why this needs formalising

ReasonWhat it would let us do
InterfacesFormalise the human-machine interfaces that are conversational, on every device without a large screen
TransactionsFormalise commercial dealings, for which a trail of messages is the most accurate model anyway
ProtocolsAnalyse the infrastructure protocols, such as HTTP, by which the information world is actually implemented

The gap he names is the same shape as the gaps named throughout Volume IV:

The standardization of XML protocols has, with XML (and RDF), a richness in terms of marshalling data formats to build on, and, with xml-schemas xforms and rdfs, a richness to draw on in terms of languages for defining valid documents, but has no basis yet for defining with equivalent power the validity (and semantics) of a sequence of interrlated messages which are a protocol. Conversations and state, 2000

Marshalling means packing data into a message for sending. XML Schema, XForms and RDF Schema are languages that say what a valid single document looks like. Put plainly: we can say what a valid message looks like. We cannot say what a valid conversation looks like.

61.4 The admission

The Web never matched its model cleanly. HTTP is stateless: each request is answered with no memory of earlier ones.

The moment it was created as a basically stateles system, many web site designers took it as their challenge to get around this model in order to create a conversational interface -- and many still do Conversations and state, 2000

It then links state to privacy:

Our concerns about privacy stem largel;y from the knowledge that our "reading" of documents is in fact done by a series of protocols which leave a trace. Conversations and state, 2000

That sentence is the bridge to Volume VII. Reading feels like looking, but it is a recorded series of exchanges.

The note names P3P, W3C’s Platform for Privacy Preferences (a Recommendation in 2002), as the attempt to measure that traffic. Its last point: on many sites a form has become the definition of a protocol, a set of valid sequences of actions. In a tax-return wizard, step three is only valid after step two.

What happened since

  • The conversational interface arrived in force. Voice assistants from 2011 onward, and chat-based AI assistants from late 2022, made the model this note describes the ordinary way many people use computers.
  • Protocol formalisation did not arrive with it. W3C attempted it with WS-CDL (2005), which saw little use. Most protocols still describe valid sequences in prose or ad-hoc state diagrams.
  • The privacy diagnosis was vindicated. The trace left by reading became the central fact of Web privacy.
  • Scaling the page down happened anyway. Responsive design (named in 2010), where one page rearranges itself for any screen width, kept the shared-state metaphor on small screens: the choice this note warns may be wrong.

Questions 4

61.1 Name an interface you use where the shared state is visible, and one where it is only in your head. Which errors does each produce (for example, forgetting which folder you are in)?

61.2 Adapting a page to a small screen may be the wrong metaphor. Describe what the right one would look like for a task you do on a phone.

61.3 List the steps of an online checkout in order. Name two sequences that should be refused (for example, paying before choosing an address). How would you write down the rule so a computer could check it?

61.4 Reading a page feels private but leaves a trace. Name another everyday action that feels like looking but is actually an exchange.
