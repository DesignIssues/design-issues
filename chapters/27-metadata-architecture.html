Chapter 27

Metadata Architecture

1997

Source Metadata Architecture, a Design Issues note by Tim Berners-Lee, 1997-01-06. read the original

The question

This note, begun in January 1997, opens Volume IV because it is where the Semantic Web starts, though it does not use the phrase. Berners-Lee says so himself in a preface added later: it was written before the roadmap of Chapter 30 and introduces the same ideas, in the historical order they arose at the Consortium, where the first driving application of machine-readable data was endorsement labels.

The definition it gives is narrower than the word’s ordinary use, and the narrowing is the point.

27.1 The definition, and the word doing the work

Metadata is machine understandable information about web resources or other things Metadata Architecture, 1997

Berners-Lee immediately says which part matters:

The phrase “machine understandable” is key. We are talking here about information which software agents can use in order to make life easier for us, ensure we obey our principles, the law, check that we can trust what we are doing, and make everything work more smoothly and rapidly. Metadata Architecture, 1997

The clause “or other things” is the seed of everything in Volumes IV to VI. He states the intention plainly: metadata was so called because it began as data about web resources, but in future it should form a basis for machine-understandable information about anything, about people, things, concepts and ideas. The first step is information about information; the design keeps the rest in mind.

27.2 The first axiom, and its consequence

Axiom. Metadata is data.

Information about information counts in all respects as information. Two consequences follow, and Berners-Lee draws both.

The first is that metadata can live anywhere. It can be stored in a resource, and one resource may carry information about itself or about another.

The second consequence is recursion without hierarchy. Metadata may itself have an owner and an expiry date, so there is meta-metadata, but the architecture does not distinguish many levels. It says metadata is data and lets the rest follow. Berners-Lee calls this a certain consistency, and it is the same move as Chapter 2’s refusal to distinguish names from addresses: one kind of thing, not a tower of kinds.

27.3 The second axiom: independent assertions

Axiom. The architecture is of metadata represented as a set of independent assertions.

Two assertions about the same resource stand alone. Grouped, they mean their logical conjunction, and since conjunction commutes, a collection of assertions is an unordered set.

The consequence is a prohibition, and it rules out a great deal of existing practice:

This design decision rules out for example, in simple sets of data, assertions which are somehow cumulative or later ones override earlier ones. Each assertion stands independently of others. Metadata Architecture, 1997

Configuration files where later rules override earlier ones, headers whose order determines what was applied to what, and formats where a flag elsewhere changes what a field means are all excluded. Chapter 32 shows what such constructs actually mean once written out as independent statements, and the answer is usually a large nested conditional that the specification never admitted to.

27.4 Assertions have a shape

The form is given by analogy with grammar: an assertion has a name or type, and a set of parameters, just as a sentence has a verb, a subject, an object and clauses. Where the subject is a resource and the assertion says it has a named property, the assertion is called an attribute of the resource.

From this the note derives what it needs: a space for attribute names, which must be global because anyone may coin one, which means URIs. The path from this paragraph to the triple of Chapter 32 is short and the note takes it without ceremony.

27.5 Self-describing information

The goal stated in the middle of the note is the one that explains why any of this was worth doing. Berners-Lee wants information that carries, with itself, enough to say what it is, so that a program meeting it for the first time can do something correct with it rather than guessing.

The rest of the note works through what was then the concrete case: PICS labels, the endorsement format whose architecture already allowed a label to be embedded, retrieved separately, or passed during the transfer. Berners-Lee uses it as the worked example of a general shape, and the generalisation is what survived. PICS did not.

What happened since

  • The general form replaced the specific one. RDF became a W3C Recommendation in February 1999, generalising the label idea into assertions about anything. PICS was superseded and formally obsoleted; the architecture described here outlived its first application by decades.
  • All three placements survive. Metadata in the document, in the transfer and in a separate description are still the three options, now as embedded structured data, HTTP headers, and separately published descriptions.
  • The authorship question was never fully answered. Who is making a statement, which section 27.2 flags as needing rationalisation, remains the weak point: most published metadata carries no indication of who asserted it, which is why Chapter 37’s treatment of trust matters.
  • The prohibition on ordering was widely ignored. Configuration formats and header conventions that depend on order remain normal, and the diagnosis in Chapter 32 still applies to them.

Connections

The quality-of-service metadata asked for in Chapter 3 and the genericity metadata of Chapter 10 are both instances of this architecture. The roadmap that supersedes this note is Chapter 30, and the assertion model it describes is drawn out in Chapter 32. The authorship question is taken up in Chapter 37, and the linking of metadata to the resource it describes returns in Chapter 49.

Questions 4

27.1 Metadata is data, so metadata can describe metadata. Show that this does not produce an infinite regress by writing three levels and saying where it stops.

27.2 Take a metadata format you use. Which of the three placements does it use, and who is making the statement in each case?

27.3 The independence axiom rules out later-overrides-earlier. Rewrite one override rule from a configuration format you know as a set of independent assertions.

27.4 “Machine understandable” is doing the work in the definition. Give an example of information about a resource that is not metadata under this definition, and say why.
