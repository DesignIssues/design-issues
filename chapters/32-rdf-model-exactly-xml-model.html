Chapter 32

Why RDF model is not exactly the XML model

1999

Source Why RDF model is not exactly the XML model, a Design Issues note by Tim Berners-Lee, 1999-01-01. read the original

The short version

Take one plain fact: this page was written by Ora. Now write it down in a structured file so a program can use it. There are at least five perfectly reasonable ways to do it.

To a person all five say the same thing. To a program they are five unrelated shapes, and a program that can find the fact in one will fail on the other four. This chapter is the clearest explanation in the book of why knowing a document’s structure is not the same as knowing what it says.

The question

Berners-Lee says why he wrote this, and the word he uses is unusual for the collection:

I wrote this note in a frustrated attempt to explain whatthe RDF model was for those who though in terms of the XML model. Why RDF model is different from the XML model, 1998

The occasion was a query language workshop where two camps had become visible: those who wanted to query documents, and those who wanted to extract the meaning and query that. This chapter is the argument for the second camp, and it is the most useful single explanation in Volume IV.

32.1 One fact, many documents, one graph

The demonstration is the whole argument. Take one assertion, that the author of a page is Ora, and write it in XML. Berners-Lee gives five renderings, all perfectly good XML, all meaning the same thing to a human reader, all producing different trees to a machine.

He then removes the crutch. Shown a tree of elements named v, x, y, z and w, a reader can say a great deal about the structure and nothing about the meaning. You cannot tell whether one value is a property of another or the reverse. You cannot even tell what real questions may be asked. The element names were a big hint, and they were a hint to the human only.

32.2 Why the mapping is hairy

There is a mapping from XML documents to semantic graphs. Berners-Lee’s word for it is hairy, and he gives four reasons.

ProblemConsequence
The mapping is many to oneA query must cover every rendering
You need the schema to know the mappingNothing can be learned from the document alone
Schemas of the day did not carry itAn inference language would have to be added
Queries over structure are longer than queries over statementsCombining two properties becomes unmanageable

The fourth is called out as the big one, with an analogy that settles it:

Think of trying to define the addition of numbers by regular expression operations on the strings. Its possible for addition. When you get to multiplication it gets ridiculous - to solve the problem you would end up reinventing numbers as a separate type. Why RDF model is different from the XML model, 1998

32.3 What a missing model looks like

The last part of the note is the most transferable, because it applies to any format, not just XML. Berners-Lee argues that if you have not gone to the trouble of making a semantic model, you may not have a well defined one, and gives four symptoms.

The jam jar. A label reads “Expires 1999”. What expires: the label, or the jam? The ambiguity is between a statement about a statement and a statement about a thing, and nothing in the format distinguishes them.

The qualifier at a distance. One element describes the author; another, elsewhere in the record, flags that “author” here means the author of the work that was translated. An inference that was safe, that a Finnish document’s author speaks Finnish, is invalidated by something in a different part of the record.

Order that means something. When the order of ostensibly independent records matters, the records are not independent. A server rule that reads “any member has access” may really mean “any member has access unless no other rule in this file matched”, and the specification said only that rules are processed in order. Written out logically, there is a large nested conditional that the specification never declared.

Unordered annotations of an ordered process. Headers saying a message is encrypted, compressed, ASCII-encoded and in HTML describe an ASCII encoding of an encrypted version of a compressed version of an HTML message. The nesting is real and the format cannot express it, so the specification carries it in fine print. Chapter 38 shows how to write it properly.

32.4 The concession about order

The note ends fairly. For a graph of knowledge, order does not matter. For a document meant to be read by a person, order is how associations are built up in a reader’s mind, and it matters a great deal. Berners-Lee suggests that reluctance to give up order comes from processing human-readable documents, and that such documents are typically not ripe for conversion anyway.

Sometimes it seems there is a set of people for whom the semantic web is the only graph which they would consider, and another for whom the document tree (or graph if you include links) is all they would consider. But it is important to recognise the difference. Why RDF model is different from the XML model, 1998

What happened since

  • The argument outlived its example. The five XML renderings are now five JSON shapes, and the problem is identical: a consumer must know the producer’s chosen structure. JSON-LD, a W3C Recommendation of January 2014, exists to attach a graph model to JSON for exactly this reason.
  • The qualifier problem was named. What this note describes as an element invalidating another is now handled by RDF-star and by annotation vocabularies, which make the statement about the statement explicit rather than implicit.
  • Order-dependent formats did not go away. Rule files evaluated in order remain the normal way to configure firewalls, routing and access control, with the nested conditional still in the prose.
  • The note’s own prediction came true the other way. Berners-Lee asks whether it would be nice to label XML so a parser could find the assertions. Schema.org markup embedded in pages does precisely that, at enormous scale, and is consumed by search engines rather than by the general agents he imagined.
