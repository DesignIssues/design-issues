Chapter 32

Why RDF model is not exactly the XML model

1999

Source Why RDF model is not exactly the XML model, a Design Issues note by Tim Berners-Lee, 1999-01-01. read the original

The short version

Take one plain fact: this page was written by Ora. Now write it down in a structured file so a program can use it. There are at least five perfectly reasonable ways to do it.

To a person all five say the same thing. To a program they are five unrelated shapes, and a program that can find the fact in one will fail on the other four. RDF records the fact itself, page · author · Ora, so every layout reduces to the same thing.

The question

Berners-Lee says why he wrote this, and the word he uses is unusual for the collection:

I wrote this note in a frustrated attempt to explain whatthe RDF model was for those who though in terms of the XML model. Why RDF model is different from the XML model, 1998

The occasion was a query language workshop where two camps had become visible: those who wanted to query documents, and those who wanted to extract the meaning and query that. This chapter is the argument for the second camp.

32.1 One fact, many documents, one graph

XML is built of elements, named tags such as <author>…</author> that nest inside one another, so a file forms a tree. An element may carry attributes, such as href="page". A parser reads the file and builds the tree; a query is a question a program asks of it.

Take one assertion, that the author of a page is Ora. Berners-Lee writes it five ways, all perfectly good XML, all meaning the same thing to a person, all producing different trees to a machine. RDF, the Semantic Web’s data model, instead stores each fact as a triple: a subject (page), a relation (author) and an object (Ora).

He then renames the elements v, x, y, z and w. The names were a big hint, and only to the human.

Of that tree a program can still ask questions such as these:

Questions about the documentQuestion about the world
Is there a w element within a details element?What is the author of page?
What is the content of the w element within the first x element?

The right-hand question can be answered only if the reader knows the document’s schema, its rules for which elements go where, and only if that schema allows few ways of saying the same thing. Berners-Lee calls each condition a big if.

32.2 Why the mapping is hairy

There is a mapping from XML documents to semantic graphs, webs of such triples. Berners-Lee’s word for it is hairy, and he gives four reasons.

ProblemConsequence
The mapping is many to oneA query must cover every rendering
The schema is needed to know the mappingNothing can be learned from the document alone
Schemas of the day did not carry itA program would need extra rules, written somewhere else, saying which layout means which fact
Queries over structure are longer than queries over statementsCombining two properties, such as books by the same author as this one, becomes unmanageable

Even one property is fragile. A schema change often adds a wrapper element, such as details above or div in HTML, which may break any query built on the old structure.

The fourth problem is the big one. The analogy needs one term: a regular expression is a pattern-matching notation for text, blind to what the characters stand for.

Think of trying to define the addition of numbers by regular expression operations on the strings. Its possible for addition. When you get to multiplication it gets ridiculous - to solve the problem you would end up reinventing numbers as a separate type. Why RDF model is different from the XML model, 1998

32.3 What a missing model looks like

The last part of the note applies to any format, not just XML. Berners-Lee argues that a format whose designers have not gone to the trouble of making a semantic model may not have a well defined one, and gives four symptoms.

SymptomExampleWhat the format never says
The jam jarA label reading “Expires 1999”Which thing expires, the label or the jam
The qualifier at a distanceAn author flagged elsewhere as the translated work’s authorThat author has changed meaning
Order that means somethingAccess rules processed in orderUnless an earlier rule has already matched
Unordered notes on an ordered processMail headers listing encodingsWhich encoding wraps which

Statements about statements

The jam jar confuses a statement about a thing with a statement about a statement. The qualifier at a distance is subtler. Normally, if a document is in Finnish, a reader may infer that its author speaks Finnish. Now a flag elsewhere in the record says that author means the author of the original, untranslated work. The inference silently fails.

Order

Independent assertions are valid one at a time and in any order, so records whose order matters are not independent. A server rule that reads “any member has access to the page” may really mean that any member has access, unless an earlier rule in this file has already matched. The specification said only that rules are processed in order. Written out logically, there is a large nested conditional that it never declared.

Mail headers saying a message is encrypted, compressed, ASCII-encoded and in HTML read as a flat list, but the truth is a nesting (Figure 32.4). Chapter 38 shows how to write it properly.

32.4 The concession about order

The note ends fairly. For a graph of knowledge, order does not matter. For a document meant to be read by a person, order is how associations are built up in a reader’s mind, and it matters a great deal. Berners-Lee suggests that reluctance to give up order comes from processing human-readable documents, and that such documents are typically not ripe for conversion anyway.

RDF can still hold a list: it breaks down into unordered statements such as “The first element of L is x”, so the order is itself recorded as facts.

Sometimes it seems there is a set of people for whom the semantic web is the only graph which they would consider, and another for whom the document tree (or graph if you include links) is all they would consider. But it is important to recognise the difference. Why RDF model is different from the XML model, 1998

What happened since

  • The argument outlived its example. The five XML renderings are now five JSON shapes, and the problem is identical: a consumer must know the producer’s chosen structure. JSON-LD, a W3C Recommendation of January 2014, exists to attach a graph model to JSON for exactly this reason.
  • The jam jar got a notation. RDF-star lets one triple be the subject of another, making statements about statements explicit. It was set out in a W3C Community Group report in 2021 and carried into the W3C’s RDF 1.2 work.
  • Order-dependent formats did not go away. Rule files evaluated in order remain the normal way to configure firewalls, routing and access control, with the nested conditional still in the prose.
  • The note’s own prediction came true the other way. Berners-Lee asks whether it would be nice to label XML so a parser could find the assertions. Schema.org, launched in June 2011, does precisely that with markup embedded in pages, at enormous scale, and is consumed by search engines rather than by the general agents he imagined.
