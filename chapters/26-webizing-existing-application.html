Chapter 26

Webizing an existing application

2017

Source Webizing an existing application, a Design Issues note by Tim Berners-Lee, 2017-03-01. read the original

The short version

To webize a system, give each of its internal names a Web address so that other systems can refer to it. Doing so often exposes names that were muddled to begin with.

The question

Volume III has been about how a system changes. This chapter closes it with the operation that changes a system into part of the Web, and Berners-Lee gives the whole procedure in one sentence:

The essential process in webizing is to take a system which is designed as a closed world, and then ask what happens when it is considered as part of an open world. Webizing existing systems, 1998

He is careful to say why this matters as much as inventing new things: not only does it bootstrap the Web from existing information, but the existing systems were researched and designed over years, and it is important not to lose the knowledge accrued in that process.

26.1 The operation

Practically, webizing a language means replacing its names, tokens and identifiers with URIs. What was previously a reference reaching only within one document or module can then reach, with equal ease, into any other.

In a clean case the URI for an object is naturally related to how it was named in the original language. His example: the element with ID foo in bar.xml becomes bar.xml#foo. It is great when the webized language closely resembles the original, and ideal when it actually compiles.

The counter-example shows how small the obstacles can be. Dan Connolly’s webizing of the Knowledge Interchange Format (KIF, a language for writing down knowledge for computers) used URIs for identifiers. KIF ignores the difference between capitals and lower case, but URIs do not: Temp and temp are different URIs. So lower-case letters had to be escaped with backslashes, turning a token such as temp into something like \t\e\m\p (an illustration, not Connolly’s exact form), which made the result less readable. Changing the underlying language in small ways, Berners-Lee concludes, can make the translation much less cumbersome.

26.2 Webizing a database

Berners-Lee’s worked example is a database. An SQL query (SQL is the standard language for questioning a database) names columns and tables that mean something only inside the database, and the database itself is nowhere mentioned, because it is context rather than content.

Prefixes are used for two reasons, he explains: writing the full URIs out each time would be cumbersome, and URIs contain characters that would clash with SQL’s own syntax. He doubts that SQL over scattered databases would optimise well, but that is not the point:

suddenly the things defined by the database are available to the outside world. Webizing existing systems, 1998

The temperature column becomes, in Berners-Lee’s words, a concept, an RDF property in fact, available for all the world to refer to. Because the schema declares it as such, systems that know nothing of SQL can use it.

Two notes for anyone publishing data

The first is that a table carries two distinct concepts. In the classic employees table:

The classEmployee, a kind of Person: what any row describes
The setSomeone works for the company if and only if they are in the table

The second is about indirection. For flexibility and security there is usually a layer between what is exposed and what is stored. A web page is not a file, though it has the same form, a string of bytes and a MIME type; a remote operation is not a local procedure, though it has the same form, a service URI, a method name and parameters. Likewise a published database should usually be a derived view that still has the form of a database. Then the external form can be persistent and suit the consumer, and the internal one efficient and convenient for the publisher.

26.3 Where it gets hard

The difficult case is nesting. Where a language relies on nested scopes, the context at one end of a link can be completely different from the context at the other. Berners-Lee reaches for Dijkstra: the objection to the goto statement (an instruction that jumps to any other line of a program) was that it is too primitive and too much an invitation to make a mess of one’s program. That is true of the hypertext link too, in a way, he concedes. Used without restraint, both remove the rules that give a language sanity, analysability and optimisability.

So, just as some languages forbid jumping into an inner loop, it may make no sense to allow a link into something deeply nested, because the thing referred to has no meaning out of context. The language must then either define how the inner thing is represented independently of its context, or make such links impossible. But he warns against jumping to that conclusion. In a three-dimensional scene language an object may sit within a scene within an object and still have an identity worth referring to. And the governing principle does not bend:

The principle that on the Web, anything must be able to say anything about anything means that these innermost nested objects must have URIs. Webizing existing systems, 1998

26.4 The diagnostic use

Webizing is a test as much as a transformation. If a name means quite different things in different contexts, the language is not suitable for webizing as it stands, and either two derived URIs should be minted or the language should be cleaned up so the concepts are distinct.

Berners-Lee gives a human example: a documentation control system where people use one name, “the pipe size draft”, both for a particular document and for the set of documents it belongs to. Those are two things, needing two URIs.

He leaves an exercise, to examine XML schemas and ask what the URI of an element type is (every <p> in an HTML page is an element of the type p), and closes with the best advice in Volume III:

When stuck, recourse to common sense. Ask what the construct actually represents in a global context, if anything. Webizing existing systems, 1998

What happened since

  • Databases were webized, by specification. R2RML, a language for mapping relational data to RDF, became a W3C Recommendation in September 2012, which is section 26.2’s example turned into a standard.
  • A default mapping too. A Direct Mapping of Relational Data to RDF, which gives every table, column and row a URI automatically, became a W3C Recommendation on the same day, 27 September 2012.

Questions 4

26.1 Take a configuration format you use and webize it. What is the URI of a setting, for example one line in a settings file? What breaks?

26.2 Section 26.2 distinguishes the kind of thing a row describes from the set of rows present. Give a table where conflating the two produces a false statement.

26.3 Some languages forbid jumping into the middle of a loop. Why might a format forbid links into the middle of a nested structure, and when would that be wrong?

26.4 Webizing reveals names that mean different things in different contexts. Find one in a system you work on, and say whether the right fix is two identifiers or one clearer concept.
