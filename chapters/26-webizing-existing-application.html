Chapter 26

Webizing an existing application

2017

Source

This chapter is about Webizing an existing application, a Design Issues note by Tim Berners-Lee, dated 2017-03-01.

Read the original at https://www.w3.org/DesignIssues/Webize.html. The Design Issues notes are Tim Berners-Lee's personal notes and are not endorsed by W3C. This book is commentary; where it quotes, it attributes.

The question

Volume III has been about how a system changes. This chapter closes it with the operation that changes a system into part of the Web, and Berners-Lee gives the whole procedure in one sentence:

The essential process in webizing is to take a system which is designed as a closed world, and then ask what happens when it is considered as part of an open world. Webizing existing systems, 1998

He is careful to say why this matters as much as inventing new things: not only does it bootstrap the Web from existing information, but the existing systems were researched and designed over years, and it is important not to lose the knowledge accrued in that process.

26.1 The operation

Practically, webizing a language means replacing its names, tokens and identifiers with URIs. What was previously a reference reaching only within one document or module can then reach, with equal ease, into any other.

He notes what a good webizing looks like: the URI for an object should be naturally related to how the object was named in the original language, so that the element with a given identifier in a file is that file's URI plus a hash plus the identifier. It is great when the webized language closely resembles the original, and ideal when it actually compiles.

The counter-example he gives is instructive about how small the obstacles can be. Dan Connolly's webizing of the Knowledge Interchange Format used URIs for identifiers, but since URIs are case sensitive and the format's tokens were not, lower case letters had to be escaped with backslashes, which made the result less readable. Berners-Lee's conclusion is that changing the underlying language in small ways can make the translation much less cumbersome.

26.2 Webizing a database

The worked example is the most concrete thing in the chapter. A query names columns and tables that mean something only inside the database, and the database itself is nowhere mentioned, because it is context rather than content.

Webized, the pieces of the database get URIs, prefixes are introduced, and a query can join a local table to a remote one. Berners-Lee is candid that his invented syntax is probably wrong and that querying scattered databases this way may not optimise well. The point is what becomes available:

suddenly the things defined by the database are available to the outside world. Webizing existing systems, 1998

A column that was a private notion of temperature reading becomes, in Berners-Lee's words, a concept, an RDF property in fact, which is available for all the world to refer to. Because the schema declares it as such, systems that know nothing of the original query language can use it.

Two notes follow that anyone exporting data should read. The first is that a table carries two distinct concepts: the kind of thing a row describes, and the set of things actually in the table. In the classic employees table there is a class of employee, and separately the fact that someone works for the company if and only if they are in the table.

The second is about indirection. Just as a web page is not a file though closely related to one, a published database should usually be a derived view, so that different engineering decisions can be made about the external form, which must be persistent and suit the consumer, and the internal one, which must be efficient and suit you.

26.3 Where it gets hard

The difficult case is nesting, and Berners-Lee reaches for Dijkstra to explain why. The objection to the goto statement was that it is too primitive and too much an invitation to make a mess of one's program. He concedes the same of the hypertext link, and draws the parallel exactly: both open a webbed world that removes the rules giving a language sanity, analysability and optimisability.

So it may make no sense to permit a link into something deeply nested, because the thing referred to has no meaning taken out of context. But he immediately warns against the easy conclusion. In a three-dimensional scene language an object may sit within a scene within an object and still have an identity worth referring to. And the governing principle does not bend:

The principle that on the Web, anything must be able to say anything about anything means that these innermost nested objects must have URIs. Webizing existing systems, 1998

26.4 The diagnostic use

The most useful observation in the note is that webizing is a test as much as a transformation. If a name means quite different things in different contexts, the language is not suitable for webizing as it stands, and either two derived URIs should be minted or the language should be cleaned up so the concepts are distinct.

Berners-Lee gives a human example: a documentation system where people use one phrase for a particular document and also for the whole set of documents it belongs to. The sentence trails off unfinished in the original, which rather proves the point.

He leaves an exercise, to examine XML schemas and ask what the URI of an element type is, and closes with the best advice in Volume III:

When stuck, recourse to common sense. Ask what the construct actually represents in a global context, if anything. Webizing existing systems, 1998

What happened since

  • Databases were webized, by specification. R2RML, a language for mapping relational data to RDF, became a W3C Recommendation in September 2012, which is section 26.2's example turned into a standard.
  • The joke row came true. The table lists “Goto Considered Harmful” becoming “Goto drives the economy”. The hyperlink is the economy's basic unit of navigation, and the objection Dijkstra raised has never been answered for it.
  • The diagnostic use spread furthest. The discovery that a name means different things in different contexts, found by trying to give it a global identifier, is now the routine first finding of any data integration effort, whether or not URIs are used.
  • The derived-view advice became standard practice. Publishing an API over a stable external model rather than exposing internal storage is ordinary, and the reason is the one given here.

Questions 4

26.2 Section 26.2 distinguishes the kind of thing a row describes from the set of rows present. Give a table where conflating the two produces a false statement.

26.3 Berners-Lee accepts Dijkstra's objection and applies it to the link. What does a language lose when arbitrary inward references are permitted?
