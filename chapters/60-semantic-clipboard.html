Chapter 60

The Semantic Clipboard

2004

Source The Semantic Clipboard, a Design Issues note by Tim Berners-Lee, 2004-01-01. read the original

The question

A short note from January 2004 built around one wish that Berners-Lee says he has quoted often:

An example I have often quoted is that I would like to be able to drag a photo album onto a calenar application and see the photos on my calendar. Semantic Clipboard, 2004

The interest is in what he does next, which is to take the wish seriously and ask what would actually have to exist.

60.1 The hard version of the problem

The note sets its own difficulty deliberately. The two applications were written independently, without this case in mind, by people who never spoke. Both store their data as a graph and both have vocabularies for what they deal in. Nothing else is assumed.

Berners-Lee then observes something about the clipboard that most people have never thought about, and it is the key to the whole design:

The clipboard, which stores things which we copy and paste, is a complex thing. It doesn't always hold the value of something clipped, it sometimes just remembers where it was clipped from. There is a form of negotiation between the source and destination about the format for the data to be transferred. Semantic Clipboard, 2004

Copying from a page into a plain message works because the two ends negotiate down to a format they share. The clipboard is already a content negotiation mechanism, and has been since before anyone called it that.

60.2 What has to be added

60.3 Entropy

The most interesting observation in the note is about what conversion costs, and it generalises well beyond clipboards:

There is a form of entropy which increases as these rules are used. Some rules may be reversable, but typically they are not. You can't turn every event back into a picture, and you can't event turn a picture taking event back into the picture as you have lost some data. Semantic Clipboard, 2004

Converting a photograph to a calendar entry discards the exposure settings. Converting back is impossible. An event is a more generic thing than a picture, so the conversion runs downhill.

The design consequence follows, and it is the same instinct as Chapter 10’s ladder of specificity:

One might assume that the system will in general try to reduce this information loss. This will involve trading at the highest level, or usingthe fewest rules. Semantic Clipboard, 2004

Berners-Lee then points out that this is not new. The existing clipboard already has a pecking order between a rich format and a plain one, and prefers the richer when both ends can manage it. What he is proposing is the same rule applied to vocabularies rather than to text formats.

60.4 What is actually being described

The closing assessment is modest about the artefact and immodest about what it implies:

The Semantic Web clipboard might be a nifty hack in the short term, might be a mainstay of desktop interoperability in the future. From the reseacrh point of view, the rule management involved is a miniature version of the Semantic Web rule indexing search engine. Semantic Clipboard, 2004

A clipboard that must hold rules, index them by what they convert, choose the path that loses least, and track who supplied each one, is the whole conversion layer of Chapter 30 shrunk to fit one machine. The small version is tractable because the rule set is small and the user can be asked.

What happened since

  • A prototype was built. The note carries an update pointing at a Semantic Clipboard project from 2009, which implemented the idea in a browser.
  • The general problem was solved by convention. Sharing between applications on modern systems works through a small fixed set of declared types rather than through conversion rules, which is a narrower answer that requires no trust decisions.
  • Personal automation arrived with the rule question unanswered. Tools that let people wire one application to another became popular from the 2010s, and the question of who wrote the connector, and what it discards, is still answered by the user clicking accept.
  • Entropy was not managed. Nothing in common use chooses a conversion path to minimise information loss; conversions are chosen by whatever connector is available.

Connections

The conversion layer this miniaturises is Chapter 30. The ladder of specificity that makes some conversions lossy is Chapter 10, and content negotiation is its mechanism. The vocabularies being converted between are Chapter 51, and the trust decision about rule sources is Chapter 66.
