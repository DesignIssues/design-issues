Chapter 60

The Semantic Clipboard

2004

Source The Semantic Clipboard, a Design Issues note by Tim Berners-Lee, 2004-01-01. read the original

The short version

The clipboard already negotiates a format that both ends of a copy and paste understand. A Semantic Web clipboard would also convert data between the vocabularies of different applications, using rules. The hard parts are deciding which rules to trust and limiting what each conversion loses.

The question

A short note from January 2004 built around one wish that Berners-Lee says he has quoted often:

An example I have often quoted is that I would like to be able to drag a photo album onto a calenar application and see the photos on my calendar. Semantic Clipboard, 2004

60.1 The hard version of the problem

The note sets a hard case: two applications written independently, without this case in mind. The only assumption is that both are “semantic-web aware”: each has its own vocabulary (an agreed set of terms, such as “start time”) for what it deals in, and each keeps a copy of its data in RDF, as a graph (a web of simple statements linking things to their properties).

The key to the design is something about the clipboard most people never notice:

The clipboard, which stores things which we copy and paste, is a complex thing. It doesn't always hold the value of something clipped, it sometimes just remembers where it was clipped from. There is a form of negotiation between the source and destination about the format for the data to be transferred. Semantic Clipboard, 2004

Copying from a page into a plain message works because the two ends negotiate down to a format they share. Content negotiation means exactly this: the sender offers several forms, the receiver says which it accepts, and they settle on one.

60.2 What has to be added

He proposes a new clipboard type in which the data travels as an RDF graph. But each application speaks its own vocabulary. The calendar can use anything with at least a start time and a description. The photograph has a creation date, perhaps a description, and technical details of the exposure.

So the clipboard must also convert. The user authorises conversion rules for it to use. Applications register what kind of information they need; the clipboard indexes the rules, looks at what it is holding, and matches what is on offer to what is wanted. The rules are usually personal. One user might want the event for a photograph to list the people in the shot; another might want just “Pic!”.

The note lists where rules might come from:

  • an advanced user, much as people write email filters;
  • a third party such as a system administrator;
  • the author of either application.

The program released second would normally ship the rules linking it to the older one, so rules tend to run in one direction. If both later offer a rule for the same conversion, the user must choose, as when deciding whether to trust the printer maker’s driver or the operating system’s.

60.3 Entropy: conversion only loses

The note’s most general observation is about what conversion costs. Entropy is a physicist’s word for disorder that only increases. Here it means information lost on the way, which cannot be got back.

There is a form of entropy which increases as these rules are used. Some rules may be reversable, but typically they are not. You can't turn every event back into a picture, and you can't event turn a picture taking event back into the picture as you have lost some data. Semantic Clipboard, 2004

An event is a more generic thing than a picture, so conversion runs downhill. The design consequence is the same instinct as Chapter 10’s ladder of specificity:

One might assume that the system will in general try to reduce this information loss. This will involve trading at the highest level, or usingthe fewest rules. Semantic Clipboard, 2004

Clipboards already prefer rich text to plain when both ends manage it; he applies the same rule to vocabularies.

60.4 What is actually being described

The close looks beyond the clipboard:

The Semantic Web clipboard might be a nifty hack in the short term, might be a mainstay of desktop interoperability in the future. From the reseacrh point of view, the rule management involved is a miniature version of the Semantic Web rule indexing search engine. Semantic Clipboard, 2004

Such a clipboard must hold rules, index them, choose the path that loses least, and track who supplied each one: the conversion layer of Chapter 30 in miniature. On one computer the rules are few and there is one user to ask. On the whole Web they are countless and there is nobody to ask. The clipboard is a small, safe place to try the problem.

What happened since

  • A prototype was built. The note carries an update pointing to the 2009 Semantic Clipboard project by Oshani Seneviratne, in MIT’s Decentralized Information Group (DIG).
