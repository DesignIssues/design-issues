Chapter 60

The Semantic Clipboard

2004

Source The Semantic Clipboard, a Design Issues note by Tim Berners-Lee, 2004-01-01. read the original

The short version

The clipboard already negotiates a format that both ends of a copy and paste understand. A Semantic Web clipboard would also convert data between the vocabularies of different applications, using rules. The hard parts are deciding which rules to trust and limiting what each conversion loses.

The question

Berners-Lee says he has often quoted one wish: to drag a photo album onto a calendar application “and see the photos on my calendar.” This January 2004 note offers it as an example of one way of looking at the Semantic Web, as a breaking down of barriers between applications, and then asks: “What would this actually take?”

60.1 The hard version of the problem

The interesting case is the hard one: neither program was written with the other in mind. The note assumes only that both are “semantic-web aware”: each has its own vocabulary for what it handles, photos or events, and keeps a copy of its data in RDF.

The key is something about the clipboard most people never notice:

The clipboard, which stores things which we copy and paste, is a complex thing. It doesn't always hold the value of something clipped, it sometimes just remembers where it was clipped from. There is a form of negotiation between the source and destination about the format for the data to be transferred. Semantic Clipboard, 2004

Copying from a page into a plain message works because the two ends negotiate down to a format they share. Windows still works this way: a program places its data in as many formats as it can, most descriptive first, and may put off producing one until a paste asks for it.

60.2 A clipboard that translates

He proposes a new clipboard type in which the data travels as an RDF graph, a web of simple statements linking things to their properties. But the two ends speak different vocabularies. The calendar, in an “iCalendar-like” one, can use anything with at least a start time and a description. The photograph, in an “EXIF-like” one, has a creation date, perhaps a description, and details of the exposure.

The note leaves the actual terms blank. In the real standards, a rule might read: DateTimeOriginal becomes DTSTART; ImageDescription becomes DESCRIPTION. ExposureTime and FNumber have nowhere to go.

So the clipboard must also convert, using rules the user authorises. It indexes them and matches what it holds to what each application registers as needing. The rules are usually personal. One user might want the event for a photograph to list the people in the shot; another might want just “Pic!”.

Rules might come from an advanced user, as people write email filters; from a third party such as a system administrator; or from the author of either program. The program released second would normally ship rules linking it to the older one, so rules tend to run one way. If both later offer a rule for the same conversion, the user must choose, as when deciding whether to trust the printer maker’s driver or the operating system’s. Users will have to track the trustworthiness of many sources, the note admits, “but these rules will give a lot back for something quite small.”

60.3 Entropy: conversion usually loses

There is a form of entropy which increases as these rules are used. Semantic Clipboard, 2004

Entropy here means information lost on the way for good. A few rules can be reversed, the note says, “but typically they are not.” Not every event can become a picture again; not even an event recording that a photo was taken can give back the photo, because data has been lost. An event is more generic than a picture, so conversion runs downhill. The system should therefore “try to reduce this information loss”, the note suggests, by “trading at the highest level” with the fewest rules.

The note likens this to the “pecking order between a rich text clipboard and a plain text clipboard”: the instinct of Chapter 10, which ranks formats and prefers the most specific both sides accept.

60.4 The Semantic Web in miniature

Such a clipboard must hold rules, index them, choose the path that loses least, and track who supplied each one. That is the job a Web-wide rule engine would have to do, the conversion layer of Chapter 30, and the note closes on the comparison:

The Semantic Web clipboard might be a nifty hack in the short term, might be a mainstay of desktop interoperability in the future. Semantic Clipboard, 2004

Seen as research, it adds, “the rule management involved is a miniature version of the Semantic Web rule indexing search engine.”

What happened since

  • A prototype was built. The note carries an update pointing to the 2009 Semantic Clipboard project by Oshani Seneviratne, in MIT’s Decentralized Information Group (DIG).
