Chapter 28

The meaning of a document - grounding in a global namespace

1999

Source The meaning of a document - grounding in a global namespace, a Design Issues note by Tim Berners-Lee, 1999-01-01. read the original

The short version

A document’s meaning comes from its text plus the definition of its language. On the Web both have addresses, so both can be looked up. A signature says who vouches for a document; it never changes what it says.

The question

Nobody filling in a US tax return decides what “Adjusted Gross Income on line 39 of a US IRS form 1040” means. A government department “socially owns the term”, and arguing for another reading does not help: “they just stick you in jail.” This 1999 note, written partly during the namespace dispute of Chapter 29, asks what plays that role on the Web: when a program receives a document, what fixes what it says?

28.1 Meaning is a product of two things

The meaning of a document is then the product of the text of the document (in some language) and the meaning of the language. The meaning of a document, 1999

On the Web the document and the language each have a URI, and by the rule (Chapter 2) that a URI’s owner says what it identifies, each is defined by its owner. Hence the note’s worry over the namespace dispute: if nobody can say what identifies a language, “the XML namespace mechanism may prove an insufficiently firm foundation for the semantic web”.

A language has three parts, shown here for HTML:

PartWhat it isIn HTML
SymbolsThe marks the language usesThe <h2> element
Syntactic rulesRules on how symbols may be combined<h2> needs a closing tag and sits inside <body>
SemanticsWhat the symbols mean, given in another formal language or a natural oneThe HTML specification says, in English, that <h2> is a second-level heading

28.2 Two kinds of language

Some languages are terminal: the chain of definitions ends there, in plain English, so programs for them have to be written by hand. Style is the test case: for many documentation systems “the only semantics required is ‘H2 means a big bold block on the left’!” CSS, the style-sheet language that sets how pages look, defines such things in English. Others have machine-readable definitions: a schema can state that one vocabulary’s “author” is a kind of another’s “creator”, so documents convert automatically down to a terminal language.

Natural languages are vaguer still: “no one (except Scrabble players) use a particular dictionary as a definitive set of meanings.”

In practice, the meaning of a word in a natural language is the sum of the associations of that word -- logical or poetic -- in the mind of the reader or writer. The meaning of a document, 1999

The Semantic Web, by contrast, wants languages defined formally and precisely; Chapter 22 is the later, humbler revision.

28.3 When one language can stand in for another

“Similarity” between languages means little. What is checkable: language A is a subset, or sublanguage, of language B when a document in A can be treated precisely as though it had been in B. Every XHTML 1.0 Strict document, for example, is also valid XHTML 1.0 Transitional (two editions of the Web’s page language, one strict and one permissive). Chapter 18 asks whether software accepts the smaller language; here the question is whether meaning survives.

28.4 What a signature does not do

A digital signature is a mathematical seal, made with a secret key, proving who vouched for a document and that it has not changed since. Languages define meaning only for whole documents, so a signature on page 3 of a contract needs a rule for fitting page 3 back into the whole. The signature does not define meaning:

The language defines semantics. On the simple philosophy that one place is enough, It is not the place of a digital signature to define semantics. The meaning of a document, 1999

Otherwise the signed document could say something its writer never intended. So, in a sentence Chapter 37 builds on:

So, signatures themselves have no meaning. The meaning of a document, 1999

Other documents give it one. The note’s example is a trust statement: “If an organization is a member of W3C according to a document signed with this key, then that organzation is indeed a member” (Figure 28.4).

28.5 Chains that end in a standard

Look up each term, then each term in its definition. An XHTML page’s <h2> leads to the XHTML Recommendation, which defines it, and on to the XML Recommendation it is written in: a chain that stops in W3C standards. A document is grounded if every chain ends in a set of documents one accepts. The note calls this the basis of the whole Internet stack.

28.6 Grounding as a myth: the web of meaning

Grounding makes systems predictable, but it is a bad long-run model for the Web. English words have no base set:

Every time you look one up in the dictionary all you find are more words. The meaning of a document, 1999

The world is web-like, and the note names the source: “This is the Wittgenstein view of meaning.”

Yet the note reconciles the two: “Yes, meaning is use”, but on the Internet laws and expectations constrain use to follow the specifications, as with the tax form of the opening.

Some terms are grounded, for now, in software: an invoice total means whatever the program fed the document does with it. That bootstrap will fade as many programs share the term. There will be no single Dewey decimal system (the one numbered tree libraries use to shelve every subject); forcing one would stop the Web scaling. Nor could anyone choose it:

No one will agree on a directed acyclic graph determining what terms are “more basic” than others. The meaning of a document, 1999

Instead each party picks its own base languages and defines the others it meets in terms of them: “A rich web of conversions, translations will grow up to support this.”

28.7 Two objections: use and context

“Surely meaning is only defined by use?” Some agreement outside the message is needed, the note concedes, but the Web is one big agreement: fetching a page over HTTP means accepting that it is read by the specifications.

“Doesn’t the meaning of a document depend on its context?” It does: enclosing a photocopy of a letter is not sending it. But publishing on the Web, posting to a public list or nailing a page to a tree all fix meaning the same way, and that common case is the document’s meaning.

What happened since

  • The formula became the standard account. RDF Semantics, a W3C Recommendation of February 2004, defines a document’s meaning from the meanings of its vocabulary.
  • Signing data proved to need a fixed way of writing it. RDF Dataset Canonicalization, which defines one for RDF, became a W3C Recommendation only in May 2024.
  • The confidence was revised. In 2012 (Chapter 22) Berners-Lee argued for definitions that are good enough, recording which model made them so.
