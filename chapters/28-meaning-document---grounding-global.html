Chapter 28

The meaning of a document - grounding in a global namespace

1999

Source The meaning of a document - grounding in a global namespace, a Design Issues note by Tim Berners-Lee, 1999-01-01. read the original

The short version

A document’s meaning comes from its text plus the definition of its language. On the Web both have addresses, so both can be looked up. A signature says who vouches for a document; it never changes what it says.

The question

Written in 1999, as the namespace argument came around again, this note answers the question Chapter 27 leaves: if metadata is assertions in some language, what fixes what they mean?

28.1 Meaning is a product of two things

The meaning of a document is then the product of the text of the document (in some language) and the meaning of the language. The meaning of a document, 1999

On the Web the document and the language each have a URI, and each URI’s owner says what it refers to: the identity axiom of Chapter 2.

“Language” is given a precise sense with three parts. HTML shows each of them:

PartWhat it isIn HTML
SymbolsThe marks the language usesThe <h2> element
Syntactic rulesRules on how symbols may be combined<h2> needs a closing tag and sits inside <body>
SemanticsWhat the symbols mean, given in another formal language or a natural oneThe HTML specification says, in English, that <h2> is a second-level heading

28.2 Two kinds of language

That last row matters. Terminal languages are defined only in prose, so programs for them are written by hand by someone who has read it. The note’s example is the style sheet language, which “gives a good definition (in English)”. Other languages have machine-readable definitions: a schema might state, in RDF, that one vocabulary’s “author” is a kind of another’s “creator”. Documents in these can be converted automatically until they reach a terminal language.

In practice, the meaning of a word in a natural language is the sum of the associations of that word -- logical or poetic -- in the mind of the reader or writer. The meaning of a document, 1999

In the Semantic Web, by contrast, meaning is not to be vague: languages must be defined formally and precisely. Chapter 22 is the later, humbler revision of this confidence.

28.3 Subsets, precisely

“Similarity” between languages means little; what is checkable is this: language A is a subset, or sublanguage, of language B when a document in A can be treated precisely as though it had been in B. Every XHTML 1.0 Strict document, for example, is also valid XHTML 1.0 Transitional, which only adds elements and attributes. This is the sublanguage assertion of Chapter 18, here a claim about meaning rather than a processing hint.

28.4 What a signature does not do

A digital signature is a mathematical seal, made with a secret key, proving who vouched for a document and that it has not changed since.

The language defines semantics. On the simple philosophy that one place is enough, It is not the place of a digital signature to define semantics. The meaning of a document, 1999

A signature may give someone reason to use information they would otherwise ignore. But it must not change what the document means, or the signed document could say something its writer never intended. Hence one short sentence that Chapter 37 develops:

So, signatures themselves have no meaning. The meaning of a document, 1999

Other documents must give a signature its meaning. The note’s example is a trust statement: if a document signed with this key says an organisation is a W3C member, it is one.

Languages define meaning for whole documents, so signing a fragment (part of a document) requires a rule for reassembling it into a second whole document. Chapter 24 reaches the same constraint from the processing side.

28.5 Grounded documents

Look up each term in a document, then each term in those definitions, and so on. A document is grounded if every chain ends in a set of documents one accepts; “grounded in W3C Recommendations” means every chain ends in W3C standards. The note calls this the basis of the whole Internet stack: each message’s meaning is fixed by a series of specifications.

28.6 Grounding as a myth: the web of meaning

Grounding is needed for predictable systems, but the note calls it a bad model for the Web in the long run. English words have no base set:

Every time you look one up in the dictionary all you find are more words. The meaning of a document, 1999

Both views hold, one inside the other. Meaning is use, but society constrains Internet use to follow the specifications, just as a tax form leaves no choice about what “Adjusted Gross Income on line 39 of a US IRS form 1040” means: a government department owns the term. But the Semantic Web will have no single Dewey decimal system. Everyone will define terms using others they find stable, and stable specifications stay essential, but forcing one tree would stop the Web scaling.

28.7 Two objections

“Meaning is only defined by use.” Interpretation does need some agreement outside the message, the note concedes. But the Web is one big agreement: fetching a page over HTTP means accepting that it is read by the specifications. Debate is over their details, not whether they apply.

“Doesn’t the meaning of a document depend on its context?” It does: enclosing a photocopy of a letter is not sending that letter. But publishing on the Web, posting to a public list or nailing a page to a tree all fix meaning the same way, and that common case is simply called the document’s meaning.

What happened since

  • The formula became the standard account. RDF Semantics, a W3C Recommendation first published in February 2004, fixes meaning exactly this way: an interpretation maps the vocabulary, and the document’s meaning follows from the vocabulary’s.
  • Canonicalisation proved as hard as the note implies. Signing data needs one fixed way of writing it. RDF Dataset Canonicalization, which defines one for RDF, became a W3C Recommendation only in May 2024.
  • The confidence was revised. Chapter 22, by the same author, argues instead for definitions that are good enough, with a record of which model made them so.
