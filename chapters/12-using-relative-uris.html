Chapter 12

Using Relative URIs

2011

Source Using Relative URIs, a Design Issues note by Tim Berners-Lee, 2011. read the original

The short version

A full web address says two things: where a thing lives, and what it is called there. A relative reference gives only the second part, and the reader’s software supplies the first part from wherever the document happens to be. That lets a set of files move from one computer or server to another without being edited. Berners-Lee complains that some standards (XML namespaces) and tools (Jena) took this ability away.

The question

This note is a complaint. Berners-Lee wrote it in 2011 after a discussion on the Jena bug tracker about whether his plea for relative URI support was a bug or a wish. The status line carries the exasperation:

It seems strange so long after the introduction of URIs to br writing something so basic about how they should be used, but it seems these are points which have passed some people by. Using Relative URIs, 2011

It belongs in Volume II because it is the practical half of Chapter 4. That chapter established that relative resolution is common to all schemes and explained why. This one shows what the property is worth when a library declines to support it.

12.1 Web architecture in one line

The note restates the whole mechanism:

<global id of document> # <local id of whatever> Using Relative URIs, 2011

A local identifier is a name that only means something inside one file: a heading named #intro inside a page, say, or a variable inside a program. Putting the document’s URI in front of local names makes them global, which he calls webizing (Chapter 26).

The point of relative references is that the first half can be left out. Within a document, a local identifier suffices, and the document need not contain its own address in order to refer to itself.

The same idea works between files. The note’s own example is a link from one page to another, wrapped round a picture: 

<a href="intro.html"><img src="../images/foo.png"/></a>

intro.html means “the file next to this one”; ../images/foo.png means “go up one folder, then into images”. The browser fills in the rest from wherever the page was loaded. The address it fills in from is called the base URI: normally the address the page itself was loaded from.

12.2 The argument by absurdity

The note makes the case by writing out what the alternative would look like in a programming language. Take a two-line program that sets a constant and prints twice its value:

Before: local names
pi = 3.14159265359;
print (2 * pi);
After: every name spelled out in full
<file:///users/foo/programs/play/circles.py#pi> = 3.14159265359;
print (2 * <file:///users/andys/programs/play/circles.py#pi>);

A file:///users/foo/… address is the address of a file on one person’s own computer. In the second version every use of pi carries the full address of the file it was saved in. His verdict is short: “Not practical, not the sort of thing you can copy and move around.” The example even shows the problem by accident: the two paths differ in the user name (foo, andys), the kind of breakage absolute references cause.

The fact is that throughout computer systems, local identifiers and relative filenames are very common. We loose a lot if we drop this relative feature when we move to the web. Using Relative URIs, 2011

12.3 Why the syntax looks like a file path

The resemblance to file paths is deliberate:

It isn't just coincidence that the syntax of URLs matches that of unix-like file systems. It is designed to let systems be looked at either with file:// glasses or with http:// glasses and still work. Using Relative URIs, 2011

The consequence is that a directory tree built locally can be exported to the Web unchanged, and that a file-mapped server lets ordinary command-line tools operate on the same material a browser sees. Chapter 14 takes up the problems that arise where the two views meet.

12.4 What the pattern buys

The note lists the cases. In each, an absolute URI would force an edit:

  • Viewing a directory both as local files and through a server.
  • Developing on a test system and moving to production.
  • Serving one system, such as a shared login or help system, as part of many sites.
  • Proxying part of a site from another server.
  • Handing a system to someone else to copy elsewhere.

Berners-Lee generalises the property. Many systems, including most of those he builds and uses, are better built without knowledge of their own base URI, so that the URIs they store are always relative. His own example is a project of RDF files that he processes as file:// files, browses over http:// through a web server, and edits through a proxy to a server on a different port. Every same-site link has to be relative, or one of the three views breaks. He is careful to add that not all systems are like this, and that absolute URIs must remain an option. He also notes smaller gains: relative references are easier to read, take less storage space and are shorter to transmit.

12.5 Two named failures

The note ends by naming implementations, unusually for the collection.

XML namespaces

The first is XML namespaces. A namespace declaration is the line at the top of an XML file that says which vocabulary its tags come from, and the XML rules discourage relative references there (the specification deprecates them, meaning they are allowed but should not be used). Berners-Lee’s diagnosis is that the authors envisaged a narrow set of cases in which namespace terms were stable and global while the document was local, and did not see the general need to generate relative URIs in arbitrary situations. His own command-line tool, cwm, has an option to override the rule and write relative URIs anyway. His suggested way round it is to write Turtle, a plain text format for RDF data, rather than RDF/XML (RDF written as XML).

Jena

The second is Jena, a widely used open-source library for handling RDF data. Its serialisers (a serialiser is the part of a program that writes data out as a file) emitted only absolute URIs, which he says prevents its use for a wide range of systems. The consequence:

There is a classic failure mode for RDF systems in which developers bring up a system on test.acme.com and then move it to production.acme.com and all the links break. Using Relative URIs, 2011

Best practice

  • Any library that serialises a Web format, such as HTML or Turtle, must offer relative URIs as an option or as the default.
  • Data stored in files, for example on a web server, should use relative URIs.
  • Data sent across the network, as in HTTP, should use them too.
  • Absolute URIs remain an option for the systems that need them.

What happened since

  • The namespace rule was never relaxed. Turtle, a W3C Recommendation since February 2014, gives files an @base directive and relative references.
  • Jena was slow to follow. A line in the note dated 2015 records that it still produced only absolute URIs.
