Chapter 12

Using Relative URIs

2011

Source

This chapter is about Using Relative URIs, a Design Issues note by Tim Berners-Lee, dated 2011.

Read the original at https://www.w3.org/DesignIssues/Relative.html. The Design Issues notes are Tim Berners-Lee's personal notes and are not endorsed by W3C. This book is commentary; where it quotes, it attributes.

The question

This note is a complaint, and it says so. Berners-Lee wrote it in 2011 after a discussion on the Jena bug tracker about whether his request for relative URI support was a bug or a wish. The status line carries the exasperation:

It seems strange so long after the introduction of URIs to br writing something so basic about how they should be used, but it seems these are points which have passed some people by. Using Relative URIs, 2011

It belongs in Volume II because it is the practical half of Chapter 4. That chapter established that relative resolution is common to all schemes and explained why. This one shows what the property is worth when a library declines to support it.

12.1 Web architecture in one line

The note restates the whole mechanism compactly enough to memorise:

<global id of document> # <local id of whatever> Using Relative URIs, 2011

Berners-Lee calls the operation webizing: take a system with local identifiers, prepend the URI of the document those identifiers live in, and they become global. Hypertext becomes the Web. Data files become the Web of Data.

The point of relative references is that the first half can be left out. Within a document, a local identifier suffices, and the document need not contain its own address in order to refer to itself.

12.2 The argument by absurdity

The note's best passage makes the case by writing out what the alternative would look like in a programming language. A two-line program that sets a constant and prints twice its value becomes: 

<file:///users/foo/programs/play/circles.py#pi> = 3.14159265359;
print (2 * <file:///users/andys/programs/play/circles.py#pi>);

Berners-Lee's verdict on it is four words: not practical, not the sort of thing you can copy and move around. The example carries an accidental demonstration of the very problem, since the two paths differ in the user name, which is exactly the class of breakage absolute references produce.

The fact is that throughout computer systems, local identifiers and relative filenames are very common. We loose a lot if we drop this relative feature when we move to the web. Using Relative URIs, 2011

12.3 Why the syntax looks like a file path

One sentence settles a question readers often assume is an accident of history:

It isn't just coincidence that the syntax of URLs matches that of unix-like file systems. It is designed to let systems be looked at either with file:// glasses or with http:// glasses and still work. Using Relative URIs, 2011

The consequence is that a directory tree built locally can be exported to the Web unchanged, and that a file-mapped server lets ordinary command-line tools operate on the same material a browser sees. Chapter 14 takes up the problems that arise where the two views meet.

12.4 What the pattern buys

The note lists the cases, and they are worth keeping as a checklist because each one is a situation where an absolute URI would force an edit:

  • Viewing a directory both as local files and through a server.
  • Developing on a test system and moving to production.
  • Serving one system, such as a shared login or help system, as part of many sites.
  • Proxying part of a site from another server.
  • Handing a system to someone else to copy elsewhere.

Berners-Lee generalises the property: such a system is better built without knowledge of its own base URI, because for its local identifiers there are no absolute URIs, only whatever the base happens to be today. He is careful to add that not all systems are like this, and that absolute URIs must remain an option.

12.5 Two named failures

The note ends by naming implementations, which is unusual for the collection and is the reason it reads as a complaint rather than an essay.

The first is XML namespaces, which forbid relative references in namespace declarations. Berners-Lee's diagnosis is that the authors envisaged a narrow set of cases in which namespace terms were stable and global while the document was local, and did not see the general need to generate relative URIs in arbitrary situations.

The second is Jena, whose serialisers at the time emitted only absolute URIs, which he says prevents its use for a wide range of systems. And the consequence, stated as the failure mode practitioners will recognise:

There is a classic failure mode for RDF systems in which developers bring up a system on test.acme.com and then move it to production.acme.com and all the links break. Using Relative URIs, 2011

The recommendation is correspondingly blunt: any library that serialises a Web format must offer relative URIs as an option or a default; data stored in files should use them; data sent across the network should use them.

What happened since

  • The XML namespace rule was never relaxed. Relative references in namespace declarations remain deprecated, and the working answer for RDF users is the one given here: use Turtle rather than RDF/XML, which permits a relative base.
  • Turtle made the base explicit. Turtle became a W3C Recommendation in February 2014 with an @base directive and relative reference support, which is the capability this note asks serialisers to provide.
  • The complaint was partly answered. The note records in a line dated 2015 that Jena still did not generate relative URIs, four years after it was written. Relative output is now available in common RDF toolchains, though rarely the default.
  • The failure mode survives its cause. Moving a system between hostnames still breaks absolute identifiers, and the practice of minting identifiers from a deployment hostname remains widespread in systems that have nothing to do with RDF.

Questions 4

12.1 The note argues a system is often better built without knowing its own base URI. Name a case where a system must know it, and say what it is doing that requires it.

12.2 XML namespaces forbid relative references. Reconstruct the argument for that prohibition as its authors would have made it, then say what it costs.

12.3 A dataset is published with absolute URIs under a test hostname. Describe what breaks on promotion to production, and which of the breakages a redirect can repair.

12.4 Relative references make a document portable and make its identifiers depend on where it is served from. State when that dependency is a defect rather than a feature.
