Chapter 40

Logic and the semantic web

1999

Source Logic and the semantic web, a Design Issues note by Tim Berners-Lee, 1999. read the original

The short version

Any system that reasons faces a trade: the more it can express, the harder it is to work out answers. Decades of research went into trying to have both.

This chapter keeps the expressive power and gives up the fast reasoner, because checking a proof is easy even when finding it was not. A maths teacher cannot always solve a hard problem, but can check a worked solution line by line. The Web only asks its programs to be teachers.

The question

Volume V opens with the note in which Berners-Lee reads the logic literature and reports back. He is candid about his standing:

A problem here is a that I am no logician, and so I am am having to step like a fascinated reporter into this world of which I do not possess intimate experience. The Semantic Web as a language of logic, 1999

The question is what kind of logical system the Web needs, and the answer turns on giving up something that every earlier system treated as essential.

40.1 Five requirements, and the one that has to go

A knowledge representation system is a program that stores facts in a strict form so that a computer can draw conclusions from them. For example:

Every invoice over £1,000 needs approval. Invoice 17 is for £1,200. So invoice 17 needs approval.

The note quotes Crawford and Kuipers on what such a system must have: a compact syntax, well-defined semantics, enough expressive power to represent human knowledge, an efficient and understandable reasoning mechanism, and usability for large knowledge bases. Expressive power means how many kinds of statement like the first line the language lets a writer express. Efficient reasoning means how quickly a program gets from the first two lines to the third. Then the observation that sets up everything:

It has proved difficult, however, to achieve the third and fourth properties simultaneously. Crawford and Kuipers, quoted in The Semantic Web as a language of logic, 1999

Berners-Lee chooses expressive power, and says exactly what is surrendered: the parts of the fourth requirement that conflict, notably a single efficient reasoning system.

40.2 A validator, not a prover

He offers a precedent, the argument of Volume I arriving in a new field:

(This fundamental change goals from KR systems to the semantic web is loosely analogous with the goal change from conventional hypertext systems to the original Web design dropping link consistency in favor of expressive flexibility and scalability. The Semantic Web as a language of logic, 1999

Hypertext gave up the guarantee that links resolve; logic gives up the guarantee that questions are answerable. Each guarantee had kept its system small.

40.3 Tractability by subsetting

Efficiency is arranged in parts. A problem is tractable when a program can solve it in a reasonable time. Berners-Lee lists five ways to carve a tractable subsystem out of an intractable whole:

MethodWhat it restrictsEveryday example
Subset the languageremoves operations, axioms and rulesa spreadsheet that can add and compare but not loop
Limit the sourcesonly statements from particular documents or sitesa shop’s app trusts only its own catalogue
Constrain the formschemas fix the shape of formulaean order form that takes only a product code and a quantity
Design the applicationchoices that guarantee tractable results with common reasoning enginesa booking site that asks only questions a database answers quickly
Hand-build the proverproofs come from application-specific programsa payroll program written for one calculation

His own example is Access Limited Logic, which, as he understands it, uses only relations r(a,b) that are available when r is accessed, and whose rules only chain forward along such links. The work therefore depends on local connections, not on the size of everything known.

What the whole must guarantee is correspondingly small:

  • Consistency: a contradiction cannot be deduced unless one was given.
  • Strength: all applications are subsets of it.
  • Grounding in reality.

40.4 Grounding, which is not a logical matter

What separates this note from a logic paper is grounding. It is not enough, Berners-Lee argues, to show that the system can be constrained to behave like some well-understood mathematical system. A particular mapping must be defined so that the representation conveys its meaning in a way that can be combined with everything else.

His reason for urgency was dated:

Electronic commerce needs a solid foundation in this way, and the development of the semantic web is (in 1999) essential to provide a rigid framework in which to define electronic commerce terms, before electronic commerce expands as a mass of vaguely defined semantics and ad hoc syntax which leaves no room for automatic treatment, and in which the court of law rather than a logical derivation settles arguments. The Semantic Web as a language of logic, 1999

Much of electronic commerce did grow this way. A partial counter-example is schema.org, launched in 2011, whose shared terms for products and offers many shop pages now carry.

In practice, the meaning of data is grounded in the non-Semantic-Web applications interfaced to it. A currency transfer application that accepts such input defines, for practical purposes, what the terms in the instrument mean. That is Chapter 37’s closed loop, seen from the logic side.

40.5 Rules cannot be outside the language

One requirement is derived that later chapters depend on. Most knowledge representation systems treat their inference rules, the permitted steps from one statement to the next, as different from the other information they believe. In some cases that is because the rules, such as substitution in a formula, cannot be written in the language at all. Berners-Lee observes that such rule sets are often not only redundant but arbitrary, and that a universal design must be minimalist.

Different machines will therefore use different algorithms and different rule sets. What must be shared is not the algorithm but the check:

The essential this is that the results of either must be provably correct against the same basic minimalist rules. In fact for interchange of proof, the set of rules is an engineering choice. The Semantic Web as a language of logic, 1999

Chapter 41 shows that a rule holds two separable things: a fact anyone can use, and a procedural hint only its own engine can.

40.6 Saying “that statement is false”

Logicians once hoped for languages in which every sentence was provably true or false, which meant forbidding self-contradiction. On the Web, where data is untrustworthy anyway, the note calls this a very academic problem. Systems that endorse statements must be able to say “that statement is false”, so self-contradictory loops will arise. A contradiction may be expressed but must never be derived. A program that meets one can stop trusting the source, or the public key, that supplied it.

Nor must anyone decide everything an agent could deduce, which in first-order logic is impossible. What it actually deduces depends on its engine, storage and indexes.

Keeping a language less powerful than first order predicate calculus is quite reasonable within an application, but not for the Web. The Semantic Web as a language of logic, 1999

Chapter 46 develops how a reader limits the damage once a contradiction turns up.

What happened since

  • The subsetting strategy was adopted formally. OWL (February 2004) came in three species, Lite, DL and Full; OWL 2 (October 2009) added three profiles, EL, QL and RL, each chosen so that reasoning stays tractable. That is section 40.3 turned into a standard.
  • The proof layer was never built. By 2026 there was no W3C Recommendation for exchanging proofs, so the asymmetry of Figure 40.2, which the whole design rests on, was never cashed in practice.
  • Grounding happened in applications, as predicted. What terms mean in practice is still fixed by the programs that consume them, which is the note’s fallback, not its ambition.
  • Checkability returned from another direction. The distinction between generating an answer by any means and verifying it cheaply is now central to systems built on language models, which reach conclusions unverifiably and are increasingly paired with checkers (test suites, proof assistants) whose verdicts can be relied on.
