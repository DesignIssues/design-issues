Chapter 38

Interpretaion properties for units and languages

2000

Source Interpretaion properties for units and languages, a Design Issues note by Tim Berners-Lee, 2000-02-28. read the original

The short version

A piece of text means nothing until something says how to read it. “Ora” is a Finnish name, and the note gives it three other readings. Berners-Lee argues that the way of reading it (a language, an encoding, a unit) belongs on the link between the text and its meaning, not on either end. That works for languages and encodings, but in 2001 he found no clean way to do it for datatypes in RDF, the Web’s format for data as a graph of nodes joined by labelled arcs.

The question

Are the letters “Ora” Finnish? As the first name of Ora Lassila they are, but the note links the same three letters to a Danish currency, an Old English weight and the Latin for shore. A computer handed the bare string cannot tell which reading is meant. RDF in 2000 marked language the XML way, which vanished once the file was read into the graph (RDF stores every fact as a triple: thing, property, value): “no triple would result”.

So where does a language belong, or a unit, or an encoding? The note gets the answer wrong twice before getting it right, then finds in 2001 that the right answer does not fit datatypes.

38.1 Two wrong answers and a right one

Berners-Lee’s test case is Ora Lassila, an editor of the 1999 RDF specification, and the XML attribute xml:lang is ruled out because it went “into the syntax but not into the model”.

Attempt one adds a second property to the person, namelang. It cannot say enough: nothing ties the tag to either of two names. In iCalendar, which the note cites, such a property is sometimes the language of a name and sometimes that of the object’s description. It persists because it keeps the structure flat, which is all that email headers can express.

Attempt two inserts an extra node holding the text (rdf:value) and a language tag. The note voices the confusion itself: “Clearly, ‘Ora Yrjö Uolevi Lassila’ is Finnish, is it not? Yes, Ora is Finnish, but that is different.” The graph looks tidy but is false:

After all, the string “Tim” - is that English (short for Timothy? or French (short for “Timothé”)? Interpretation properties, 1998

Attempt three makes Finnish itself the arc: Ora’s name is what results from reading the string as Finnish. The cost falls on software expecting a string: “what is the poor system supposed to do in order to accommodate finding a natural language object in place of a string?” His answer is a class that includes both.

38.2 The pattern, named

Natural languages, encodings, and similar relationships between one abstract thing and another, are best modeled in RDF as properties. I call these Interpretation properties in that they express the relationship between one value and that value interpreted (or processed in the imagination) in a specific way. Interpretation properties, 1998

38.3 Nesting puts the order in the data

Interpretation properties compose, and composition records order. Berners-Lee’s example tidies the W3C home page into standard form, takes its fingerprint, then writes the fingerprint as printable text, and the nesting states that order.

Compare this withe the HTTP situation in which the headers cannot be nested, and the encodings and compression and other things applied to the body are mentioned as unordered annotations, and the spec has to provide a way of making the right conclusion about which happened in what order. Interpretation properties, 1998

HTTP still works that way. Its current definition (RFC 9110, 2022) requires the Content-Encoding header to list the codings in the order in which they were applied: a rule about order, stated in prose.

38.4 Ten of what?

The note’s Conclusion limits its own proposal: the idea makes “a clean accurate model”, but “using the concept for datatypes in RDF is incompatible with RDF as we know it today.”

The shoe size

A datatype says how to read a string as a value: “10” as the integer ten, say. The note’s example is a shoe: 

<#myshoe> shoe:size "10" .
This doesn't tell us what it is 10 of. Interpretation properties, 1998

The simple fix is to declare that shoe:size is an integer, so that the string and the type together give the value ten. “This works.” It is what XML datatypes do, with the snag that two values cannot be compared unless their datatypes are known.

A datatype’s design decides when two values count as equal. The note lists the trade-offs as five questions (a “representation” is how a value is written), here with XML Schema’s answers as Berners-Lee understood them:

QuestionXML Schema’s answer
Can the type always be told from how the value is written? (1.4e4 and 1.4d4 differ in precision.)No
Are values of different datatypes distinct? Is 1 the same as 1.0?Yes
Is the set of datatypes extensible? Could complex or prime numbers be added?Yes
Does representation equality imply value equality?Yes
Does value equality imply representation equality? (Is only the canonical form allowed?)No

Modelling the reading as an interpretation property needs an extra node, and ordinary RDF has none. He considers two ways to supply it. The first is to change how every literal (a plain string value in the data) is parsed, so that each one gains an abstract node. He calls it frightful. The second is to treat “10” as standing for everything it could represent under some datatype. That is frightful too: if “10” stands for ten inches and ten feet alike, a shoe of ten inches and a pole of ten feet have the “same” size, so equality stops working.

He sketches a third route, keeping shoe:size as a loose link to the string and adding a property, rdf:actual, that leads to the typed value. Then comes a note to himself:

@@@ No clear way forward for describing datatypes in RDF/DAML (2001/1) @@ Interpretation properties, 1998

RDF eventually settled language tags closer to the attempt this note rejected, packaging the tag with the string.

What happened since

  • Datatypes got a working answer in 2004. The RDF Recommendations of February 2004 introduced typed literals, written "10"^^xsd:integer, which pair the string with an XML Schema datatype: the first real answer to section 38.4’s problem.
  • RDF 1.1 went further. In the W3C Recommendation of February 2014 every literal carries a datatype, and language-tagged strings have a datatype of their own. A language-tagged string’s value is a pair of text and tag, closer to attempt two than to attempt three.
  • Units. The 2006 section of the note points to a small ontology of units of measure at http://www.w3.org/2007/ont/unit, built on this pattern.
  • Nesting stayed the right answer for encodings. XML Signature, a W3C Recommendation of 2002, describes canonicalisation, digest and base-64 encoding as an ordered chain, which is section 38.3’s argument.
