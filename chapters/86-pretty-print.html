Pretty Print

2023

Source Pretty Print, a Design Issues note by Tim Berners-Lee, 2023-10-05. read the original

The question

Written in October 2023, the most recent technical note in the collection and the most domestic. Its subject is how data should be laid out when written to a file, and its argument is that legibility is a system property rather than a courtesy.

86.1 The view-source effect

The reason given first is the one that connects this note to the whole history:

The "view source effect" which allowed the web to spread though people copying and adapting each others web pages is important linked data in Solid pods too. Pretty Printing, 2023

Chapter 56 identified the four steps by which the document Web spread: copy, change, look, show someone. The first step requires that the source be readable by someone who did not write it. A format that is legible only through a tool loses the first step, and with it the others.

Berners-Lee then reports the collective experience of the field, which is a stronger claim than an aesthetic preference:

It has been the long communal experience in the internet protocol design community that simple text formats (like FTP, SNTP, HTTP, HTML, XML) have been key to adoption and understanding of new systems. Pretty Printing, 2023

And answers the obvious objection before it is raised:

So while you can ship a binary format and give everyone tools for translating it into something legible, actually is is better to ship legible formats directly across the net. Pretty Printing, 2023

86.2 Small change, small difference

The testing case is given as a separate reason and is the one that persuades implementers. Comparing what a system produced against what it should have produced is easy when both are laid out the same way and impossible when they are not.

86.3 Writing, not only reading

The note makes a point that most discussions of formatting miss, because they consider only the reader:

Legibility and aesthetic properties affect not only reading code but also people writing it. If are expressing by hand instance data, from random facts through configuration files to ontologies and rules, being able to write it in a clear, English like way also is more pleasant, and easier to check for mistakes. Pretty Printing, 2023

This is the case for the notation of Chapter 42 stated as an ergonomic argument rather than a logical one. A syntax close to a sentence is easier to get right by hand, and data written by hand is where most vocabularies and rules come from.

The last case is the most specific and the most modern:

When a group is collaborating the same same data document, such as on a whiteboard or in a chat, then legibility and writability are both important. Pretty Printing, 2023

Data gets pasted into conversations. A format that can be read in a chat window by someone without tooling is a format a team can discuss.

86.4 The argument in general

Four benefits are claimed and they are of different kinds, which is what makes the case strong rather than sentimental.

BenefitWho gains
Understanding how existing programs workA developer arriving new
Seeing what has gone wrongThe same developer, later
Readable version history and clean comparisonsEveryone maintaining it
Smaller text, sometimesThe network, marginally

Berners-Lee is honest about the last, noting it may or may not matter since the text may be compressed at another stage. The case does not rest on it.

What happened since

  • Canonical serialisation became a standard. RDF Dataset Canonicalization, a W3C Recommendation of May 2024, supplies the deterministic form section 86.2 asks for, for comparison and signing.
  • Automatic formatting became universal. Opinionated formatters that produce one layout from any input became standard practice across programming languages, which is the first requirement adopted everywhere.
  • Diff-friendliness became a format design criterion. Formats intended to live in version control are now judged on whether a small edit produces a small difference, which is the second requirement.
  • Legible wire formats held their ground. Text formats remain dominant for configuration and data interchange, with binary encodings used where volume demands, which is the balance this note argues for.
