Chapter 53

Putting Government Data on the Web

2009

Source Putting Government Data on the Web, a Design Issues note by Tim Berners-Lee, 2009-06-01. read the original

The short version

A department publishing its data should get it out now, in whatever form it has, and convert it into one common model from which every other format can be produced. It should not wait for a committee to agree terms, and should leave the attractive websites to others.

The question

“This, 2009, is the year for putting government data online,” the note begins. The American and British governments had both made public commitments toward open data, and outsiders such as mySociety, GovTrack and Watchdog.net were already publishing government data themselves, some of it as linked data. Then the note asks the officials’ question: “So if you want to do this, what should you do?” It starts with an order:

Start with the "low-hanging fruit". Whatever else, the raw data should be made available as soon as possible. Putting Government Data online, 2009

53.1 Why the government’s own website comes last

The note ranks four steps, and the one a department might start with, a polished website, comes last. First comes raw data: the records themselves, before anyone turns them into charts or reports. Second, preferably, linked data, in which each thing described, a school or a road or a payment, gets its own web address for other data to point to. Third, links to other sources. Only then an interface, if nobody outside has built one.

A department’s own site cannot compete with outside sites, for two reasons: no interface yet lets ordinary users compose their own queries, and an outside site adds value by joining the data to other data for its own purpose (Figure 53.2). Sometimes, the note grants, the government site must still give ordinary users an easy way in.

A second case concerns accountability: one agency publishes the money given to each town, another maps it against income per head there, “and so on in uncountable permutation.”

53.2 Three reasons, one technique

Government data goes online for accountability, for valuable information about the world, and for a country that works more efficiently; the note says linked data serves all three. It joins with no advance planning, as when health spending for an area meets data about the people living there to show whether a programme worked. The note does not care which formats come in or go out, only what sits in the middle. RDF is the Web’s common model for data: every statement links two things, each named by a web address. A bus is a shared connector that everything plugs into, so nothing needs a direct link to anything else. The note’s advice:

The essential message is that whatever data format people want the data in, and whatever format they give it to you in, you use the RDF model as the interconnection bus. Putting Government Data online, 2009

SPARQL is the query language of this toolkit: a program anywhere can send a question to a SPARQL service and get the answer back as RDF, XML, sometimes JSON or CSV. A query joining data from different sources can be encoded into one long URI, “a URI for a virtual XML document for that particular view”. Any view across the data thus gets its own address that anyone can link to or fetch.

The note admits the difference is hard to see for those who know other technologies, and stops arguing: “Sometimes it is better just to do it.”

53.3 Two philosophies, and the one that finishes

The note says there are two ways to begin. The first needs an ontology, an agreed list of terms and what each one means:

The top-down one is to make a corporate or national plan, by getting committees together of all the interested parties, and make a consistent set of terms (ontology) into which everything fits. This in fact takes so long it is often never finished, and anyway does not in fact get corporate or national consensus in the end. Putting Government Data online, 2009

The alternative concedes what the top-down approach is for:

A top-level mandate is extremely valuable, but grass-roots action is essential. Put the data up where it is: join it together later. Putting Government Data online, 2009

A mandate from the top supplies permission (Chapter 51’s first star, and the hardest thing to obtain), not the vocabulary.

53.4 Mixing vocabularies

A vocabulary is a set of shared terms for describing data. The note recommends terms others already use: foaf:name for a person’s name, dc:title for a title, geo:lat and geo:long for position. The prefix names the vocabulary: FOAF (“friend of a friend”) for people, Dublin Core for documents. A department uses international terms where they exist and local ones for the rest.

The Linked Data technology, unlike any other technology, allows any data communication to be composed of many mixed vocabularies. Each vocabulary is from a community, be it international, national, state or local; or specific to an industry sector. This optimizes the usual trade-off between the expense and difficulty of getting wide agreement, and the practicality of working in a smaller community. Putting Government Data online, 2009

53.5 From whatever exists to linked data

A full inventory first is wise and cautious, the note says, but it may take longer than just doing it.

Leave the existing system alone

The most important rule is not to disturb the systems, or the people, responsible for the data. Putting a dataset together “often takes years of negotiation”, and there are “social as well as technical systems” to protect. Extract the data with the export facilities it already has and add “a thin shim” to adapt it to the standard. Nor should a public server run on the live database unless it is built for heavy use; serve a copy instead.

A worked example

For the proprietary case the note sketches the whole job. Give each book and shelf a web address, such as http://id.example.com/id/isbn/123457890 and http://id.example.com/id/shelf/746; then write a small script that, given one of these addresses, returns that thing’s data as RDF, with its shelf or its books. That script is the department’s linked data server.

What the note does not ask for

The note does not argue that all data should be public. Personal data will probably not be an early choice, though converting data that is already public, with privacy settled, is an excellent idea. Each dataset’s licence should be machine-readable, using the Creative Commons cc:license term or the CC0 waiver.

What happened since

  • The portals arrived around the note. The American data portal, data.gov, opened in May 2009, a month before it. On 10 June 2009 Gordon Brown told the Commons he had asked Berners-Lee to help open up British government data; Nigel Shadbolt joined him, and data.gov.uk followed in January 2010.
