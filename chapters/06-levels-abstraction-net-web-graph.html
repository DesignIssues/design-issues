Levels of Abstraction: Net, Web, Graph

2007

Source

This chapter is about Levels of Abstraction: Net, Web, Graph, a Design Issues note by Tim Berners-Lee, dated 2007-10-23, about 1,123 words.

Read the original at https://www.w3.org/DesignIssues/Abstractions.html. The Design Issues notes are Tim Berners-Lee's personal notes and are not endorsed by W3C. This book is commentary; where it quotes, it attributes.

The question

Nine years after the survey of Chapter 5, Berners-Lee wrote this note with an unusually frank status line: it was written, he says, in response to another round of circular discussions of Web architecture. It is short, it contains no new mechanism, and it closes Volume I because it supplies the thing the earlier notes lack, which is a reason why the layering is the way it is.

The claim is that the Web's layers are not layers of technology. They are layers of social responsibility, and each one borrows the accountability of the one beneath.

6.1 Three refusals

The note advances by rejecting three answers in turn, and the rhetorical shape is the content.

It is not the wires. When computers were connected by telephone lines, one ran a program to connect to a particular machine, and to reach a third machine one had to know how to drive the second. Mail travelled by machines calling each other at night, and addresses named the route: Berners-Lee gives the example timbl@mcvax!cernvax!cernvms. The Internet removed the wires from the picture. Messages enter and emerge, and the Domain Name System with TCP and IP let a program on one machine address a program on another without anybody tracing the path.

It is not the computers. That power was not usable by ordinary people until the Web, whose realisation he states as a slogan: it is not the computers which are interesting, it is the documents. The user is then in a web of interconnected documents and need not think about the protocols underneath.

It is not the documents. The Semantic Web's realisation is the same move again: it is not the documents which are interesting, it is the things they are about. A reader of a page about a protein is usually interested in the protein. In business and science the customers, products, genes and proteins are the objects of interest, and a good browser would show information about the thing, merged from many sources.

6.2 The two exceptions, repeated at every level

Each abstraction is said to hold except in two cases, and the pair recurs identically at every level, which is what makes the pattern an architecture rather than a story.

The first exception is debugging. When something fails, the user must be able to lift the hood and determine at which layer it failed: whether the connection broke locally or in the middle of the network, whether the URI was wrong or the server erred, whether the document was fetched correctly but lacked the data.

The second exception is trust, and Berners-Lee gives it more weight:

The information you are browsing comes from a particular server, whose name has registered against a particular person or organization. The trust you put in that information is related to who that organization is. It is the serving organization which is responsible for keeping the URIs you bookmark today alive tomorrow -- and some are better at it than others. Phishing attacks succeed when people are fooled into thinking it is an organiztion you trust when it isn't. Levels of Abstraction: Net, Web, Graph, 2007

Provenance is therefore not an optional feature layered on top. It is the reason the abstraction is allowed to be an abstraction at all.

6.3 The seams are visible in the identifier

The note's neatest observation is that each join between layers is legible in the URI itself. In 

http://acme.example.com/products/machin/truc

the owner's domain name is part of the name of the document, so the company is identifiably responsible for supporting that document. In 

http://acme.example.com/products/machin/truc#part3

the name of the document is part of the name of the thing. The thing is identified as the thing described by that document: a gene as defined in the Gene Ontology, a protein as defined in a particular taxonomy, a citizen as defined in a particular glossary. A thing may have many URIs, but a URI of this form says whose account of the thing is being used.

Berners-Lee adds a parenthesis that has become a chapter of its own. Since 2005 there have been URIs for things not explicitly bound to a document, which require the server to name a suitable document at request time. He calls this more complicated and moves on. Chapters 7 and 8 are what lies behind the parenthesis.

6.4 The conclusion, which is about people

The web of things is built on the web of documents, which is built on the web of computers controlled by Domain Name owners, which itself is build on a set of interconnected cables. This is an architecture which provides a social backing to the names for things. Levels of Abstraction: Net, Web, Graph, 2007

And then the sentence the note exists to deliver:

The value of this architecture is that each layer leverages the social components of the lower layer's architecture. Levels of Abstraction: Net, Web, Graph, 2007

A name for a gene is trustworthy because a document is trustworthy, which is trustworthy because a domain owner is accountable, which is meaningful because a registry binds the domain to a party. Take away the accountability at any level and the levels above lose their footing. This is why Chapter 3 concluded that naming is a contractual matter, and why the failures catalogued in Volumes VII and VIII are failures of the same structure rather than a separate set of problems.

What happened since

  • The trust exception failed in the field. Extended Validation certificates were the mechanism for showing a user which organisation stood behind a page. Research through the 2010s found that users did not act on the indicator, and both Chrome and Firefox removed the prominent EV display in 2019. The layer Berners-Lee identified as load-bearing was one that browsers concluded users could not see.
  • The parenthesis became a decade of argument. The Technical Architecture Group's resolution of the issue known as httpRange-14, in June 2005, established the 303 redirect convention for URIs denoting things that are not documents. Practice afterwards split between that pattern and hash URIs, and the split has not closed.
  • The third layer arrived partially. Schema.org, launched in June 2011, put structured descriptions of things on a large fraction of pages, and search engines consume them. The browser showing a user a merged view of a thing, which this note describes, remains uncommon outside specialist tools.
  • Layer separation weakened elsewhere. Consolidation of hosting and content delivery means that the domain owner named in a URI is frequently not the party in control of what is served, which complicates the inference from name to responsibility that the whole argument rests on.

Connections

This chapter completes Volume I by explaining what the earlier axioms are for. The parenthetical question about URIs for things opens Volume II at Chapters 7 and 8. The trust exception is the starting point of Volume VII, especially Chapter 66 on modelling real trust. The social reading of naming returns from Chapter 3 and reaches its full statement in Chapter 49 on Linked Data.

Questions

6.1 The two exceptions, debugging and trust, recur at every layer. Construct the pair for a fourth layer above the web of things, and say what would have to be visible for the pattern to hold.

6.2 The argument requires that a domain name identify a responsible party. Give two circumstances in which it does not, and say whether either can be repaired without changing the layering.

6.3 Hash URIs make a thing's identifier contain a document's identifier. URIs served through a 303 redirect do not. Which better supports the social backing described here, and what is lost by choosing it?

6.4 Browsers removed the Extended Validation indicator after concluding users did not use it. Does that refute the claim that trust is an unavoidable exception to the abstraction, or only the claim that the browser is where it should be shown?
