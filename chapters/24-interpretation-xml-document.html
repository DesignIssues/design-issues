Chapter 24

The Interpretation of an XML document

2002

Source The Interpretation of an XML document, a Design Issues note by Tim Berners-Lee, 2002-01-01. read the original

The short version

One XML file can mix tags from several vocabularies, so something must decide which specification governs which part. Berners-Lee’s answer is that the outermost element decides, and each element governs only what is inside it. Some elements, such as include, transform and decrypt, are replaced by their result, and an element must be able to mark its contents as quoted, not to be run.

The question

Chapter 17 established that one document may carry several vocabularies. This note, from February 2002 and revised in June 2005, asks the question that leaves open, in the bluntest possible form:

If one party sends another an XML document, how does one say what it means? The Interpretation of XML documents, 2002

24.1 The problem: specifications that fight

Berners-Lee credits Paul Prescod with the list of places one might look:

  • the document type declaration (DOCTYPE), a line at the top naming the document’s grammar;
  • the top-level namespace;
  • a schema reference (a schema is a machine-readable list of which tags may appear where);
  • other namespaces declared at the root;
  • any attribute on the root element;
  • anything at all in the document.

With six authorities and no precedence rule, the result is combat:

In fact the general problem is that without any overall architecture, one can write specs which battle each other. “The X attribute changes the meaning of the Y attribute”, “The Z attribute restores the meaning of the X attribute irrespective of any Y attribute” and so on. The Interpretation of XML documents, 2002

Prescod also supplied the way out, and Berners-Lee agrees. The root element is the one outermost element that contains everything else; a namespace is a label saying which vocabulary a tag belongs to. The namespace of the root element is the only thing a processor must be able to dispatch on. Everything else is decided further down.

24.2 Two models

The usual assumption was a pipeline: one stage per technology, such as inclusion, then style sheets, then decryption. Berners-Lee calls this, in the general case, “basically broken”: once elements nest arbitrarily, no single order of stages handles them all.

Many ways, one meaning

Top-down is not one procedure. The note sketches three:

StrategyHow it works
Repeated pipelineRun each processor in turn, cycling until no functions are left.
Recursive parserHand each foreign element to the code for its namespace as it is met.
Lazy viewerElaborate a function (run it and put its result in its place) only when the reader scrolls to it.

These are “mathematically equivalent in their effect”, which is why he speaks of the meaning of a document rather than its processing model.

24.3 XML functions

Some foreign elements are instructions that yield more document when elaborated. Berners-Lee calls them XML functions.

NamespaceIn plain wordsThe element is replaced by
XSLT, in “Literal Result Element as Stylesheet” modea template that computes textthe output its template computes
XIncludepaste in another file herethe referenced document or part
XML Encryptiona locked box that opens into contentthe decrypted content
XQuery (listed with a question mark)a database question whose answer goes herethe result of the query
Internationalisation tagsa marker for translatorstheir contents, marked “do not translate this phrase when translating this document”

What they share:

  • any document may use them, without its schema foreseeing them;
  • each is replaced by its result;
  • the result may contain further functions;
  • “none of its ancestors or siblings may be affected”.

The last property makes order unimportant: no function reaches outside its branch. Of nested inclusions the note says it “doesn’t make any difference” whether the inner ones are expanded first.

24.4 The need to quote

Sometimes a function must be mentioned without being run. In an XML package the packaged items are quoted. An XSLT template that outputs an XInclude element contains a real XInclude element, which must not be expanded inside the XSLT.

A pipeline cannot say this. Such ambiguities, Berners-Lee says, “stem from the lack of quoting syntax in XML”. Running quoted material is dangerous, not merely wrong.

24.5 The conclusion

The top-down processing model for XML as an architectual principle resolves many of the questions which remain unanswerable with pipelined processing. In fact, consideration of the example shows that pipeline processing could be actually dangerious, producing errors and possibly security issues, in the case of generally nested XML technologies of the types discussed. The Interpretation of XML documents, 2002

One issue is left open: references to parts of the document that may or may not have been elaborated yet.

  • A function may read outside itself. Does it see the document before or after other functions run?
  • An XPointer could point into the raw or the elaborated document. Berners-Lee inclines to “after”, so that a pointer into SVG lands on SVG.
  • XML Signature, he was told, signs the raw source before XInclude; either choice is sometimes useful.

24.6 Labelling the document

Because the root element decides, its namespace says what the whole document is: an XHTML root yields a hypertext page, an SVG root a diagram. A MIME type is the label a server sends in the HTTP headers, ahead of the file itself, such as image/svg+xml. The note recommends a specific MIME type for each well-known root, so that the label alone shows what the document is, and the +xml suffix only where the top-down model applies.

The alternative, one great schema for each combination of vocabularies, scales badly. A working group combining four specifications (XHTML, SVG, XForms, MathML) must settle how every pair fits together; the note asks whether it would take “n2 years”. He would rather each facility had its own schema.

What happened since

  • The question was overtaken. Mixed-namespace XML did not become the ordinary way to publish; the HTML that won (Chapter 23) has no author-declared namespaces.
  • A pipeline language was standardised. XProc became a W3C Recommendation in May 2010, sitting at the top of the tree as the note allowed.
  • The security concern was correct in general. XML processors that fetch external references unasked are attacked through XML External Entity (XXE) flaws, listed in the OWASP Top 10 of 2017.
  • The quoting problem recurs. “Prompt injection”, a term in use since 2022, names the same failure in AI systems: text meant as data is obeyed as instruction.
