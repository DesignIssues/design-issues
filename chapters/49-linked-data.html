Chapter 49

Linked Data

2006

Source Linked Data, a Design Issues note by Tim Berners-Lee, 2006-07-27. read the original

The short version

Putting data online is not the same as making it usable. A spreadsheet on a website is online, but it is a dead end: nothing in it points anywhere, and nothing points into it.

Linked data is written as small three-part statements, such as (Albert, child, Brian): a thing, a relationship, another thing. When each part is a web address, every statement is also a link. This note gives four rules for publishing data so that a person or a program arriving at one piece can find the rest.

The question

This is the most widely read note in the collection. Written in July 2006, it opens Volume VI because everything after it either applies its four rules or argues about what they left out.

The first sentence does the work of a whole volume:

The Semantic Web isn't just about putting data on the web. It is about making links, so that a person or machine can explore the web of data. With linked data, when you have some of it, you can find other, related, data. Linked Data, 2006

49.1 The four rules

A URI is a web address used as a name, of a person or an idea as well as a page. RDF is the standard format for three-part statements. An ontology is a published set of terms, such as child or title. A dataset is a large body of statements, such as a library catalogue.

Walked through with one person: name Albert with a URI; make it an http: address, so that it can be looked up; when someone looks it up, return statements such as (Albert, child, Brian); and make Brian a URI too, so the reader can go on.

49.2 Where each rule fails

The failures differ in kind. The first rule is definitional: if it does not use the universal set of symbols, Berners-Lee does not call it Semantic Web.

The second rule’s one deviation has been a constant tendency to invent new identifier schemes: LSIDs, handles, XRIs, DOIs and others. He gives two reasons. The first is control:

Typically, these involve not wanting to commit to the established Domain Name System (DNS) for delegation of authority but to construct something under separate control. Linked Data, 2006

The second is a misunderstanding: not seeing that HTTP URIs are names, not addresses, and that looking them up is a powerful and evolving set of standards. Chapter 3 takes that misunderstanding apart; Chapter 13 explains what separate control would honestly require.

The third rule fails by accident. Vocabularies are served; datasets frequently are not.

Many research and evaluation projects in the few years of the Semantic Web technologies produced ontologies, and significant data stores, but the data, if available at all, is buried in a zip archive somewhere, rather than being accessible on the web as linked data. Linked Data, 2006

The fourth rule is argued from manners. On the hypertext Web it is bad etiquette not to link to related material, and the value of one’s information depends on what it links to.

49.3 Two ways to make the link

The simplest link is a name in one file that points into another. Berners-Lee’s example is two families.

The local name #carol becomes the global name http://example.org/smith#carol, which anyone can use. The note calls the two steps, cut and fetch, dereferencing the URI; it is the fragment mechanism of Chapter 11.

Some vocabularies, including early Dublin Core and FOAF, used names without a hash. For these the server answers with a redirect: a reply, with the status code 303, telling the client to fetch a different address instead (Chapter 8). Names can then take any form, at a price. In Figure 49.3 a GET is a browser’s ordinary request for a page.

49.4 The convention that worked and was wrong

In 2006 the dominant form of linked data on the Web used neither pattern. The Friend of a Friend (FOAF) vocabulary identified a person by two properties: a mailbox to say who, and a pointer to a document for more. The source’s example records that its author knows Joe: 

<#i>  foaf:knows  [
       foaf:mbox <mailto:joe@example.com>;
       rdfs:seeAlso <http://example.com/foaf/joe> ].

Read: I know someone whose mailbox is joe@example.com, and more about them is at example.com/foaf/joe. Joe himself has no name of his own.

For privacy, publishers often gave a one-way hash of the address instead: a fingerprint of it that cannot be reversed.

This clever trick allows people who know their email address already to work out that it is the same person, without giving the email away to others. Linked Data, 2006

Berners-Lee credits the success, then names the defect:

However, the system has the snag that it does not give URIs to people, and so basic links to them cannot be made. Linked Data, 2006

This is rule one failing inside a system that obeys the other three. His remedy: people making FOAF files should give themselves a URI, and others should use it.

49.5 Which links to make

Data is browsable if looking up any thing returns every statement in which it appears, as first part or last. Then a group leads to its members and a member to the group.

The price is that a statement relating two documents must be repeated in both (Figure 49.4, left). That breaks the first rule of data storage, not to store the same thing twice. Generated data escapes the cost: dbview, a program written at MIT in 2004 and extended in 2006, presents any relational database as linked pages. Otherwise the choice is common sense:

If someone has the URI of that thing, what relationships to what other objects is it useful to know about? Linked Data, 2006

Very large datasets may offer a query service in SPARQL, RDF’s standard query language. The data stays linked only if someone holding just a URI can find that service, again through a 303.

What happened since

  • The note grew stars. In 2010 Berners-Lee added a five-star rating scheme to this note, aimed especially at government data. Chapter 51 takes it up.
  • Linked open data grew. The Linking Open Data project began in 2007; its diagram of interlinked public datasets grew from about a dozen to more than a thousand by the late 2010s.
  • Rule two was partly won. DOIs predate this note, but since 2017 Crossref has recommended writing them as https://doi.org/… links, which puts the rival scheme inside an HTTP name.
  • People got URIs, by two routes. Decentralised identifiers (did:, a W3C Recommendation in 2022) are a new non-HTTP scheme of the kind section 49.2 describes. Solid’s WebIDs, HTTP URIs for people, follow rule two. Chapter 54 discusses both.
