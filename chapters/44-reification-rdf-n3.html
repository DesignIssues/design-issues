Chapter 44

Reification of RDF and N3

2004

Source Reification of RDF and N3, a Design Issues note by Tim Berners-Lee, 2004-12-31. read the original

The short version

RDF data is three-part statements. Sometimes a writer needs to talk about a statement without making it. Berners-Lee makes three points. A description must keep the exact names the original used, so it holds them as strings. A description of a thing is not the thing. Describing a statement commits the writer to nothing; asserting it as true does.

The question

Written in December 2004, this note defines what it means to describe a graph using the same machinery the graph is made of, and in the course of doing so explains why the mechanism already in the specification was unusable.

Reification in this context means the expression of something in a language using the language, so that it becomes treatable by the language. Reifying RDF (properly), and N3, 2004

It isolates a mistake that any system describing its own data can make.

44.1 The rule, and the reason for it

An RDF statement has three parts: a subject, a predicate and an object. The statement ex:joe ex:name "James Doe" reads “Joe’s name is James Doe”. To describe it, one makes a new node that stands for the statement and gives that node three properties, one for each part.

The difficult question is how to refer to the identifier in the subject position. The obvious answer, to use the identifier ex:joe itself, is marked in the note with a comment reading “Wrong”. The note’s example uses a second identifier, ex:jd1, for the same person.

Berners-Lee’s verdict on the mechanism already in the standard is given without softening:

The form of reification which is provided by the original RDF specification is not suitable, because it loses that information. Reifying RDF (properly), and N3, 2004

The two descriptions are not merely different in form. They describe different graphs, even when the two names refer to the same person, because a graph is made of the symbols it actually used. If the system knows the two names are equivalent, the second can be derived from the first. But it matters to know which name a graph used.

44.2 Describing a blank node

A blank node is a node with no URI, standing for “something”. When a description meets one, it says that the node is blank. The node doing the describing is not the node being described.

This blank node in the description is a description of a blank node in the original graph. They are node the same blank node. Reifying RDF (properly), and N3, 2004

The second sentence is evidently meant to read “not the same”. The describing node may even be given a name; that changes nothing about the unnamed node it describes.

44.3 Sets, and the ungainliness admitted

A graph is a set of statements, and the model has ordered lists but no sets. Berners-Lee builds one out of a list and the relation that holds between a class and a list of its members, and then says exactly what it costs:

Using the set may be ungainly, but it ensures that two RDFGraphs which contain the same statements are demonstrably the same in their reified form. Reifying RDF (properly), and N3, 2004

He adds, in a parenthesis, that later systems might process sets explicitly and that the notation could gain set syntax. Chapter 43 argues for doing so; RDF never added sets, and this workaround is the consequence.

44.4 Why quotation is not assertion

The reason for the whole apparatus is an example about what one person knows. In N3, curly braces enclose a formula: a small graph treated as one thing, which can sit inside a statement. 

ex:jane  ex:knows   { ex:joe ex:name  "James Doe" }.

Jane’s knowledge is in those terms. Even if two identifiers refer to the same person, Jane may not know that, and so may not know the corresponding fact about the other name.

A formula can also introduce variables, so a description of it must carry three things: the statements, the universals (symbols that stand for anything) and the existentials (symbols that stand for some particular thing). The note’s example reads, roughly, “There is a car. Anything which is a car is a vehicle”: x is a universal, meaning anything, and c an existential, meaning some particular car. Run through the note’s tool, the description comes out several times longer than the input.

44.5 The final distinction

The closing section draws the line that makes the whole thing safe, and it is the same line Chapter 24 draws for documents:

Note that in this mode, the formula is not only described, but it is also stated to be a Truth. To simply describe a formula as existing doesn't say anything. Formulae are abstract things, to say one exists doesn't add anything. Reifying RDF (properly), and N3, 2004
FormCommits the writer to
A formula described as existingNothing; all formulae exist
A formula typed log:TruthIts contents

A system that conflates the two believes everything it reads, including everything it was merely told about.

What happened since

  • The standard mechanism was abandoned. The reification vocabulary this note criticises was little used and its removal was proposed in the 2010 note restated in Chapter 47. It survives in the specification and is avoided in practice.
  • The requirement was met differently. Named graphs, proposed in 2005, built into SPARQL datasets (Recommendation, January 2008) and RDF 1.1 (2014), let a set of statements be identified and described without being restated, which is what this note is trying to achieve.
  • Statements about statements returned. The RDF-star Community Group report (2021) and the RDF 1.2 work that followed from 2022 added a compact way to annotate a statement, and had to settle exactly the question this chapter raises: whether annotating a statement asserts it.
  • Sets are still absent. The workaround of section 44.3 is still the way to express an unordered collection.
