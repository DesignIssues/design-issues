Chapter 44

Reification of RDF and N3

2004

Source Reification of RDF and N3, a Design Issues note by Tim Berners-Lee, 2004-12-31. read the original

The question

Written in December 2004, this note defines what it means to describe a graph using the same machinery the graph is made of, and in the course of doing so explains why the mechanism already in the specification was unusable.

Reification in this context means the expression of something in a language using the language, so that it becomes treatable by the language. Reifying RDF (properly), and N3, 2004

The chapter matters beyond its notation because it isolates a mistake that any system describing its own data can make.

44.1 The rule, and the reason for it

To describe a statement, one describes its three parts. The question is how to refer to the identifier in the subject position. The obvious answer, to use the identifier itself, is marked in the note with a comment reading “Wrong”.

Berners-Lee’s verdict on the mechanism already in the standard is given without softening:

The form of reification which is provided by the original RDF specification is not suitable, because it loses that information. Reifying RDF (properly), and N3, 2004

He is careful to explain that the two descriptions are not merely different in form. They describe different graphs, even when the two names refer to the same person, because a graph is made of the symbols it actually used. If the system knows the two names are equivalent, the second description can be derived from the first. The derivation must go that way, and not be performed silently in advance.

44.2 Describing a blank node

A short passage makes a distinction that catches almost everyone. When describing a node that has no name, one says of it that it is a nameless node. The node doing the describing is not the node being described.

This blank node in the description is a description of a blank node in the original graph. They are node the same blank node. Reifying RDF (properly), and N3, 2004

One may even give the describing node a name, which is not a contradiction: naming the thing that describes an unnamed thing changes nothing about the thing described.

44.3 Sets, and the ungainliness admitted

A graph is a set of statements, and the model has ordered lists but no sets. Berners-Lee builds one out of a list and the relation that holds between a class and a list of its members, and then says exactly what it costs:

Using the set may be ungainly, but it ensures that two RDFGraphs which contain the same statements are demonstrably the same in their reified form. Reifying RDF (properly), and N3, 2004

He adds, in a parenthesis, that later systems might have explicit processing for sets and that the notation could be extended with set syntax. Chapter 43 is the argument for doing so; it was never done, and this workaround is the consequence.

44.4 Why quotation is not assertion

The reason the whole apparatus is needed is stated with an example about what one person knows about another. Jane knows that Joe’s name is James Doe. The quotation matters because Jane’s knowledge is in those terms: even if two identifiers refer to the same person, Jane may not know that, and so may not know the corresponding fact about the other name.

A description of a formula must therefore carry three things: the statements, the symbols quantified over all cases, and the symbols asserted to exist. The note gives the output of running a small example through the tool that performs this transformation, and the result is several times longer than the input, which is itself part of the argument.

44.5 The final distinction

The closing section draws the line that makes the whole thing safe, and it is the same line Chapter 24 draws for documents:

Note that in this mode, the formula is not only described, but it is also stated to be a Truth. To simply describe a formula as existing doesn't say anything. Formulae are abstract things, to say one exists doesn't add anything. Reifying RDF (properly), and N3, 2004

Describing a statement commits you to nothing. Asserting it commits you to its contents. A system that conflates the two believes everything it reads, including everything it was merely told about.

What happened since

  • The standard mechanism was abandoned. The reification vocabulary this note criticises was little used and its removal was proposed in Chapter 47. It survives in the specification and is avoided in practice.
  • The requirement was met differently. Named graphs, which arrived with SPARQL in January 2008, let a set of statements be identified and described without being restated, which is what this note is trying to achieve.
  • Statements about statements returned. RDF-star work from 2021 onward added a compact way to annotate a statement, and had to settle exactly the question this chapter raises: whether annotating a statement asserts it.
  • Sets are still absent. The workaround of section 44.3 is still the way to express an unordered collection.

Questions 4

44.1 Two descriptions differ only in which name they record. Explain why they describe different graphs, using the definition of a graph.

44.2 The node describing a nameless node is not that node. Give a case where confusing the two produces a false statement.

44.3 Describing a formula asserts nothing; asserting it commits you. Find a system that conflates them, and say what an attacker could do.

44.4 Jane knows a fact under one name and not another. Model that, and say what your model forbids an inference engine from doing.
