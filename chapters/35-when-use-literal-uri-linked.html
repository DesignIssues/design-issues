Chapter 35

When use a literal for a URI in Linked Data

2017

Source When use a literal for a URI in Linked Data, a Design Issues note by Tim Berners-Lee, 2017-11-05. read the original

The short version

In Linked Data, a web address in angle brackets stands for the thing it names; in quotation marks it is only a string of characters. When a statement is about the name itself, quote it, or a later merge will silently rewrite it.

The question

The shortest note in Volume IV, dated 5 November 2017, marked a first draft, and by its author’s own account a small point that sometimes needs careful explanation. It exists because a habit becomes a trap.

When you use RDF, we get used to using URIs a symbols so much that we can slip up and accidentally use it that way on one of the very rare occasions on which we are not talking about the thing the symbol represents, we are talking about the URI itself as a string. When use a literal for a URI in Linked Data, 2017

A whole note, as he says, just to make that point. It earns a chapter because the distinction between using a name and mentioning it is one every system with identifiers eventually gets wrong.

35.1 The rule

RDF describes the world as statements, each a triple: subject, property, value. Turtle is a common way of writing those triples down. In Turtle a URI in angle brackets is a symbol: it names a thing. A value in quotation marks is a literal: a piece of text, taken as it stands. Berners-Lee offers a mnemonic for the brackets:

You can think of the < and > signs around the URI in turtle meaning that identified by. When use a literal for a URI in Linked Data, 2017
Written asMeansJoe’s example
<…>the thing the URI names<https://uni.edu/students#JRMeadows> is Joe himself
"…"the characters themselves"https://uni.edu/students#JRMeadows" is a 34-character string

Almost always the thing is what is wanted, so the rare case catches people.

35.2 What goes wrong, exactly

The note’s example builds up in four steps.

  1. Example.com calls Joe <https://example.com/people#Joe> and says he is a person.
  2. A university calls him <https://uni.edu/students#JRMeadows> and says he is a student.
  3. Someone states that the two are the same, using the property owl:sameAs.
  4. A system may now normalise: pick one name and use it everywhere, so the data is “smushed together”.

Now Joe adds a line to his profile: he prefers to be known by the university name. That line is about a name, not about Joe, so the name must be quoted. Figure 35.2 follows both versions through the merge.

35.3 Why this is not a quirk of one notation

The mistake is a confusion of use and mention. Paris is a city; “Paris” has five letters. The first sentence uses the word to talk about a place; the second mentions the word to talk about the word.

It bites in RDF because the system may substitute equals for equals. Any system that rewrites identifiers will rewrite a mentioned name along with the used ones unless the format tells them apart. Many everyday tools do:

SettingUsed as a referenceMentioned as textWhat a rewrite does
Spreadsheetthe formula =B2the typed note “see B2”Inserting a row above moves the formula to B3; the note still says B2.
Word processoran automatic cross-reference to Figure 3the words “Figure 3” typed by handRenumbering updates the cross-reference, not the typed words.
Databasea customer number in a foreign-key columnthe same number in a free-text commentMerging two customers updates the key, not the comment.

Where the format cannot record the difference, a rewriting pass treats every occurrence alike and the rare mention is lost. Rare occasions are exactly the ones a habit destroys.

What happened since

  • The notation was already standard. RDF 1.1 Turtle became a W3C Recommendation in February 2014, so the bracket-versus-quote syntax the note relies on was fixed three years before it was written.
  • So was the merge. owl:sameAs, the “same as” statement that licenses smushing, comes from OWL, a W3C Recommendation since February 2004.
