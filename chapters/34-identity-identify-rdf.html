Chapter 34

Identity: how to identify what in RDF

2008

Source Identity: how to identify what in RDF, a Design Issues note by Tim Berners-Lee, 2008-01-01. read the original

The short version

In RDF written as XML, a reference such as #foo can mean a piece of the document, a node in the data, or the real person. Relabel a file from RDF to XML and the same link stops naming a person and starts naming markup. Berners-Lee identifies a person by something only they have, such as a mailbox, without pretending the person is the mailbox.

The question

Berners-Lee wrote a few lines of data describing Ora Lassila, and wanted to say so. Point that claim at the wrong level and it makes him the author of Ora Lassila himself. Does a reference mean the element in a document, the node in the graph, or the thing in the world? The note, from 1998, opens with an example of how invisible the question usually is:

In most cases it seems obvious to the human reader. The jam jar label text does not (normally) read “jam jar label text” or “jam jar label” or “jam jar” but “jam”. Identity, 1998

People resolve these levels without noticing. Machines cannot.

34.1 Three things a reference might mean

The markup is XML: tagged elements, which carry attributes (name=value settings) and contain child elements. The data is RDF: a graph whose nodes stand for things, linked by properties. The XML encodes the graph; the graph describes the world.

Berners-Lee’s example describes a person, Albert, in an element with id="foo". Inside it, a description of Albert’s father, Joe, says that Joe wrote #foo and is a friend of #foo (Figure 34.1). Which does each mean?

In a programming language a marker character would do: #foo for the node, @#foo for the thing described. Berners-Lee wants to manage with XML as it is, so he distinguishes by the referring attribute’s name, not its value:

AttributeWhat it refers toIn the example
value=a literal: the string itself, not a referencethe name “Joe”
href=the piece of document (text, or XML fragment) that the URI points atJoe wrote the element
resource=the abstract thing that the RDF node for that fragment describesJoe’s friend is Albert

href= matters because a digital signature covers the exact markup, so a signer must point at the XML, not at what it describes:

This is important, as for example it is bits of XML which one digitaly signs, not (in sigend XML) bits of RDF. Identity, 1998

34.2 Same link, two meanings

In February 2000 Berners-Lee added a section calling this a bug in how XML and RDF fit together. It is Chapter 24’s problem again: the same bytes read differently under different rules.

Take a URI with a fragment (the part after #) pointing into a file describing Ora Lassila. A fragment’s meaning comes from the media type, the label saying what kind of file it is (Chapter 11).

Served as RDF, the fragment names Ora himself. Served as text/xml, it names the element, or nothing, or another element: even the XML reading is unclear. His verdict:

To have a different interpretation of a URI as a function of the notional type of the document belies the fact the point of using XML syntax for RDF was that RDF documents should be XML documents! Of course we embed RDF in regular XML documents. So this distinction is nonsense. Identity, 2000

The easy fix fails. RDF could simply say a fragment always means the thing described, but then nothing is left for talking about the markup: saying he wrote foo.rdf#bar would make him the author of Ora Lassila (Figure 34.2). He lists three remedies:

  • Already in RDF: parseType="Resource" or parseType="Literal" on inline data, saying whether the reference is to the RDF thing or to the XML.
  • A new property linking an XML subtree to the RDF object it describes.
  • A new attribute: object= for the RDF node, leaving resource= for the fragment: the pointer missing from Figure 34.1.

34.3 Identifying things that have no address

The word “resource” makes the confusion worse. On the Web it means a thing with a URI; RDF uses it for anything that can be talked about, people included:

RDF treats people as “resources” and in using this terminolgy which normally means tautologically “things with URIs” makes people expect Ora to be synonymous with his web page or his mailbox. This is not of course good design. Identity, 1998

“We must not muddle the email address with the person.” Instead he identifies a thing by a property that happens to be unambiguous, not by an address it does not have. Ora gets an anonymous node, with no URI. Suppose no two people may share a mailbox. One record says a book’s author has the mailbox ora.lassila@research.nokia.com; a separate record says someone with that mailbox is named Ora Lassila. A program can merge the two and conclude that the book’s author is named Ora Lassila, which neither record states. An unfinished aside compares SQL (Chapter 33): “no identifiers, only use properties.”

A compound property such as author-mailbox collapses the two steps into one arrow and saves a node, so shortcuts are sometimes needed. They cost something.

With the shortcut there is no node for the author, so what it abbreviates must be stated elsewhere. The schema, the published definition of a vocabulary’s terms, is a good place: it makes the expansion evident to any processing machinery.

He declines to settle which properties should count as identifying, calling it a rat hole not core to the discussion. What matters is the step the mailbox makes possible: from “written by a person whose email is ora@w3.org” to the more useful “written by the person whose mailbox is ora@w3.org”.

What happened since

  • The mechanism was standardised. Inverse functional properties, which formalise “no two things share this value”, are part of OWL, a W3C Recommendation of February 2004. The Friend of a Friend (FOAF) vocabulary (begun in 2000) identifies people by mailbox, or by a scrambled (hashed) form that hides the address, mbox_sha1sum.
  • RDF got its own media type. RFC 3870, published in September 2004, registered application/rdf+xml, a label under which RDF’s own fragment rules apply.
  • The question of what a URI names went to the TAG. In June 2005 the W3C Technical Architecture Group resolved its “httpRange-14” issue: an http URI may name anything, including a person, but one without a fragment that answers with a document names a document.
