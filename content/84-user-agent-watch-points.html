The short version

A browser is the user’s agent, not a mere viewer, so it must pass on what the protocol means. The note picks three cases. Two kinds of redirect differ in which address to keep. Forms that commit the user should look different from links and leave a record. And people should deal in titles, not raw addresses.

The question

First dated 1998 and revised in 1999, this note begins by insisting that a term of art is not merely a term of art:

Browsers and Email programs are user agents. This isn't just a formal long term for them, it is an important issue. They are programs which act on behalf of, and represent, the user. User Agent Watch Points, 1999

And states the duty that follows, in the form of a warning:

The computer protocols such as HTTP are defined to carry a particular meaning, and it behooves a user agent to representthat meaning to the user, or the whol system of peeople and machines breaks. User Agent Watch Points, 1999

Chapter 20 established that meaning travels up a stack of specifications. This says somebody has to deliver it at the top.

84.1 Two redirections that mean opposite things

A server asked for one address can reply, in effect, that the browser should look somewhere else. HTTP has two ways of saying this, for opposite reasons. In the note’s example, a university gives its theses durable addresses on one reliable machine but serves them from fast department machines.

The two addresses carry different promises. This is Chapter 3’s point that a name is only as durable as the commitment of whoever runs it, turned into a question about which address a person copies down. Berners-Lee’s verdict on the browsers of 1999 is a parenthesis with two names and a question mark: very few implemented this properly.

84.2 The commitment the interface hides

Following an ordinary link sends a GET request. In the note’s words it is reversible, has no long-term effect and cannot commit a user to anything. Submitting a form to order a book sends a POST, and that does commit the user. Berners-Lee asks for the difference to be visible:

A graphic client, for example, should use a very different cursor while the user is hovering over a POST button to when the user is hovering over a GET link. User Agent Watch Points, 1999

Then comes the analogy that gives the requirement its force:

Doing a POST is like sending an email. User Agent Watch Points, 1999

Everyone expects to be able to look at what they have sent, because those are the things they are committed to. The same should be true of forms:

The web client should keep a record of POSTs which have been submitted. User Agent Watch Points, 1999

More than a quarter of a century later, that record still exists only in the inboxes of the parties a person committed to. Sites that muddle the two methods would waste the space, he concedes, but they are broken anyway. He adds that a digital signature will one day be an action just like POST, but with weight added. Then the principle:

Understanding when a commitment is made is a really important part of the user interface. Get it right. User Agent Watch Points, 1999

84.3 Hide the identifiers

The third watch point is an objective stated absolutely:

A web user should never be aware of a URI while using the Web, either creatively or browsing. User Agent Watch Points, 1999

The techniques the note lists are practical:

  • keep addresses in an under-the-hood window or the status bar (the strip at the foot of the window that shows where a link leads);
  • identify things by their titles;
  • add properties for short titles and icons to make that easier;
  • move every address-handling function to an optional menu;
  • refer to files and documents by drag-and-drop or a copied reference, not by typing addresses.

Servers help by generating the addresses of new documents.

This is in tension with Chapter 68, where the address bar is how a person learns who they are dealing with, and Chapter 6, where the domain name is the visible part that says who is accountable. Both are right about different things: a person needs to know whose site this is, and does not need to see the path.

84.4 Why an agent is not a viewer

A viewer displays what arrives. An agent represents someone, which means conveying what the other party has actually said, including what that party would rather not emphasise. A site that redirects to a mirror might prefer users to bookmark the mirror; the agent should keep the original address anyway.

Each watch point is a distinction the protocol made carefully and the browser failed to pass on, wasting the precision below.

What happened since

  • The redirection distinction stayed below the surface. Browsers cache permanent redirects, but whichever kind of redirect occurred they show, and bookmark, the address they ended up at, and never say which kind it was.
  • More redirect codes arrived. HTTP added 307 Temporary Redirect, which the note mentions, and in 2015 308 Permanent Redirect (RFC 7538).
  • The sent-items folder was never built. The nearest equivalents are password managers and per-site account pages.
  • Hiding addresses was tried and contested. Safari shows only the domain by default, while Chrome tested a domain-only address bar in 2020 and dropped the experiment in 2021.
  • The commitment cue never arrived. Its one common trace is the warning browsers give on reloading a page reached by POST, asking whether to resubmit the form.
