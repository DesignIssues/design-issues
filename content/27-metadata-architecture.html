The short version

Metadata is data about things, written so that a program can use it. Berners-Lee lays down two rules. First, metadata is ordinary data, so it can live inside a page, travel with it, or sit in a separate document. Second, it is a set of separate statements, none of which overrides another.

The question

This note, begun in January 1997, opens Volume IV because it is where the Semantic Web starts, though it does not use the phrase. Berners-Lee says so himself in a preface added later: it was written before the roadmap of Chapter 30 and introduces the same ideas, in the historical order they arose at the Consortium. There the first driving application of machine-readable data was endorsement labels: ratings, such as whether a page suits children, attached to pages. W3C’s format for them was PICS, the Platform for Internet Content Selection.

The definition it gives is narrower than the word’s ordinary use, and the narrowing is the point.

27.1 The definition, and the word doing the work

Metadata is machine understandable information about web resources or other things Metadata Architecture, 1997

When a browser fetches a page, the server also sends lines such as Date: and Expires:. Those lines are metadata: data about the page, written so that a program can act on them. Berners-Lee immediately says which part of the definition matters (“software agents” are programs acting on someone’s behalf):

The phrase “machine understandable” is key. We are talking here about information which software agents can use in order to make life easier for us, ensure we obey our principles, the law, check that we can trust what we are doing, and make everything work more smoothly and rapidly. Metadata Architecture, 1997

The clause “or other things” is the seed of Volumes IV to VI. Metadata began as data about web resources, but it should in future describe anything: people, things, concepts and ideas.

27.2 The first axiom, and its consequence

Axiom. Metadata is data.

Information about information counts in all respects as information. Two consequences follow. The first is that metadata can live anywhere, in the three places of Figure 27.1. (An HTML page’s head is the undisplayed part holding its title; HTTP headers are the lines the server sends ahead of the page.)

The second consequence is recursion without hierarchy. Metadata may itself have an owner and an expiry date, so there is meta-metadata (data about the metadata, such as the date a review of the page was written), but the architecture does not distinguish many levels. It is the same move as Chapter 3’s refusal to distinguish names from addresses: one kind of thing, not a tower of kinds.

27.3 The second axiom: independent assertions

Axiom. The architecture is of metadata represented as a set of independent assertions.

Two assertions about the same resource stand alone. Together they mean “this AND that”, and AND does not care about order, so a collection of assertions is an unordered set. The consequence is a prohibition, and it rules out a great deal of existing practice:

This design decision rules out for example, in simple sets of data, assertions which are somehow cumulative or later ones override earlier ones. Each assertion stands independently of others. Metadata Architecture, 1997

Configuration files where later rules override earlier ones are excluded; Chapter 32 returns to them.

27.4 Assertions have a shape

An assertion has a type, a subject and parameters (the other things the statement mentions), as a sentence has a verb, a subject and an object. The note writes (A u1 p q…): A names the type, u1 is the URI of the subject, and p, q are the rest. An assertion that a resource has a named property, such as its author, is an attribute. Who said it, and when, are usually left implicit.

Often the subject is left implicit too. The note calls a set of assertions with the subject taken out a label. Like the label on a jam jar, it carries information, but something else, its placement on the jar, says what it applies to.

Links are assertions too

A link is an assertion relating two resources: the triple (A u1 u2) of a relationship type and two URIs, as in the versioning example of Figure 27.3. Names for types must come from a global space, because anyone may coin one, and that means URIs. This is already the triple of Chapter 32: three parts, a relationship and the two things it relates, which RDF later made the basic unit of all Semantic Web data.

27.5 Self-describing information

The note’s central goal is data that “carries a reference to the specification of the semantics” of its assertions: each type of statement points, by URI, to its own definition. A program meeting an unfamiliar type can follow that link and extend what it understands, rather than guessing.

PICS is the note’s running example. The rest of the note, rough by its own account, covers label syntax, authorship, manipulating labels without knowing their vocabulary, and ordering. On ordering it lists mail header lines and SGML attributes as unordered, HTTP header lines and SGML elements as ordered, and asks whether a form is needed for assertions with many fixed, ordered parameters. The generalisation survived. PICS did not.

What happened since

  • The general form replaced the specific one. RDF became a W3C Recommendation in February 1999, generalising the label idea into assertions about anything. PICS was superseded, with POWDER (a W3C Recommendation of 2009) taking over its job of describing groups of pages; the architecture described here outlived its first application by decades.
  • All three placements survive. Metadata in the document, in the transfer and in a separate description are still the three options: embedded data (schema.org, launched in June 2011, usually embedded as JSON-LD), HTTP headers, and separately published descriptions.
  • The authorship question was never fully answered. Who is making a statement, which section 27.2 flags as needing rationalisation, remains the weak point: most embedded metadata records no author for its statements, which is why Chapter 37’s treatment of trust matters.
  • Ordering never went away. Even in 1997 the note listed HTTP header lines as ordered; order-dependent formats remain common, and the diagnosis in Chapter 32 still applies to them.

Questions

27.1 Metadata is data, so metadata can describe metadata. Show that this does not produce an infinite regress by writing three levels (for instance: a page; a review of the page; the date the review was written) and saying where it stops.

27.2 Take a metadata format you use. Which of the three placements does it use, and who is making the statement in each case?

27.3 The independence axiom rules out later-overrides-earlier. A file says allow everyone then deny Bob. Rewrite it as statements that mean the same whatever order they are read in.

27.4 “Machine understandable” is doing the work in the definition. Give an example of information about a resource that is not metadata under this definition, and say why.

27.5 The note compares a label to the label on a jam jar. Why does a label not need to name its subject?
