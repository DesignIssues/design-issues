The short version

Metadata is data about things, written so that a program can use it. Berners-Lee lays down two rules. First, metadata is ordinary data, so it can live inside a page, travel with it, or sit in a separate document. Second, it is a set of separate statements, none of which overrides another.

The question

Every page a server sends arrives with lines the reader never sees, such as Date: and Expires:. They are statements about the page, written for a program. In January 1997 Berners-Lee asked what follows if such statements are taken seriously: if they can sit in any document, about any resource, written by anyone. W3C’s first use for them was endorsement labels: ratings, such as whether a page suits children, in a format called PICS, the Platform for Internet Content Selection. The note never uses the phrase, but this is where the Semantic Web starts, before the roadmap of Chapter 30.

27.1 The definition, and the word doing the work

Metadata is machine understandable information about web resources or other things Metadata Architecture, 1997

The Date: and Expires: lines fit: data about the page that a program can act on. Berners-Lee immediately says which part of the definition matters (“software agents” are programs acting on someone’s behalf):

The phrase “machine understandable” is key. We are talking here about information which software agents can use in order to make life easier for us, ensure we obey our principles, the law, check that we can trust what we are doing, and make everything work more smoothly and rapidly. Metadata Architecture, 1997

The clause “or other things” is the seed of Volumes IV to VI: metadata should in future describe anything, including people, concepts and ideas.

27.2 Metadata is data, so it can live anywhere

Axiom. Metadata is data.

Information about information counts in all respects as information. The first consequence is that metadata can live anywhere, in the three places of Figure 27.1. (An HTML page’s head is the undisplayed part holding its title; HTTP headers are the lines the server sends ahead of the page.)

The second is recursion without hierarchy. Metadata may itself have an owner and an expiry date, so there is meta-metadata, but the architecture does not distinguish many levels.

27.3 Statements that can be shuffled and dropped

Axiom. The architecture is of metadata represented as a set of independent assertions.

Two assertions about the same resource stand alone. Together they mean “this AND that”, and AND does not care about order, so a collection of assertions is an unordered set. The note spells out what this forbids:

This design decision rules out for example, in simple sets of data, assertions which are somehow cumulative or later ones override earlier ones. Each assertion stands independently of others. Metadata Architecture, 1997

The note’s test is a pair of labels (Figure 27.2).

This rules out, for example, configuration files where later rules override earlier ones; Chapter 32 returns to them.

27.4 Every statement is a small sentence

An assertion has a type, a subject and parameters (the other things the statement mentions), as a sentence has a verb, a subject and an object. The note writes (A u1 p q…): A names the type, u1 is the URI of the subject, and p, q are the rest. An assertion that a resource has a named property, such as its author, is an attribute. Who said it, and when, are usually left implicit, but they are never absent. That is why the note says “assertion” rather than fact: an attribute and its value “must be seen as a statement by a particular party”. That is what rides on the open question of Figure 27.1.

Often the subject is left implicit too. The note calls a set of assertions with the subject taken out a label. Like the label on a jam jar, it carries information, but something else, its placement on the jar, says what it applies to.

Links are assertions too

A link is an assertion relating two resources: the triple (A u1 u2) of a relationship type and two URIs, as in the versioning example of Figure 27.3. Why name the types with URIs? Across all applications the dictionary of such names “would be so large that ad hoc arbitrary extension would be just as chaotic as central registration would be stifling.” URIs let names be coined in a decentralised way. This is already the triple of Chapter 32, which RDF (the Resource Description Framework, W3C’s format for such statements) later made the basic unit of Semantic Web data.

Saying something nobody planned for

In an Entity-Relationship database, an object’s type fixes what can be said about it. Once a person has been defined by name, address and phone number, the schema must be altered before anything can be said about, say, their credit card number. The Web has no such gate: “One can define a property ‘coolness’ within one’s own part of the web, and then make statements about the ‘coolness’ of any object on the web.” Elsewhere the note puts it in five words: “Anyone can say anything about anything.” The cost is admitted. Statements of new forms “may lead to nonsense or paradox”, a repeat of the choice to make links one-way, “sacrificing consistency for scalability.”

27.5 Data that points to its own dictionary

The note’s goal is data that “carries a reference to the specification of the semantics” of its assertions. A program meeting an unfamiliar type can follow that link rather than guess.

The alternative, as the note puts it:

Without self-describing information, development must wait for large companies or standards committees to meet and agree on the commonly agreed semantics. Metadata Architecture, 1997

What happened since

  • The general form replaced the specific one. RDF became a W3C Recommendation in February 1999, generalising the label idea into assertions about anything. PICS was superseded by POWDER (a W3C Recommendation of 2009) for describing groups of pages.
  • All three placements survive: embedded data (schema.org, launched in June 2011, usually embedded as JSON-LD), HTTP headers, and separately published descriptions.
  • The authorship question was never fully answered. Embedded metadata seldom records who made each statement, which is why Chapter 37’s treatment of trust matters.

Questions

27.1 Metadata is data, so metadata can describe metadata. Write three levels (a page; a review of it; the review’s date) and say why this is no infinite regress.

27.2 Take a metadata format you use. Which of the three placements does it use, and who is making the statement in each case?

27.3 The independence axiom rules out later-overrides-earlier. A file says allow everyone then deny Bob. Rewrite it as statements that mean the same whatever order they are read in.

27.4 “Machine understandable” is doing the work in the definition. Give an example of information about a resource that is not metadata under this definition, and say why.

27.5 A database refuses a fact its schema did not plan for; the Web accepts a statement about anyone’s ‘coolness’. Give one benefit and one harm of each.
