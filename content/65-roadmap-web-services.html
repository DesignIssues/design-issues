The short version

In 2002 a web service meant one firm’s program sending XML messages over HTTP to another’s. Berners-Lee calls the word Web a misnomer, since these exchanges drop the shared information space. What business messages need is accountability, a record either side can produce years later. A central directory of services is optional, not the centre.

The question

Volume VI closes with Berners-Lee’s October 2002 note on the technology of the moment, and his first move is to object to its name.

The Web in Web Services is, from the first point, a misuse: the term Internet Services would be more appropriate. Web Services, 2002

The complaint is not pedantry: the note asks what is lost when a system built on Web protocols abandons the thing that made them work.

65.1 Three common themes

He begins with what everyone agreed on. A quasi-static information space is the Web of Chapter 2: pages at addresses that change only now and then. Enterprises are businesses.

ThemeWhat it implies
A departure from a quasi-static information space to one where interactions are primaryMessages, not pages, become what matters (the trend of Chapter 61)
Use of existing Web standards as building blocksHTTP and XML are well understood and well debugged, so worth reusing
A focus on operations within and between enterprisesFirms that do not trust each other must prove what was sent

The first theme earns the objection to the name. The third separates this from ordinary remote procedure calls, in which one program asks another machine to run a function and return the result:

The fact that data is exchanged for business purposes and between different social entities means that accountability is required, rather than just reliable transmission. Web Services, 2002

TCP, the protocol under HTTP, already makes delivery reliable, but keeps nothing afterwards.

65.2 What the vendors wanted

One sentence, offered without comment, explains most of what happened to this technology:

The vendors of software see web services as way to repackage existing capability in a way which makes it interoperable with other systems. Web Services, 2002

Not to build something new: to wrap what already existed, in a common envelope called SOAP, an XML format for sending a message over HTTP. Around it grew a stack of specifications for securing, routing and transacting what was already secured, routed and transacted.

Two ways to send a message

SOAP, he notes, works in two modes: the XML either carries the parameters of a remote procedure call, packed and unpacked by stubs (local stand-ins for the remote function), or carries a whole document for the receiver to process.

The document mode of SOAP seems to be getting the most traction in the ecommerce stack. This is not an accident. The XML mode is more flexible than the RPC mode. Web Services, 2002

65.3 The discovery cloud

Reducing the architecture to the interaction is the same move as Chapter 19: find the small interface everything else is built on, and refuse to let accessories into it.

Why a registry is the wrong centre

A registry is a directory where providers list services for others to look up; the one proposed was UDDI. Most services, he expects, will link partners who already know each other, and where discovery is needed UDDI has the wrong shape:

Problems with it are that it is centralized by design, both in the single-tree ontology, and in the design based fundamentally on a central registry, with inter-registry operation as a secondary thing. Web Services, 2002

If discovery were essential, that registry would become the centre. He would rather services were one more thing described on the Semantic Web, found by the same queries as catalogues, parts and contracts.

65.4 Where he sends the reader instead

The philosophy section does not argue. It lists three earlier notes:

Here he only asks the question. Chapter 62’s answer is that the journal came first and the database is computed from it; keeping only the database throws away what makes accountability possible.

The bank statement, told twice

Later he describes a bank two ways: as a monthly process, and as rules about which documents make which others valid.

The document-oriented attitude suggests the use of business rules systems triggered by the receipt of new information -- new documents, in this case new web services messages. Web Services, 2002

A flight shows the same split: the real constraint is that a confirmation needs a reserved flight, while a choreography, “a particular dance, if you like”, is just one sequence of calls that achieves it.

65.5 Why this closes the volume

Volume VI has described data that is named, published, linked, written back, watched and reacted to in an open space, like a feed anyone may subscribe to. This chapter is the alternative of its day: the same protocols carrying closed exchanges, like an order message only two firms can read.

He names the cost of keeping the two apart. Scripts that depend on exact XML message formats suffer “DTD fragility”, breaking when the format changes; descriptions with no RDF mapping make web services “instant legacy technoplogy for the semantic web” (his spelling). His objection came at the outset; the outcome is below.

What happened since

  • The stack was built and then abandoned. SOAP 1.2 became a W3C Recommendation in June 2003 and WSDL 2.0 in 2007. In the 2010s the WS-* stack was largely displaced by simpler resource-oriented (REST) interfaces exchanging JSON, a lightweight data format.
  • The SOAP sense of the name faded. Amazon Web Services (2006) kept the phrase, but what this note meant by it is now usually called an API, reached at an endpoint (a URL programs send requests to).
  • Discovery stayed optional, as predicted. The public UDDI Business Registry, run by IBM, Microsoft and SAP, was shut in January 2006. Services are found through configuration and documentation.
  • Accountability came back separately. Signed messages, audit logs (append-only records of who did what) and event sourcing (state computed from a stored log of changes) supply what section 65.1 asks for.
