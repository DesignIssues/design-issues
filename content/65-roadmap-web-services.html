The short version

In 2002 a web service meant one firm’s program sending XML messages over HTTP to another’s. Berners-Lee calls the word Web a misuse, since these exchanges drop the shared information space. What business messages need is accountability, a record either side can produce years later. A central directory of services is optional, not the centre.

The question

TCP can deliver a business message once, in order, without loss. What it cannot do, the note observes, is let a firm “show the tax man the acknowledgement of receipt 7 years later”. Berners-Lee’s October 2002 note on web services, which closes Volume VI, is about that gap, and it begins by objecting to the name.

The Web in Web Services is, from the first point, a misuse: the term Internet Services would be more appropriate. Web Services, 2002

65.1 Why ‘Web’ is the wrong word

He begins with three themes common to the many approaches: a move away from a quasi-static information space (the Web of Chapter 2) to one where interactions are primary; reuse of well-debugged HTTP and XML; and a focus on operations within and between enterprises.

The first theme is why he objects to the name: a Web of messages is no longer an information space. The third separates this from ordinary remote procedure calls, in which one program asks another machine to run a function and return the result:

The fact that data is exchanged for business purposes and between different social entities means that accountability is required, rather than just reliable transmission. Web Services, 2002

TCP, the protocol under HTTP, already makes delivery reliable, but keeps nothing afterwards, and systems are not “designed to keep TCP connections open for the weeks or years over which a web service may run”.

65.2 What the vendors wanted

The vendors’ aim takes one sentence:

The vendors of software see web services as way to repackage existing capability in a way which makes it interoperable with other systems. Web Services, 2002

Not to build anew but to wrap the old, in a common envelope called SOAP, an XML format for sending a message over HTTP.

Two ways to send a message

SOAP, he notes, works in two modes: the XML either carries the parameters of a remote procedure call, packed and unpacked by stubs (local stand-ins for the remote function), or carries a whole document for the receiver to process.

The document mode of SOAP seems to be getting the most traction in the ecommerce stack. This is not an accident. The XML mode is more flexible than the RPC mode. Web Services, 2002

65.3 Why the directory is not the centre

W3C drew web services as a triangle: requester, provider, and a discovery agency, such as the proposed UDDI registry, that introduces them. Berners-Lee keeps only one edge of the triangle as essential:

The discovery agencies are well represented as a cloud, rather than being a well-defined module in the web services architecture. They will become interface to a huge world of data and query services which provide data about web services as well as many other things. Web Services, 2002

Why a registry is the wrong centre

Many services, he expects, will at first link partners who already know each other. He credits UDDI with defining an ontology for services, but where discovery is needed it has the wrong shape:

Problems with it are that it is centralized by design, both in the single-tree ontology, and in the design based fundamentally on a central registry, with inter-registry operation as a secondary thing. Web Services, 2002

If discovery were essential, that registry would become the centre. He would rather services were one more thing described on the Semantic Web, found by the same queries as catalogues, parts and contracts.

65.4 Which came first, the journal or the database?

Berners-Lee’s answer, from Paper Trail (Chapter 62), is that the journal came first and the database is computed from it; keeping only the database throws away what makes accountability possible. Many web services can, he says elsewhere, be described as the publication of documents, “just as the billing of a peer company is in reality effected by the issuance of an invoice”.

The bank statement, told twice

Later he describes a bank two ways: as a monthly process, and as rules about which documents make which others valid. In the rules version nothing is scheduled. Each arriving document, such as a matching transfer from the payee bank, makes something else true: a cheque cleared, a transaction valid.

The document-oriented attitude suggests the use of business rules systems triggered by the receipt of new information -- new documents, in this case new web services messages. Web Services, 2002

A flight shows the same split between a rule and a choreography, which he glosses as “a particular dance, if you like”:

ConstraintA confirmation is valid only if a reserved flight exists.
ChoreographyQuery flights, then reserve one, then confirm it. This is one route among several to a reserved flight.

What a firm would like to check automatically is whether the process will terminate, whether a sale will always gain, and:

Will we ever promise to ship something we do not have in stock? Web Services, 2002

Formal models and rule-based systems can go some way to answering such questions, “a good reason for keeping the languages involved as simple as possible”.

65.5 The cost of keeping them apart

A DTD is the rulebook listing which XML elements a message may contain; change it and every script written against the old one may break, which the note says “has been called” DTD fragility. Moving to RDF “may, by removing a layer of arbitrary design, reduce that fragility”.

The note calls the whole description side “a clear semantic web application”. While service languages are defined with English specs but no RDF mapping, web services become, in its words, “instant legacy” technology for the Semantic Web. Why, then, were the two kept apart? The argument, he writes, “is mainly social. It is costly to coordinate very large groups.” The apparent consensus of W3C members at Nice in November 2000 was to let each proceed without a mandated link.

What happened since

  • The stack was built and then largely displaced. SOAP 1.2 became a W3C Recommendation in June 2003 and WSDL 2.0 in 2007. In the 2010s simpler resource-oriented (REST) interfaces exchanging JSON took over most new work.
  • The SOAP sense of the name faded. Amazon Web Services (whose storage and compute services arrived in 2006) kept the phrase, but what this note meant by it is now usually called an API, reached at an endpoint (a URL programs send requests to).
  • The central registry did not last. The public UDDI Business Registry, run by IBM, Microsoft and SAP, was shut in January 2006. Services are mostly found through configuration and documentation.
  • Append-only records appeared elsewhere. Certificate Transparency (RFC 6962, 2013) introduced public append-only logs of certificates, a distant cousin of the receipts in 65.1.
