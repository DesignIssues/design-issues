The short version

The proposal in the previous chapter sounds, to anyone who knows the history, like a repeat of experiments that already failed. Machines that understand us; systems that reason about everything; the grand encyclopaedia of facts. Those projects were real, and they did fail.

This chapter answers six objections, then refuses to give ground on a seventh: that the Web’s contradictions demand fuzzy logic. Each of the six fears is granted, and each claim turns out smaller. The note then maps database tables onto the new model.

The question

Berners-Lee calls this note parenthetical, written so as not to disturb the flow of what a Semantic Web is. It explains why the objections need answering:

Where the other models are related to previous unmet promises of computer science, now passed into folk law as unsolvable problems, they suggest a fear that the goal of a Semantic Web is inappropriate. What the Semantic Web can represent, 1998

The objections are memories of earlier failures.

31.1 Six denials

31.2 Not artificial intelligence

The first denial is the one the note is remembered for, and the cost is stated in the same breath:

The concept of machine-understandable documents does not imply some magical artificial intelligence which allows machines to comprehend human mumblings. It only indicates a machine's ability to solve a well-defined problem by performing well-defined operations on existing well-defined data. Instead of asking machines to understand people's language, it involves asking people to make the extra effort What the Semantic Web can represent, 1998

The last sentence, usually left out, holds the difficulty.

31.3 Complete language, limited applications

The language must be complete, because it must represent the world. It must be able to state a paradox (a statement that contradicts itself) and a tautology (one that is true whatever the facts). Berners-Lee accepts the consequence: it will be possible to phrase questions whose answers would require a search of the entire Web and an unimaginable amount of time.

This should not deter us, he says. Each application uses a schema, a declared list of the terms it will handle, to restrict itself to a limited language; most will produce simple access control lists, privacy preferences and search criteria. Completeness at the bottom, restraint at the top.

Checking a proof, not finding one

The first uses, such as access control on web sites, involve only the validation of a previously prepared proof. Generating a proof for an arbitrary question is typically intractable, and the plan does not need it.

Real life is not efficiently computable

To the objection that much of this is not efficiently computable, his answer begins “Dead right.” The classical solution constrains the language so that every query finishes. The weblike one keeps the full language and creates subsets of the Web whose constraints give specific computational properties.

Older systems forced data into a fixed tree or grid, which kept it consistent; he bets DARPA, the American defence research agency, still has many. Joining them needed something looser, global hypertext, and critics said users would get lost: “You could follow links forever.” Yet many web sites stay orderly inside, and now ordered and unordered data can be linked.

31.4 The globalisation argument

The next objection is that this is another run at knowledge representation, the field that writes facts down for programs to reason over. Berners-Lee agrees it has been tried:

Knowledge representation is a field which is currently seems to have the reputation of being initially interesting, but which did not seem to shake the world to the extent that some of its proponents hoped. It made sense but was of limited use on a small scale, but never made it to the large scale. This is exactly the state which the hypertext field was in before the Web. What the Semantic Web can represent, 1998
The Semantic Web is what we will get if we perform the same globalization process to Knowledge Representation that the Web initially did to Hypertext. We remove the centralized concepts of absolute truth, total knowledge, and total provability, and see what we can do with limited knowledge. What the Semantic Web can represent, 1998

The objection that predicate calculus (formal logic with “for all” and “there exists”) never had wide impact gets the same answer: neither did hypertext before 1990. Both were centralised. Knowledge bases could not be merged, because each concept had one place in a tree. KIF, a standard language for passing logic between programs, is very centralised; Cyc, a long project to hand-write common-sense knowledge, suggests everyone agree on the same terms for common English words. The cure is hypertext’s:

Replace identifiers with URIs. Remove any requirement for global consistency. Put in a significant effort into getting critical mass. Sit back. What the Semantic Web can represent, 1998

31.5 On inconsistency, and what he will not concede

Check the source

This is the one objection the note does not concede. In classical logic, once a system believes a statement and its opposite, it can derive any conclusion at all. The Web is full of contradictions, so the objection runs that only a fuzzy system will do.

Berners-Lee refuses. A real system will not believe anything it reads but check the source, inferring only from statements signed by particular keys (a digital signature proves who wrote them). Within such a system an inconsistency is a serious problem, not something to be worked around. If my bank says my balance is one hundred dollars and my computer says two hundred, we need to figure out the problem. Same with launching missiles.

Rules are statements too

Earlier systems mixed information with tips on how to use it. A rule is typically stored not as a statement but in a table of rules to apply at a particular time. That timing is information about the rule, which the language cannot express. The note’s example, with the second row ours:

Stored asContent
a statement“a daughter of one’s daughter is one’s grandaughter”
an engine tipwhenever a parent of a daughter is found, apply the grandaughter rule

Only the first row can be exchanged between systems whose engines apply rules differently.

31.6 The closed world

At its opening the note names “one consistent difference” between the Semantic Web and many programming data models: the closed world assumption. The note does not define it. In the usual sense, which this chapter supplies, a database that does not list a fact treats it as false, while an open system may only treat it as unknown.

That difference is what makes the mappings in Chapter 33 approximate rather than exact, and it is the reason the deduction in Chapter 7 could not default to treating a URI as a page.

31.7 Records, columns and cells

The note’s second half maps existing data models onto the new one. An entity-relationship model, the boxes-and-lines diagram used to design databases, maps almost directly, except that relationships have URIs, so anyone can make one. One person may define a vehicle as having wheels, a weight and a length, and not foresee colour; someone else can still say a given car is red, using a colour vocabulary from elsewhere.

For relational databases the mapping is three lines (the example column is ours). In RDF a node is the thing a statement is about; a property is the kind of fact; the value is what the fact says.

A database never checks meaning: a query can join any columns of matching type, listing, in his example, houses with as many rooms as an employee’s shoe size. On the Web, information relating different databases can be added alongside them.

What happened since

  • Knowledge graphs. Google announced its Knowledge Graph in 2012: well-defined facts about entities, used in search.
  • Provenance was standardised. W3C PROV, a vocabulary for recording who produced data and how, became a Recommendation in 2013: a tool for the source checking of section 31.5.
  • Both approaches arrived. Systems that understand human mumblings were built after all, and they are not this; since retrieval-augmented generation was described in 2020, structured data often grounds what they produce.
