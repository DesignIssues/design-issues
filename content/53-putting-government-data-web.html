The short version

A department that wants to publish its data should get it out now, in whatever form it has, and convert it into one common model from which every other format can be produced. It should not wait for a committee to agree on terms, and it should leave the attractive websites to others.

The question

Written in June 2009 for British and American officials who wanted to publish data and did not know what to do next, this note is a set of practical instructions. It opens by ranking the steps in order.

Start with the "low-hanging fruit". Whatever else, the raw data should be made available as soon as possible. Putting Government Data online, 2009

53.1 The ranking, and what it demotes

Raw data means the records themselves, before anyone has turned them into charts or reports; a spreadsheet that is a plain table is already close. Linked data goes further: each thing described, a school or a road or a payment, gets its own web address, so other data can point to it.

A department’s own site cannot compete with outside sites, for two reasons: no interface yet lets ordinary users ask questions its designers did not foresee, and an outside site adds value by joining the data to other data for its own purpose, as in Figure 53.2. The note grants one exception: there are times when the government site must give ordinary users an easy way in.

53.2 Three reasons, one technique

Government data goes online for three reasons: accountability to citizens, valuable information about the world, and a government and country that work more efficiently. One technique serves all three, characterised in three words.

PropertyWhat it means for a department
OpenReachable by an unlimited variety of applications, because the format is not proprietary
ModularCombinable with anything else published the same way, with no advance planning by either party
ScalableEasy to add to, even when the terms and definitions change over time

The example of modularity is health expenditure for an area combined with its population characteristics to assess whether a programme worked. The note does not care which formats come in or go out, only what sits in the middle:

The essential message is that whatever data format people want the data in, and whatever format they give it to you in, you use the RDF model as the interconnection bus. Putting Government Data online, 2009

RDF is the Web’s common model for data: every statement links two things, each named by a web address. A bus is a shared connector that everything plugs into, so nothing needs a direct link to anything else.

SPARQL is the query language of this toolkit: a program anywhere can send a question to a SPARQL service and get the answer back as RDF, XML, sometimes JSON or CSV. Some users prefer each, so the outputs should be generated automatically.

53.3 Two philosophies, and the one that finishes

An ontology is an agreed list of terms and what each one means.

The top-down one is to make a corporate or national plan, by getting committees together of all the interested parties, and make a consistent set of terms (ontology) into which everything fits. This in fact takes so long it is often never finished, and anyway does not in fact get corporate or national consensus in the end. Putting Government Data online, 2009

The alternative concedes what the top-down approach is for:

A top-level mandate is extremely valuable, but grass-roots action is essential. Put the data up where it is: join it together later. Putting Government Data online, 2009

A mandate from the top supplies permission, in the terms of Chapter 51 the first star and the hardest thing to obtain. It does not supply the vocabulary.

53.4 Mixing vocabularies

A vocabulary is a set of shared terms for describing data. The note recommends terms others already use: foaf:name for a person’s name, dc:title for a title, geo:lat and geo:long for position. The part before the colon is a short nickname for the vocabulary: FOAF (“friend of a friend”) for people, DC (Dublin Core) for documents, geo for positions. Chapter 17 argued that one document must carry several vocabularies; here a department uses international terms where they exist and local ones for the rest.

The Linked Data technology, unlike any other technology, allows any data communication to be composed of many mixed vocabularies. Each vocabulary is from a community, be it international, national, state or local; or specific to an industry sector. This optimizes the usual trade-off between the expense and difficulty of getting wide agreement, and the practicality of working in a smaller community. Putting Government Data online, 2009

53.5 From whatever exists to linked data

The note advises against a preliminary survey: an inventory of every dataset may take longer than publishing one.

Leave the existing system alone

The most important rule is not to disturb the systems, or the people, responsible for the data, who may have spent years assembling it. Extract the data with the export facilities it already has and add “a thin shim” to adapt it to the standard. Likewise, do not run a public server on the live database unless it is built for heavy use: take a copy, or generate the RDF once and serve that.

Whatever form it is in

The data is inWhat the note suggests
A relational databaseUse an open-source tool such as D2RServer or Triplify, with a mapping file that says how the tables represent things and their relationships
A spreadsheetIf it is a plain table, export it as CSV and convert that to RDF; spreadsheets full of headings and notes are harder
XMLPut the XML up as it is while thinking, then write a script that converts each file to RDF
A proprietary formatSomeone writes a program to get the data out and convert it
An existing websiteChange the page-generating scripts to embed the data in each page (RDFa), or give each page a parallel page of RDF

A worked example

For the proprietary case the note sketches the whole job with books and shelves. Give each thing a web address: a book becomes http://id.example.com/id/isbn/123457890, named by its ISBN, and a shelf http://id.example.com/id/shelf/746. Then write a small script which, given one of these addresses, looks up that book (and its shelf) or that shelf (and its books) and returns RDF. That script is the department’s linked data server.

What the note does not ask for

The note does not argue that all data should be public. Personal data will probably not be an early choice, though where privacy is settled and the data already public, converting it is an excellent idea. Each dataset’s licence should be machine-readable, using the Creative Commons cc:license term or the CC0 waiver, which gives up all rights where the law allows.

What happened since

  • The portals arrived around the note. The American data portal, data.gov, opened in May 2009, a month before it; Britain’s, data.gov.uk, followed in January 2010, seven months after. The note itself records that both governments made public commitments toward open data that year.
