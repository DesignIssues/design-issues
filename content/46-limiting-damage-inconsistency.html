The short version

In classical logic, once two statements that contradict each other are both accepted, any conclusion at all can be proved. The Web is certain to contain contradictions. The answer is that nothing on the Web is believed just because it is there: it is believed only for a reason, for a limited purpose, and for a limited time.

The question

This note answers the objection that everyone raises, and Berners-Lee states it in the reader’s own voice before answering:

What, many people ask, will happen when this huge mass of classical logic meets its first inconsistncy? Surely, once you have one staement that A and another somewhere on the web that not A, then doesn't the whole system fall apart? Surely, then you can deduce anything you want? Inconsistent data, 1998

The objection is correct about logic and wrong about what a system does with documents.

46.1 Where the objection goes wrong

Suppose a naive logic engine holds both “the meeting is on Tuesday” and “the meeting is not on Tuesday”. By the ordinary rules of inference (drawing new conclusions from old ones), it can then prove that the moon is made of cheese, or anything else. Logicians call this the principle of explosion.

This fear of course is quite valid - or would be if all assertions in the whole world were regarded as bing on equal footing. Some imagine that an RDF parser will simply search all XML documents on the web for any facts, and add them to a massive set of belived assertions. This is not how realisic systems will actually work. Inconsistent data, 1998

An RDF parser is the program that reads a document and extracts the statements in it. The correction is a chain: a fact is asserted in an expression (a single statement), which is part of a formula (a group of statements), which is found by parsing a document. Then the sentence that does the work:

There is no a priori reason to believe any document on the web. Inconsistent data, 1998

The note leaves a placeholder for a picture here; Figure 46.1 supplies it. In it, metadata means a statement about a document.

46.2 Forwards and backwards

Two ways of organising such a system are named. Working forwards starts from a configuration page, a document the system’s owner has chosen as its starting point. Working backwards starts from a global index, a search service that lists every document mentioning a given term.

46.3 Scoping trust to a key and a form

Digital signature adds security: a document signed with a key carries a mark only that key’s holder can make. A checksum is a short fingerprint computed from a document’s exact contents. The first requirement is that an endorsement records the checksum the document had when it was believed. Endorsing a location endorses whatever appears there later; endorsing a checksum does not.

The second step is a rule. Its bluntest form trusts a key for everything:

“whatever any document says so long it is signed with key 57832498437”. Inconsistent data, 1998

In practice, Berners-Lee says, authorities are trusted only for specific purposes, and the rule must be narrowed to match. His narrower examples trust one key only for statements that someone is a member of W3C, and another only for statements that someone is an employee of IBM.

Trust is granted not to a party but to a party for a purpose, and that narrowness is what limits the damage.

46.4 The choice he does not make

The centre of the note is a dilemma left open, and both options are bad in ways worth understanding.

RuleCost
Believe statements of this form signed with this keyBureaucratic: the exact wording must be kept, so an equivalent statement phrased differently will not match
Believe what can be inferred from information signed with this keyOne contradiction under that key makes everything derivable from it

The first gives up something we normally rely on: being able to replace any set of formulae with another set deducible from it. He calls this very messy. The second is the inconsistency trap:

However, the attacked system may not realize what has happened before it has been convinced that the sun rises in the west. Inconsistent data, 1998

Nothing guarantees the system notices the break before it has acted on absurd conclusions.

The way out he offers is to limit the kinds of inference rule that may be used, as knowledge-representation systems with limited logics already do. The cost falls on the implementer: a general proof engine must either be told the permitted rules as data, or have each limited reasoner built in. He does not pretend to have finished the thought.

46.5 Time, and the tortoise again

The last section addresses a source of apparent contradiction that is not an attack at all, and opens with the dialogue characters of Chapter 29:

Tortoise: What's the time, Achilles?
Achilles: Five past ten, my friend. [They chat for a minute]
Tortoise: What is the time, Achilles?
Achilles: Six minutes past ten, Mr. Toroise.
Tortoise: But Achilles, you just told me just a minute ago it was five minutes past ten. How can I ever believe you again? Inconsistent data, 1998

Both answers were true when given. People and documents change status, and the contradiction comes from forgetting when each statement was made.

Expiry

The first remedy is an expiry date on everything, as an HTTP server can already send with a resource. All conclusions drawn from a document are cancelled when its date arrives, unless a fresher copy says the same thing. Statements should also be fully qualified. On the Semantic Web, “It is rainy” becomes something like “at Mon Jan 24 09:41:06 EST 2000 the measurement guage 5 at Dubin Airport read rain as having fallen in the last hour”. A fuzzy system would conclude Dublin is wet; a classical one, only that at least once it rained somewhere in Dublin.

Writing the slack into the rule

The second remedy applies far beyond this subject: make the looseness in the real system visible. Instead of

Any employee of any member orgainzation of W3C may register Inconsistent data, 1998

the registration engine is told

Any person who was some time in the last 2 months an employy of an organization which was som etim ein the last 2 montsh a W3C member may register. Inconsistent data, 1998

If an organisation drops its membership, the system need not propagate that instantly: the slack has been written down. Berners-Lee also expects time-unaware reasoners fed data with expiry dates, their results used only while all the inputs are still valid.

What happened since

  • Trust scoped by purpose became standard. X.509 certificates carry an extended key usage field (RFC 5280, 2008) limiting what a key is trusted for; OAuth 2.0 (RFC 6749, 2012) grants tokens limited scopes.
  • Endorsing by checksum became ordinary. W3C Subresource Integrity (2016) lets a page load a script only if its hash matches; SLSA (2021) attestations identify software by hash.
  • Explicit validity periods are built into revocation. Certificate revocation lists and OCSP responses (RFC 6960, 2013) state when the next update is due.
