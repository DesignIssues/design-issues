The short version

A reasoning program stores rules that mix two things: what is true, and when to work it out. Only the first can be shared on the Web. The Web uses classical logic because it is the only kind in which adding new facts never overturns old conclusions, so anyone can check anyone else’s proof.

The question

Chapter 40 concluded that inference rules cannot live outside the language. This note, from 1998, shows what happens when a rule is taken out of an engine and put on the Web, and finds that a rule is two things wearing one coat.

41.1 A rule contains two separable things

An inference engine is a program that draws new conclusions from the facts it has stored, its database. The worked example is kinship. An engine holds a rule about daughters and granddaughters, and Berners-Lee reads it the way the engine understands it: whenever a new daughter relationship is found, look for the next one up, and conclude the granddaughter relationship, where “conclude” means add to the database. Whether to do this at once or only when someone asks is decided outside the rule itself, possibly by a person; the note calls this an out-of-band decision.

Written down, the rule and the fact beneath it look almost the same (g stands for granddaughter, d for daughter; ∀ reads as for all, |= as is to be concluded when and <= as is true whenever):

FormNotationWhat it means
As a ruleg(a,c) |= d(a,b) & d(b,c)An instruction: on finding the two daughter links, add the granddaughter link.
As a fact∀a,b,c g(a,c) <= d(a,b) & d(b,c)A statement: whenever the two daughter links hold, so does the granddaughter link.

The trade is stated without regret, because answering arbitrary queries was never the goal:

The goal is to unify everything which can be expressed in classical logic (including more mathematics when we get to it) without futher constraint. Rules and Facts, 1998

Classical logic here means the ordinary logic of mathematics, in which a statement once proved stays proved. (Spellings such as “futher” are the note’s own.) And the reason no compromise is available:

A system which tries to constrain the expressive power cannot be universal. Rules and Facts, 1998

41.2 The penguin

The hardest case is a system where adding a fact can make a previous conclusion false. The note calls these non-monotonic logics: their stock of conclusions does not only grow. They rest on defaults, things assumed unless one is told otherwise, and so they are closed-world systems: whatever is not in their fixed set of facts is treated as false.

Two ways of exporting such knowledge to the Web are offered:

OptionWhat gets publishedWho can use itProblem
Export the rule systemA report on the engine: in its collection, nothing contradicts “birds can fly” for penguins or any wider groupIn practice, only engines of the same kind (the note calls it unwieldy)It describes the engine’s state, not penguins
Export the outputA particular system has concluded that Pingu fliesAnyoneTreating it as true is the catalogue mistake below

Of the second, Berners-Lee notes that a system might risk incorporating such statements, and says what that amounts to:

This is the logical equivalent of declaring, “Well, I don't think such a book exists becase it wasn't in Blackwell's catalog”. Rules and Facts, 1998

Blackwell’s is an Oxford bookshop; a book missing from its catalogue may still have been published. The remedy he sketches is a definitive list from a party entitled to give one, such as the publisher’s list for that year, which turns an absence of evidence into a positive statement someone is answerable for.

41.3 Why classical logic, and not as a matter of taste

The note’s central claim is put as a denial that this was a preference:

The choice of classical logic for hte Semantic web is not an arbitrary choice among equals. Classical logic is the only way that inference can scale across the web. Rules and Facts, 1998

Two alternatives are ruled out. Fuzzy systems, which hold beliefs to a degree rather than as true or false, tend to believe something more strongly the more often evidence for it is presented. On an open network that is a recipe for manipulation: a claim repeated on a thousand spam pages would be believed more strongly with every copy.

Closed-world systems do not scale because the scope of a default is usually left implicit and differs from fact to fact. A list showing no flights on Sunday may be true of one airline’s timetable but not of the world, and a bare statement that there are none does not say which list it was relative to.

What classical logic buys is a particular social move, named with a phrase that recurs in his writing:

When a fact is presented as a fact, the “Oh yeah?” function of demanding justification can be satsfifed by a roof in a universal language of proof. Rules and Facts, 1998

(For “satsfifed by a roof” read satisfied by a proof.) Heuristic systems, which search by rules of thumb rather than strict logic, may have been used to discover the proof. Once found, it can be checked as valid by any Semantic Web system. The note places heuristic systems above a shared Semantic Web bus (a channel every system plugs into, like a computer’s bus) and classical systems below it.

41.4 What publishing a rule strips out

The operation at the centre of this chapter is given its plainest statement:

Exposing rules as classic logic facts strips the (pragmatically useful) hint information which controls the actual sequence of operation of a local inference engine. Rules and Facts, 1998

The hint is called pragmatically useful, not worthless. It is discarded because it cannot travel, not because it does not matter. Its owner keeps it; everyone else gets the fact.

The companion note of Chapter 31 names the underlying error: most knowledge representation systems confuse information with inference tips. A rule stored in a table to be fired at a particular moment has its meaning tangled up with its scheduling. Two systems must be able to exchange what a rule means even when neither recognises the other’s notion of when to apply it.

The note then turns to a further problem, what happens when the Web holds both a statement and its contradiction. Chapter 46 treats that question.

What happened since

  • The separation was standardised. The Rule Interchange Format, a W3C Recommendation of June 2010, exists precisely to exchange rules between engines with different execution strategies, which is this chapter’s requirement.
