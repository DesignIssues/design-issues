The short version

Desktop and browser are two interfaces for one idea: things to open. A folder should be a list of links, not a place. Mail, news and the Web all make links, so the user should not have to pick a protocol, or a filename.

The question

Volume IX opens with a note from February 1997, written with some reluctance. Berners-Lee names its audience:

Those people who asked what I meant by a consistent user interface and then said, "Don't just say it, write it down!". For software developers in the hope that some of this will come true. Cleaning up the User Interface, 1997

82.1 The inconsistency nobody notices

The arrangement is so familiar that nobody asks the obvious questions:

Why can't I put folders into my hypertext documents? Why can't I write on the desk? Cleaning up the User Interface, 1997

He does not want folders and documents merged entirely: different forms of object for distinctly different uses are fine.

82.2 Location fixation

The real difference is a single relationship:

The only fundamental difference between a hypertext document and a folder is that there is a special relationship between any document and the folder where is "is". Cleaning up the User Interface, 1997

That relationship is an artefact of storage. Unix lets a file sit in several directories through hard links, extra directory entries for one stored file, but only on the same disk; DOS allows just one directory. Users should not have to care which disk a file is on. So file everything under its creator and creation date, and make everything else a pointer:

Then a folder becomes a useful sort of document for helping us organize things, but not a container with implications on physical storage. The relationship between a folder and a file in it becomes just a hypertext link. Ah, consistency! Cleaning up the User Interface, 1997

82.3 Protocols the user never asked about

The second inconsistency is the split between mail, news and browsing tools, each speaking its own protocol:

This is of course totally meaningless to a user. Cleaning up the User Interface, 1997
ProgramProtocol it speaksWhat it does, in the user’s terms
MailSimple Mail Transfer ProtocolLinks a message into someone else’s “In” box, which is a folder by another name.
NewsNetwork News Transfer ProtocolLinks a document from a group visible all over the world; much like mailing a list.
Web editorHypertext Transfer ProtocolUploads a document to a server. HTTP’s POST was originally meant to make a new document and a link to it.

Described by what they do, all three make links. Someone wanting one item linked from a few inboxes, newsgroups and pages should not, he says, have to choose an application.

Menus, history and mailto

The same reasoning reaches every container. Favorites, most of the Start Menu and mailboxes all classify things, so they should share one interface, and the history list should span all applications. Even mailto: falls short: Berners-Lee calls it “a misnomer (my fault I feel as I didn’t think when we created it)”, since it should name a mailbox, not start a message.

82.4 Why this belongs in a book about architecture

This is the interface counterpart of Chapter 26. Webizing means giving things global names, such as Web addresses, so they can be pointed at from anywhere. If a folder holds links and a mailbox is a folder, moving something between them is one operation everywhere. The note’s example is saving a web page in a mailbox, which would freeze a copy and keep a pointer to it.

82.5 The last thing I want to be asked is the filename

The "save as" filename dialog box is one of the things currently holding up our civilization. Cleaning up the User Interface, 1997

It asks about disks, once the writing is finished. He would rather choose at creation, usually by picking a template, who may see the document and what storage it needs (archived, or rapidly available), and get a URI back.

82.6 Documents and deeds

Documents that can always change suit an encyclopaedia, not a cheque book. Signing turns a document into a deed, which freezes: it can be cancelled by another deed, but not edited (Figure 82.5). A sent email cannot be unsent, only followed by another message.

Every time you press "send" in your email you are making a deed. Cleaning up the User Interface, 1997

The interface should make it plain when the user is committing rather than just searching. The note also proposes an “Oh, yeah?” button for asking why a document should be trusted; Chapter 41 develops it.

What happened since

  • Documents moved into the browser with suites such as Google Docs (2006).
  • One message, many folders. Gmail (2004) used labels, so a message can sit in several without copies.
  • One home, everything else a pointer. In 2020 Google Drive gave each file a single folder, with shortcuts elsewhere, close to section 82.2.
  • Protocols partly hidden. Webmail hides SMTP and IMAP, but mail, chat and the Web remain separate applications.
