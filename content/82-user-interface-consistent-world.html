The question

Volume IX opens with a note from February 1997 written under protest. Berners-Lee names its audience and his own reluctance in the same breath:

Those people who asked what I meant by a consistent user interface and then said, "Don't just say it, write it down!". For software developers in the hope that some of this will come true. Cleaning up the User Interface, 1997

He adds that he is a bit embarrassed, because everyone has pet ideas about how interfaces frustrate them and listening to them can be tedious, and suggests that is why he had not written it down before.

82.1 The inconsistency nobody notices

The questions that follow the observation are the ones nobody asks because the arrangement is so familiar:

Why can't I put folders into my hypertext documents? Why can't I write on the desk? Cleaning up the User Interface, 1997

He is careful not to over-reach. The concepts could be extended until they were the same, and he says he does not think that would necessarily be a good idea: it is fine to have different forms of object for distinctly different uses.

82.2 Location fixation

The actual difference is identified precisely, and it is a single relationship:

The only fundamental difference between a hypertext document and a folder is that there is a special relationship between any document and the folder where is "is". Cleaning up the User Interface, 1997

That relationship is an artefact of storage, and the proposal is to break it. File everything under its creator and creation date, make everything else a pointer, and the consequence is stated as a small triumph:

Then a folder becomes a useful sort of document for helping us organize things, but not a container with implications on physical storage. The relationship between a folder and a file in it becomes just a hypertext link. Ah, consistency! Cleaning up the User Interface, 1997

A folder stops being a place and becomes a document that lists things. The same thing can then be in several, without copies, because being in one is a statement rather than a location.

82.3 Protocols the user never asked about

The second inconsistency is the division between mail, news and browsing, and the argument is that it reflects the engineers' categories rather than the user's.

This is of course totally meaningless to a user. Cleaning up the User Interface, 1997

He then re-describes each program in terms of what it actually does, and the descriptions converge. A mail program moves data between mailboxes, which are folders by another name, and links it into someone else's incoming folder. The word he insists on is link, because the relationship it creates is that this message is in this mailbox, and he has already argued that such a relationship should be a link.

Three programs, three protocols, one operation.

82.4 Why this belongs in a book about architecture

The chapter is the interface counterpart of Chapter 26. Webizing a language means replacing local names with global ones so that references can cross boundaries. Webizing an interface means the same thing: if the relationship between a folder and a file is a link, and a mailbox is a folder, then moving something between them is the same operation everywhere, and the boundaries between applications stop being boundaries.

The obstacle is that the categories are not in the software but in the institutions that produced it. Mail, news and hypertext were three communities with three protocols, and the user inherited the org chart.

What happened since

  • The desktop and the browser did converge, from the other direction. Files moved into the browser rather than the Web moving onto the desktop, and most people's documents now live in a window.
  • Location fixation weakened. Search-first file systems and tagging reduced how much people must know about where a thing is, and the folder survives as the primary metaphor.
  • A file can be in several places. Synchronised stores let one item appear in several collections without copies, which is section 82.2's proposal in ordinary use.
  • The protocol division dissolved. Mail, chat and feeds are now read in whatever application the user prefers, and the underlying protocol is genuinely invisible, which is what the note asks for.
