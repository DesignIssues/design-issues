The short version

Desktop and browser are two interfaces for one idea: things to open. A folder should be a list of links, not a place: store a thing once and let every folder point to it. Mail, news and the Web all make links, so the user should not have to pick a protocol, or a filename.

The question

Berners-Lee asks two questions of the screens of his day:

Why can't I put folders into my hypertext documents? Why can't I write on the desk? Cleaning up the User Interface, 1997

People had told him: “Don’t just say it, write it down!”

82.1 Two metaphors on one screen

In 1997 a PC or Mac showed its own files as folders spread over the whole screen, a desktop, and the rest of the world inside one browser window. He had raised this split at WWW4 in Boston in December 1995. It is one of “a few unfortunate inconsistencies which make it more difficult to use, and less powerful”.

“Folders should be just another sort of document,” he argues, though he does not want the two merged entirely: different uses may keep different forms. The second question is the mirror image: why can the desktop not be a document, written on like a page?

82.2 Location fixation

The only fundamental difference between a hypertext document and a folder is that there is a special relationship between any document and the folder where is "is". Cleaning up the User Interface, 1997

That relationship is an artefact of storage. Unix lets a file sit in several directories through hard links, but only on one disk; DOS allows just one folder. Users should not have to care which disk a file is on. So file everything under its creator and creation date, and make everything else a pointer. Then “the relationship between a folder and a file in it becomes just a hypertext link. Ah, consistency!”

82.3 Protocols the user never asked about

The second inconsistency is the split between mail, news and browsing tools, each speaking its own protocol:

This is of course totally meaningless to a user. Cleaning up the User Interface, 1997
ProgramProtocol it speaksWhat it does, in the user’s terms
MailSMTPLinks a message into someone’s “In” box, a folder by another name.
News (Usenet discussion groups)NNTPLinks a document from a group visible worldwide.
Web editorHTTPUploads a document; POST was meant to make a new document and a link to it.

All three make links, so the user should not have to choose an application.

Favorites, most of the Start Menu and mailboxes “are all ways of classifying things”, so they should share one interface. History should span every application: one list could hold the page read, the mail sent and the file edited, viewed “just like a mailbox”.

82.4 Webizing the desktop

Webizing (Chapter 26) gives things global names; applied to the interface, every move becomes a link. The note’s example is editing a photo. To mail it, “I drag the document onto the person icon” and choose To or Cc (main or copied recipient); “If I drag it to a newsgroup, the functionality will be exactly the same”, though the options differ. Dragging it to a folder makes a link too.

A mistake of his own: mailto

A mailto: link opens a blank email. Berners-Lee calls it “a misnomer (my fault I feel as I didn’t think when we created it)”: it should name a mailbox, not start a message. Clicking it should show the mailbox, perhaps with “an address book entry and a list of the messages sent to/from” that person.

82.5 The last thing I want to be asked is the filename

The "save as" filename dialog box is one of the things currently holding up our civilization. Cleaning up the User Interface, 1997

It asks about disks, once the writing is finished. He would rather pick a template at the start, which settles who may read the document and how it is stored, and get a URI back at the end. A template could mint names that never need changing, from a macro such as http://my.co.com/BY/<user>/<yymm>/NOTE/<seq>.txt: a user’s third note of May 1997 might become .../BY/alice/9705/NOTE/3.txt, a name nobody has to invent. Keeping a page in a “personal archive” is then a menu item: “No ‘Save As’. No filenames. It has a URI already.”

82.6 Pressing send makes a deed

Documents that can always change suit an encyclopaedia, not a cheque book. With only living documents, the only possible actions are those “just as good if you do them twice as if you do them once”, and “this doesn’t work for paying bills.” Signing turns a document into a deed, which freezes: it can be cancelled by another deed, but not edited (Figure 82.5).

The interface should show plainly when the user is committing. Berners-Lee imagines “rubber stamp” icons: one for stamping W3C Recommendations, “and a totally different one for ordering medium sized purchases on my credit card.” Email is the everyday case:

Every time you press "send" in your email you are making a deed. The document freezes. You may even be digitally signing it. You lose control -- you can't take it back. Cleaning up the User Interface, 1997

What happened since

  • One message, many folders. Gmail (2004) used labels, not copies.
  • One home, everything else a pointer. In 2020 Google Drive gave each file a single folder, with shortcuts elsewhere, close to section 82.2.
  • No Save As. Google Docs & Spreadsheets (October 2006; Chapter 83) kept each document on a server at its own address and saved it every few seconds while the writer typed.
