The short version

Most web pages are, strictly speaking, broken, and browsers display them anyway. HTML is the language web pages are written in; XML is a stricter cousin used for data, in which a single error stops the whole document. In 2008 HTML was splitting into a strict XML version (XHTML) and a forgiving one (HTML5).

The note argues that authors get no reward for fixing errors gradually, and proposes a browser toolbar that would rate a page with errors out of 100.

The question

In 2008 the W3C had to choose between a strict HTML that refuses broken pages and a forgiving one that accepts them. Berners-Lee put the dilemma to its members, the Advisory Committee, like this:

To continue to promote messy code on the Web is to create problems and pain later on. To promote clean XML is a current pain for real users which they will not put up with. HTML and XML, 2008

The paper stayed private until May 2019, by which time the question had been settled the other way.

23.1 One misplaced tag, two verdicts

<b><i>text</b></i>

The italic tag opens inside the bold one but closes outside it. An XML parser (the program that reads markup) refuses this as not well-formed. A browser reading it as HTML shows bold italic text and moves on.

XHTML, the note adds, “was not widely deployed in the dominant Web browser, Internet Explorer”, which could not display pages served with the XHTML content type until version 9, in 2011. For most readers, then, the strict branch did not exist.

23.2 Two philosophies of extension

The HTML case for central extension: the modules proposed for HTML, such as SVG, MathML and XForms, “can be counted on the finger of one hand”, so the design authority can simply add them. Even so, vendors often add tags and values such as rel="nofollow" without coordination: “the ‘marketplace’ decides”.

The XML branch extends a language with namespaces: a web address put in front of a tag name, so that two groups using the same word cannot collide. Its case, against central registries like the Dewey decimal system, is a requirement:

This is the requirement for a group to be able to define the terms involved in the new technology without having to get an audience with and agreement with central committee. HTML and XML, 2008

ARIA, about thirty attributes describing interface elements to assistive software, shows the split:

BranchHow an ARIA attribute such as “label” is writtenWho decides the name
XHTMLaria:label, the prefix bound to a namespace addressWhoever owns that address
HTML5aria-label, a plain HTML attributeThe HTML editors, or in practice the market

23.3 Why ‘be liberal’ failed on the Web

Since at least RFC 793 (1981), Internet protocols have followed Jon Postel’s rule: be conservative in what is sent and liberal in what is accepted. Send lines of limited length but accept any length; send one letter case but accept either.

It has not worked so well on the Web, because the Web page designers in fact paid no heed to being conservative. They were not in general engineers who had read the spec at all, but random people copying each other's Web pages, and seeing what worked when they modified them. HTML and XML, 2008

The second part is about time:

Once a Web page is out there with badly nested tags, it is out there for good. HTML and XML, 2008

The robustness principle assumes short-lived messages and a feedback loop between engineers. The Web has long-lived documents and no loop at all.

23.4 Why broken pages stay broken

The note starts from a rule: “To look at a system which includes people, one must study the incentives for those people.” So it graphs the reward an author gets for effort.

Under the strict branch, most authors starting with many errors “did not make it to the right when serving their code as XHTML.” The remedy follows from the shape:

What does this mean? It means distinguishing more than the two possible outcomes of success and failure. We need to make a slope, so we need different levels. HTML and XML, 2008

He proposes three:

  1. A browser toolbar that slides down on a page with errors and rates it out of a hundred. Visitors might want to know whether a site is “polluting the Web”, and anyone producing one, “up to the CEO and board”, could ask for detailed feedback.
  2. “View Source”, the way markup has always spread, would show and copy a tidied version.
  3. The W3C validator would become a page checker that grades, as in Figure 23.5. One check is the Content-Type, the server’s label for the kind of file, such as text/html.

23.5 Who needs a namespace: vocabularies by size

Section 23.2 counted HTML’s modules on one hand; the note replies that HTML cannot be fenced off from other communities. The Web is scale-free: as with inbound links to pages, which follow a power law, a few communities are enormous and most are small. The note walks down the scale from HTML through SVG and Atom feeds to “protein scientists and history museums, for scout troops and bird fanciers”, down to “today’s experiment in a lab”. He asks that this shape be engineered for: HTML at the top can be managed centrally, but the shaded tail of Figure 23.6 needs a way to coin names without a committee.

23.6 The grouchy robustness principle

The note’s last words return to the page authors and restate Postel’s rule:

Be conservative what you produce. Be liberal about what you accept but complain about any deviations from the spec in a way to help and to motivate the producers to adhere to it better. HTML and XML, 2008

Complaining helpfully supplies the slope of Figure 23.4.

23.7 Meeting in the middle

Meeting HTML would mean changing XML, whose value is its stability: “Attempts at create an XML1.1 failed, just trying to introduce a few new Unicode characters.” The complaints against it:

Issue with XMLMotivation
Quotes are required around attributesEase of use
The whole tag name must be spelled in the end tagEase of use
Parsers must stop on errorUnfriendly, impractical
Namespace URIs take too much spaceImpractical
Non-nested begin and end tags must be accommodatedLegacy “tag soup” (bad nesting, section 23.1)

Top rows could be cured by redesigning XML, bottom rows are HTML habits he would keep, and the middle invites compromise. His sketch of an “XML2” lets simple attribute values go unquoted, takes the namespace from the Content-Type, drops DTDs (old grammar declarations) and processing instructions (see section 1.2), and perhaps allows </> as a close tag. Below, the XML declaration, DOCTYPE, namespace and quotes all vanish. A page that starts 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html PUBLIC
 "-//W3C//DTD XHTML 1.0 Transitional//EN"
 "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml">
<head>
  <link href="../../../People/Berners-Lee/general.css"
  rel="stylesheet"  type="text/css" />
</head>

could, served as text/html, simply be 

<html>
<head>
 <link href=../../../People/Berners-Lee/general.css
  rel=stylesheet type=text/css />
</head>

and still be valid XML2. The only non-HTML habit left is the /> closing the link tag. The note calls this “a compromise between the forks, but one in which everyone can do most of what they want”, and asks for an attitude that “we are going to clean up the Web just as we sometimes need to clean a bedroom -- or a planet.”

What happened since

  • The fork closed by one branch ending. W3C stopped work on XHTML 2 in 2009, and HTML5 became a Recommendation in October 2014. In 2019 W3C and the WHATWG (the browser makers’ group that started HTML5) agreed that the WHATWG Living Standard would be the single version of HTML. There was no XML2, and HTML has no namespaces.
  • The slope was built, partly, for developers only. Google’s Lighthouse (from 2016) scores pages from 0 to 100, though for performance and accessibility rather than markup errors. Nothing slides down in front of an ordinary reader.
  • Decentralised extension arrived by another route. Custom elements (shipped from 2016), tags a page defines for itself with script, require a hyphen in the name rather than a namespace, and structured data in pages uses schema.org (2011) vocabulary URIs in JSON-LD. The requirement of section 23.2 was met without the mechanism this note defends.

Questions
