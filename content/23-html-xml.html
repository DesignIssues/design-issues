The short version

HTML is the language web pages are written in. XML is a stricter cousin used for data, in which a single error stops the whole document. In 2008 HTML was splitting into a strict XML version (XHTML) and a forgiving one (HTML5).

Most web pages are, strictly speaking, broken, and browsers display them anyway. The note argues that authors get no reward for fixing errors gradually, and proposes graded warnings so that they would.

The question

Written in 2008 as a talk to the W3C Advisory Committee (the meeting of W3C’s member organisations), and not made public until May 2019, this note addresses a split in the Web that Berners-Lee could not prevent:

Occasionally it seems that some strategic thinking is necessary in order to ensure that the system as a whole will continue to work well and evolve smoothly. This is one of those times. HTML and XML, 2008

By 2019 the question had been settled against the position argued here, and the note was released as a record rather than as an intervention.

23.1 The fork

Both languages descend from SGML, an older and more elaborate markup standard; XML is a simplification of it. The practical difference is easiest to see in one line of badly nested markup: 

<b><i>text</b></i>

The italic tag opens inside the bold one but closes outside it. An XML parser (the program that reads markup) refuses this as not well-formed. A browser reading it as HTML shows bold italic text and moves on.

23.2 Two philosophies of extension

The note sets out to understand each branch’s motives, not to decide which fork is “right”. The case for centralised extension: the modules anyone proposes adding to HTML can be counted on one hand, so the design authority can simply add them.

The XML branch extends a language with namespaces: a web address put in front of a tag name, so that two groups using the same word cannot collide. Its case is a requirement rather than a preference:

This is the requirement for a group to be able to define the terms involved in the new technology without having to get an audience with and agreement with central committee. HTML and XML, 2008

The note’s own example is ARIA, about thirty attributes that describe the role of interface elements to assistive software. The branches wrote them differently:

BranchHow an ARIA attribute such as “label” is writtenWho decides the name
XHTMLaria:label, the prefix bound to a namespace addressWhoever owns that address
HTML5aria-label, a plain HTML attributeThe HTML editors, or in practice the market

23.3 The robustness principle, reconsidered

Since at least RFC 793 (1981), Internet protocols have followed Jon Postel’s rule: be conservative in what is sent and liberal in what is accepted. Send lines of limited length but accept any length; send one letter case but accept either. The note explains why this rule, which worked for protocols, failed for pages.

It has not worked so well on the Web, because the Web page designers in fact paid no heed to being conservative. They were not in general engineers who had read the spec at all, but random people copying each other's Web pages, and seeing what worked when they modified them. HTML and XML, 2008

The second part is about time:

Once a Web page is out there with badly nested tags, it is out there for good. HTML and XML, 2008

The robustness principle assumes short-lived messages and a feedback loop between engineers. The Web has long-lived documents and no loop at all.

23.4 The incentive curve

Berners-Lee then analyses the system as one containing people with motives, and draws the reward for effort.

The remedy follows from the shape:

What does this mean? It means distinguishing more than the two possible outcomes of success and failure. We need to make a slope, so we need different levels. HTML and XML, 2008

He proposes three:

  1. A browser toolbar that slides down on a page with errors and rates it out of a hundred. To the objection that no browser wants to give the worse experience, he answers that, as with environmental cleanup, a browser without it would look irresponsible.
  2. “View Source”, the way markup has always spread, would show and copy a tidied version.
  3. The validator (the W3C’s service that checks a page against the specification) would become a page checker that grades, as in Figure 23.5. One check is the Content-Type, the server’s label for the kind of file, such as text/html.

23.5 Scale-free vocabularies

The Web is made of communities of very different sizes. It is scale-free: there is no typical number of inbound links to a page, only a power law, in which a few pages have enormous numbers and most have few. Berners-Lee suggests, as an unproved hunch, that this may be the best trade-off between one ungainly universal language and many agile small ones. He asks that the shape be engineered for, not merely admired: HTML at the top can be centrally managed, but the shaded tail of Figure 23.6 needs a way for groups to coin names without a committee.

23.6 The grouchy robustness principle

The note ends with a restatement of Postel’s rule:

Be conservative what you produce. Be liberal about what you accept but complain about any deviations from the spec in a way to help and to motivate the producers to adhere to it better. HTML and XML, 2008

The added clause, complain helpfully, is what supplies the graded reward of Figure 23.4.

23.7 Meeting in the middle

The note also lists its complaints about XML:

Issue with XMLMotivation
Quotes are required around attributesEase of use
The whole tag name must be spelled in the end tagEase of use
Parsers must stop on errorUnfriendly, impractical
Namespace URIs take too much spaceImpractical
Non-nested begin and end tags must be accommodatedLegacy “tag soup” (bad nesting, section 23.1)

Rows near the top could be cured by redesigning XML; the bottom rows are HTML habits he would keep; the middle invites compromise. His sketch of an “XML2” lets simple attribute values go unquoted, takes the namespace from the Content-Type, drops DTDs (old grammar declarations) and processing instructions (see section 1.2), and perhaps allows </> as a close tag. A page that starts 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html PUBLIC
 "-//W3C//DTD XHTML 1.0 Transitional//EN"
 "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml">
<head>
  <link href="../../../People/Berners-Lee/general.css"
  rel="stylesheet"  type="text/css" />
</head>

could, served as text/html, simply be 

<html>
<head>
 <link href=../../../People/Berners-Lee/general.css
  rel=stylesheet type=text/css />
</head>

and still be valid XML2. Gone are the XML declaration and DOCTYPE, the xmlns attribute (the namespace now comes from the Content-Type), and the quotes around simple values. The only non-HTML habit left is the /> closing the link tag.

What happened since

  • The fork closed by one branch ending. W3C stopped work on XHTML 2 in 2009, and HTML5 became a Recommendation in October 2014. In 2019 W3C and the WHATWG (the browser makers’ group that started HTML5) agreed that the WHATWG Living Standard would be the single version of HTML.
  • The note was published at that moment, and its argument was not adopted: there was no XML2, HTML has no namespaces, and extension is centralised.
  • The slope was built, partly, for developers only. Google’s Lighthouse (from 2016) scores pages from 0 to 100, though for performance and accessibility rather than markup errors. Nothing slides down in front of an ordinary reader, the part that would have changed authors’ incentives.
  • Decentralised extension arrived by another route. Custom elements (shipped from 2016), tags a page defines for itself with script, require a hyphen in the name rather than a namespace, and structured data in pages uses schema.org (2011) vocabulary URIs in JSON-LD. The requirement of section 23.2 was met without the mechanism this note defends.
