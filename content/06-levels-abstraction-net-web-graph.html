The short version

An abstraction lets someone forget the machinery underneath it. The Web stacks four: cables, computers, documents, and the things the documents are about. A user may ignore every lower layer except when something breaks and when trust is in question; for trust, the web address itself says who is responsible.

The question

Berners-Lee’s example of an old email address is timbl@mcvax!cernvax!cernvms: not a name but a set of directions, one machine after another. This 2007 note is about how the Web made such directions unnecessary, and about the two occasions on which a user must still look beneath the layers: when something breaks, and when it matters who stands behind what is being read.

Its status line says it was written in response to another round of circular discussions of Web architecture. It adds no mechanism; it supplies a reason for the layering: each layer is also a layer of responsibility, borrowing the accountability of the one beneath.

6.1 Three refusals

The note advances by rejecting three answers in turn. Each step is named for what no longer has to be thought about.

Not the wires

When computers were connected by telephone lines, one ran a program to connect to a particular machine, and to reach a third machine one had to know how to drive the second. Mail travelled by machines calling each other at night, and addresses named the route: in timbl@mcvax!cernvax!cernvms each ! separates one machine on the path from the next.

The Internet removed the wires from the picture. It was thought of as the “Internet Cloud”: messages went in and appeared at another computer without, “(when things worked)”, anyone worrying about packets or routes. DNS names the computers, and TCP/IP lets a program on one talk to a program on another. When things went wrong, one ran diagnostics to find the break, but that was the exception.

Not the computers

Even so, computers talking to computers was not easily usable by ordinary people until the Web, whose insight he states as a slogan: it is not the computers which are interesting, it is the documents. The Web’s protocols, URI, HTTP and HTML, defined how documents could be sent between servers and browsers. The user is then “apparently in a web of interconnected documents” and need not think about the protocols underneath. The word “apparently” matters: the lower layers are still there.

Not the documents

The Semantic Web’s insight is the same move again: it is not the documents which are interesting, it is the things they are about. A reader of a page about a protein is usually interested in the protein. In business and science the customers, products, genes and proteins are the objects of interest, and a good browser would show information about the thing, merged from many sources. What the user sees is a web of connections between things: this person is a customer who made this order which includes this item which is manufactured by this facility, and so on.

6.2 When the hood must come up: failure and trust

Each layer can be ignored except in two cases. The first is debugging: when something fails, the user must be able to lift the hood and find the layer at which it failed.

The second is trust, and it is the one the note’s conclusion returns to:

The information you are browsing comes from a particular server, whose name has registered against a particular person or organization. The trust you put in that information is related to who that organization is. It is the serving organization which is responsible for keeping the URIs you bookmark today alive tomorrow -- and some are better at it than others. Phishing attacks succeed when people are fooled into thinking it is an organiztion you trust when it isn't. Levels of Abstraction: Net, Web, Graph, 2007

Keeping bookmarks alive is no small duty: a Pew Research Center study published in May 2024 found that 38% of web pages that existed in 2013 were no longer available.

Phishing, a fake page posing as an organisation the reader trusts in order to collect passwords or payment details, works by faking exactly this: who is behind the page. Provenance, the record of where a piece of information came from and who stands behind it, is therefore something a user cannot be allowed to lose sight of. Both questions recur at every layer (Figure 6.2).

6.3 The seams are visible in the identifier

Each join between layers is legible in the URI. In 

http://acme.example.com/products/machin/truc

the owner’s domain name, acme.example.com, is part of the name of the document, so the company is identifiably responsible for supporting that document. In 

http://acme.example.com/products/machin/truc#part3

the name of the document is part of the name of the thing. The part after the # picks out something within or described by the document, and everything before it is the document’s own name.

The thing is identified as the thing described by that document: a gene as defined in the Gene Ontology, a shared public catalogue of gene names, a protein as defined in a particular taxonomy, a citizen as defined by the Immigration and Naturalization Service glossary. A thing may have many URIs, but a URI of this form says whose account of the thing is being used. The last example carries its own warning: the INS had ceased to exist in March 2003, four years before the note: a thing’s name is only as durable as the organisation whose document defines it.

Berners-Lee adds a parenthesis that has become a chapter of its own. Since 2005 there have been URIs for things not explicitly bound to a document, which require the server to name a suitable document at request time. He calls this more complicated and moves on.

6.4 The conclusion, which is about people

The web of things is built on the web of documents, which is built on the web of computers controlled by Domain Name owners, which itself is build on a set of interconnected cables. This is an architecture which provides a social backing to the names for things. Levels of Abstraction: Net, Web, Graph, 2007

That social backing lets people find out the social side of what they deal with, not only the raw data: provenance, trust, persistence, licensing and appropriate use. And when things fail, they can work out what went wrong, because the layering makes clear who is responsible.

The sentence the note builds to:

The value of this architecture is that each layer leverages the social components of the lower layer's architecture. Levels of Abstraction: Net, Web, Graph, 2007

Read from the bottom up (Figure 6.3), the chain of borrowed trust runs:

  1. A registry binds the domain name to a party.
  2. So the owner answers for what its computers serve.
  3. So a document under that domain is as trustworthy as the owner.
  4. So a gene’s name built from that document’s name is as trustworthy as the document.

Take away the accountability at any level and the levels above lose their footing, which is why Chapter 3 concluded that naming is a contractual matter. The name in the address still points to the party responsible, though that party may no longer run the machines itself (see below).

What happened since

  • One way of showing trust failed in the field. Extended Validation (EV) certificates, issued only after checking an organisation’s legal identity, let browsers show which organisation stood behind a page, typically as a company name beside the address bar. Chrome 77 (September 2019) and Firefox 70 (October 2019) removed that display, having concluded that users did not act on it.
  • The parenthesis became a decade of argument. The Technical Architecture Group’s resolution of the issue known as httpRange-14, in June 2005, set the 303 convention: asked for a URI denoting a thing that is not a document, the server answers 303 (“See Other”) with the address of a document about it. Practice split between that and hash URIs like #part3 above. Chapters 7 and 8 take this up.
  • The third layer arrived partially. Schema.org, launched in June 2011, put structured descriptions of things on a large fraction of pages, which search engines consume. A browser showing a merged view of a thing remains uncommon outside specialist tools.
  • Layer separation weakened elsewhere. Content delivery networks (Akamai, founded in 1998, was an early large one) and shared cloud hosting mean that the domain owner named in a URI is often not the party running the machines that serve it, so the name says who is accountable but no longer who operates the servers.
