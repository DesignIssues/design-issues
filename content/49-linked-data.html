The short version

Data that is online is not thereby usable. A spreadsheet on a website is a dead end: nothing in it points anywhere, and nothing points into it.

Linked data is written as small three-part statements, such as (Albert, child, Brian): a thing, a relationship, another thing. When each part is a web address, every statement is also a link. Four rules let a person or program arriving at one piece find the rest.

The question

In 2006 Berners-Lee could write in his own data file that he knew Håkon Lie, using the URI the Opera Community site gave Lie, and anyone following that link could “find all his friends”. Typical social network portals, the note observes, did not link to other sites. This July 2006 note sets out four rules that make the first case possible. It begins:

The Semantic Web isn't just about putting data on the web. It is about making links, so that a person or machine can explore the web of data. With linked data, when you have some of it, you can find other, related, data. Linked Data, 2006

49.1 The four rules

Applied to one person, the rules say: name Albert with a URI, a web address used as a name, of a person or an idea as well as a page; make it an http: address, so that it can be looked up; when someone looks it up, return statements such as (Albert, child, Brian) in RDF, the standard format for three-part statements; and make Brian a URI too, so the reader can go on. Then comes the twist: “Simple. In fact, though, a surprising amount of data isn’t linked in 2006”.

49.2 Where each rule fails

The first rule is definitional: without URIs, Berners-Lee does not call it Semantic Web.

Rule two is broken by new identifier schemes: LSIDs, handles, XRIs, DOIs. One motive is control:

Typically, these involve not wanting to commit to the established Domain Name System (DNS) for delegation of authority but to construct something under separate control. Linked Data, 2006

Another is not seeing that HTTP URIs are names, not addresses, with a powerful and evolving lookup. Chapter 3 takes that misunderstanding apart; Chapter 13 explains what separate control would require.

The third rule is well followed for vocabularies (published sets of terms, such as child or title), but, “for some reason”, not for some major datasets.

Many research and evaluation projects in the few years of the Semantic Web technologies produced ontologies, and significant data stores, but the data, if available at all, is buried in a zip archive somewhere, rather than being accessible on the web as linked data. Linked Data, 2006

The note names Biopax and the CSAktive data on computer-science research; a 2007 update records that the latter is now linked data.

The fourth rule is argued from manners: on the hypertext Web it is bad etiquette not to link to related material.

49.3 Following a name to its data

The simplest link is a name in one file that points into another. Berners-Lee’s example is two families.

The local name #carol becomes the global name http://example.org/smith#carol, which anyone can use. The note calls the two steps, cut and fetch, dereferencing the URI; it is the fragment mechanism of Chapter 11.

Some vocabularies, including early Dublin Core and FOAF, used names without a hash. For these the server answers with a redirect: a reply, with the status code 303, telling the client to fetch a different address instead (Chapter 8), as suits a dictionary such as WordNet, with one word per document. Names can then take any form, but each costs an extra round trip (Figure 49.3; a GET is an ordinary request for a page).

49.4 The convention that worked and was wrong

The dominant linked data of 2006 used neither pattern. The Friend of a Friend (FOAF) vocabulary identified a person by a mailbox, plus a pointer to a document for more: 

<#i>  foaf:knows  [
       foaf:mbox <mailto:joe@example.com>;
       rdfs:seeAlso <http://example.com/foaf/joe> ].

Read: I know whoever has mailbox joe@example.com; more is at example.com/foaf/joe. Joe himself has no name.

For privacy, publishers often gave an irreversible hash of the address instead.

This clever trick allows people who know their email address already to work out that it is the same person, without giving the email away to others. Linked Data, 2006

Then the defect:

However, the system has the snag that it does not give URIs to people, and so basic links to them cannot be made. Linked Data, 2006

This is rule one failing inside a system that otherwise worked. His remedy: people making FOAF files should give themselves a URI, and others should use it.

49.5 Links that run one way

Data is browsable if looking up any thing returns every statement in which it appears, as first part or last.

The price is that a statement relating two documents must be repeated in both (Figure 49.4, left). That breaks the first rule of data storage, not to store the same thing twice. Generated data escapes the cost: Dan Connolly’s DBView (2004, adapted by Rob Crowell in 2006) presents any relational database as linked pages. Otherwise the choice is common sense:

If someone has the URI of that thing, what relationships to what other objects is it useful to know about? Linked Data, 2006

Sometimes the answer is social. Berners-Lee’s FOAF file says he knows various people, who “don’t generally repeat that information”. Someone else’s claim to know him is “theirs to assert, and the reader’s to trust or not”. Other times the number of links makes both directions impractical.

Very large datasets may offer a query service in SPARQL, RDF’s standard query language. The data stays linked only if someone holding just a URI can find that service, again through a 303.

The note concludes that linked data is “quite easy to do with a little thought, and becomes second nature”, and offers the Tabulator browser as a way to check that it works.

What happened since

  • Tools followed within months. The note’s follow-up list records D2R Server (September 2006) and the Semantic Web Client Library (October 2006).
  • The note grew stars. In 2010 Berners-Lee added a five-star rating scheme to this note, aimed especially at government data. Chapter 51 takes it up.
  • Linked open data grew. The Linking Open Data project began in 2007; its diagram of interlinked public datasets grew from 12 datasets in 2007 to over 1,200 in 2019.
  • Rule two was partly won. DOIs predate this note, but since 2017 Crossref has recommended writing them as https://doi.org/… links, which puts the rival scheme inside an HTTP name.
  • People got URIs, by two routes. Decentralised identifiers (did:, a W3C Recommendation in 2022) are a new non-HTTP scheme; Solid’s WebIDs are HTTP URIs for people. Chapter 54 discusses both.
