The short version

Take one plain fact: this page was written by Ora. Now write it down in a structured file so a program can use it. There are at least five perfectly reasonable ways to do it.

To a person all five say the same thing. To a program they are five unrelated shapes. RDF records the fact itself, page · author · Ora, so every layout reduces to the same thing.

The question

The note sets out to answer “Why should I use RDF - why not just XML?”, a question that “has been around ever since RDF started”. Berners-Lee says why he wrote it:

I wrote this note in a frustrated attempt to explain whatthe RDF model was for those who though in terms of the XML model. Why RDF model is different from the XML model, 1998

The occasion was a query language workshop where two camps had become visible: those who wanted to query documents, and those who wanted to extract the meaning and query that. The note argues for the second camp. He later listened to the first, and tried to write the argument the other way round in another note.

32.1 One fact, many documents, one graph

XML nests named tags such as <author>…</author> into a tree. Berners-Lee writes the assertion that Ora is the author of a page five ways, all perfectly good XML. “To a machine parsing them, they produce different XML trees.”

These tags are elements; they form a tree and may carry attributes such as href="page"; a parser builds the tree and a query asks it questions. RDF, the Semantic Web’s data model, instead stores each fact as a triple: a subject (page), a relation (author) and an object (Ora).

He then shows a tree with the shape of the third layout but its names replaced by v, x, y, z and w. The names were a big hint, and only to the human.

A program can still ask such questions as these:

Questions about the documentQuestion about the world
Is there a w element within a details element?What is the author of page?
What is the content of the w element within the first x element?

The right-hand question can be answered only if the reader knows the document’s schema, its rules for which elements go where, and only if that schema allows few ways of saying the same thing. Berners-Lee calls each condition a big if.

32.2 Why the mapping is hairy

Answering such questions from documents is possible only through a mapping from XML documents to semantic graphs, webs of triples. He calls the job hairy, for four reasons.

ProblemConsequence
The mapping is many to oneA query must cover every rendering
The schema is needed to know the mappingNothing can be learned from the document alone
Schemas of the day did not carry itThey “would have to have a whole inference language added”
Queries over structure are longer than queries over statementsCombining two properties, such as books by the same author as this one, becomes unmanageable

Even one property is fragile. A schema change often adds a wrapper element, such as details above or div in HTML, which may break any query built on the old structure.

The fourth problem is the big one. (A regular expression is a pattern-matching notation for text.)

Think of trying to define the addition of numbers by regular expression operations on the strings. Its possible for addition. When you get to multiplication it gets ridiculous - to solve the problem you would end up reinventing numbers as a separate type. Why RDF model is different from the XML model, 1998

A query that copes with every layout ends up doing RDF’s job, which RDF does once, in the parser; of the triples that result “you can use the ones you want ignoring the ones you don’t understand.” His verdict on the alternative:

It is a mess when you use questions about a document to try to ask questions about what the document is trying to convey. It will work. In a way. Why RDF model is different from the XML model, 1998

32.3 Four ways a format hides its meaning

“These things can work when one program handles all the records, but when you start mixing records you get trouble.” On the Web, records are always mixed. A format whose designers have not gone to the trouble of making a semantic model, Berners-Lee argues, may not have a well defined one; he gives four symptoms.

SymptomExampleWhat the format never says
The jam jarA label reading “Expires 1999”Which thing expires, the label or the jam
The qualifier at a distanceAn author flagged elsewhere as the translated work’s authorThat author has changed meaning
Order that means somethingAccess rules processed in orderUnless an earlier rule has already matched
Unordered notes on an ordered processMail headers listing encodingsWhich encoding wraps which

Statements about statements

The jam jar asks: “What expires: the label, or the jam?” ‘Expires 1999’ may be a statement about the jam, or a statement about the label’s own statement; the format never says which. The qualifier at a distance is subtler. Normally, if a document is in Finnish, a reader may infer that its author speaks Finnish. Now a flag elsewhere in the record says that author means the author of the original, untranslated work. The inference silently fails.

Order

Independent assertions are valid one at a time and in any order, so records whose order matters are not independent. A server rule that reads “any member has access to the page” may really mean that any member has access, unless an earlier rule in this file has already matched. Written out logically, the rule says: if no earlier rule matched and the reader is a member, allow access. The specification said only that rules are processed in order.

Mail headers saying a message is encrypted, compressed, ASCII-encoded and in HTML read as a flat list, but the truth is a nesting (Figure 32.4).

32.4 Where order does matter

For a graph of knowledge, order does not matter. For a document meant to be read by a person, order is how associations are built up in a reader’s mind, and it matters a great deal. Berners-Lee suggests that reluctance to give up order comes from processing human-readable documents, and that such documents are typically not ripe for conversion anyway.

RDF can still hold a list: it breaks down into unordered statements such as “The first element of L is x”, so the order is itself recorded as facts.

Sometimes it seems there is a set of people for whom the semantic web is the only graph which they would consider, and another for whom the document tree (or graph if you include links) is all they would consider. But it is important to recognise the difference. Why RDF model is different from the XML model, 1998

On the Web, where records are always mixed, that difference decides whether a program can trust what it reads.

What happened since

  • The argument outlived its example. The five XML renderings are now five JSON shapes, with the same problem. JSON-LD, a W3C Recommendation of January 2014, attaches a graph model to JSON for exactly this reason.
  • The jam jar got a notation. RDF-star lets one triple be the subject of another, making statements about statements explicit. A W3C Community Group set it out in 2021, and it was carried into RDF 1.2.
  • Labelled markup arrived. The note asks whether XML could be labelled so a parser finds the assertions, and answers that RDF already does this. Schema.org, launched in June 2011, is such labelling inside ordinary pages, read mainly by search engines.
