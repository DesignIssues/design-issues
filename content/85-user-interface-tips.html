The short version

A dozen everyday interface rules: let people copy and paste, do not interrupt them, name pages so they can be found again, and never lose what they typed. Most are broken by replacing or interrupting what the browser already does well.

The question

Written in December 2016, this is by its author’s account a list of his own biases in a bit of a random order. It is included for its opening:

In a way, more than 25 years after the WWW project started, you'd think that these things would be be generally understood. And they are covered in many blogs and books. But here are some points which still now seem to need pointing out. User Interface: Random tips, 2016

Sections 85.1 to 85.3 take the rules about text; section 85.5 lists the rest.

85.1 Text must be copyable

The focus is the place where typed characters will go. The argument for copyable error messages is about who can be helped:

People who do not understand a lot about your system may still be able to use a full detailed error message, but looking it up in a search engine, or asking a friend. User Interface: Random tips, 2016

A message nobody can copy helps only someone who already understands it.

85.2 The self-defeating password field

The argument about pasting is a chain of consequences:

If they then can't paste them in, and are forced to type them (perhaps on a phone keyboard with the echo of the characters replaced by dots) they may give up and switch to using a short and unsafe password out of frustration. User Interface: Random tips, 2016

Blocking paste forces a password short enough to remember, which is a weak one: Chapter 23’s point that the design shapes behaviour, and the behaviour is what matters. The demand for visibility is the same argument reversed:

If you want me to use a good password, I am not going to be able to type it in without mistakes -- unless you let me see it as I type it User Interface: Random tips, 2016

85.3 The cause underneath

Berners-Lee names the mechanism:

If you take suppress and replace the default line editing the browser does in each device, then you should have really important reason for it, not just cuteness. User Interface: Random tips, 2016

The three text rules share one act. The platform, the browser or phone’s built-in text box, works in every language and with every assistive technology (screen readers and similar aids). A developer replaces it to make one field stricter: a numeric field that accepts only digits refuses a pasted ‘1,200’. The replacement handles its own case and loses everything else.

A usual culprit is an auto-complete library, ready-made code that suggests entries during typing. One that blocks pasting is a step backwards; go back to the basic widget, the standard input box.

85.4 Why the list still needed writing

The note offers no diagnosis; it calls the tips its author’s own biases. Our reading: a developer knows what the error means and tests the input they had in mind, so the failures rarely show from where they sit. Chapter 88 describes the same gap for language.

85.5 The rest of the list

The note gives eight more tips, in two groups.

Don’t interrupt

TipWhy it hurtsFix
Never use modalsIt blocks the rest of the page until answered, yet a bank transfer’s account number may be elsewhere on the site.Open the dialogue in place, between related things, and close it when done.
Never use popupsHis calendar went dead because a popup about a recurring event sat on another screen. alert() and confirm() cannot hold links. Users learn to type an administrator password into any box, and “Popups are too easy to fake.”Ask beside the thing concerned, or in the app itself.
Never use a carouselAnything that moves by itself distracts. The extreme case, in a postscript: a multi-page electronic road sign takes drivers’ eyes off the road for 10–12 seconds.Move only when the user starts it, as with a video.
Don’t time out my sessionGetting the passport whose number is asked for may take weeks.Keep what was entered; time out only powerful sessions such as banking.

Don’t lose or hide things

TipWhy it hurtsFix
Set and update the titleBookmarks and tabs show the title out of context; “Orders” or “Acme Inc” is useless months later.“Acme Order 8948375 Complete”, specific part first; change it per view, each view with its own URI.
Useful download filenamesA PDF has no title the user sees, and file browsers sort alphabetically.Put the date first, year then month then day.
Never throw away my dataUnsaved input is lost; one bad field can wipe a whole form.Save automatically; show saving and errors by colour; keep the valid fields.
Stick with the default font sizeText at 80% overrides the size the reader chose.Keep body text at 100%.

What happened since

  • Security guidance took his side on pasting. In 2017 the UK National Cyber Security Centre told sites to let users paste passwords, and the US NIST guideline SP 800-63B said sites should permit pasting and offer to display the password.
  • Accessibility rules followed. WCAG 2.2, a W3C Recommendation of October 2023, added criteria against making users re-enter information already given and against log-ins that depend on memorising or transcribing, which in practice means allowing paste.
