The short version

The photographs live with the photograph company. The messages live with the messaging company. Each holds a piece of one person’s life, none of them can see the others, and leaving any of them means losing what was kept there.

This note turns that inside out: the data in one place under its owner’s control, and applications as things that come and go. It is the founding document of the project its author has worked on ever since.

The question

Written in August 2009 and still being edited in 2023, this note asks who may write the data that Chapter 50 made writable. It answers by separating two things the Web had bolted together. Principals are those to whom permissions are given.

Crucial design issues are that principals (users) and groups are identifies by URIs, and so are global in scope, and that elements of storage are access controlled using those global identifiers. Socially Aware Cloud Storage, 2009

54.1 The diagnosis

The note first describes fairly what it means to replace. A site stores state (everything it remembers between visits) and serves scripts; users have an identity on the site; much of the work happens in the browser. The problem is a consequence, not a complaint:

However, the javascript of the web site is is the only thing which accesses the user's data stored on that site. Indeed, for security purposes, scripts from other sites are deliberately prevented from accessing it. Socially Aware Cloud Storage, 2009

This is the same-origin policy, the browser rule that a script may read data only from the site it came from (Chapter 68), working as designed. Each site becomes a silo, reachable only by its own software. Joining two silos needs a go-between, and that invites a known flaw:

Because the functionality of an application (such as looking at photos) is on a given web site, when the user wants to use that application to access photos on another site, the first site must get access to the second site on the user's behalf. This is a more complex form of authentication, and is subject to "confused deputy" attacks. Socially Aware Cloud Storage, 2009

A confused deputy is a trusted program tricked into using its authority for someone else: a photo site allowed to fetch a user’s pictures elsewhere can be steered by a third party into fetching something else.

Delegated access schemes such as OAuth let a user grant one site specific data held by another, such as a list of friends. The note calls this clumsy in some ways, and it requires that the receiving site be completely trusted.

Nor are silos an accident. The site sells ads “because it forces the user to use its web site to access her data”, so it has little reason to let the data go.

54.2 The separation

The proposal holds the two apart. Storage belongs to the user, like the disk space a university gives its students. Applications are programs the user runs, which visit that storage with the user’s permission. Storage becomes a commodity: interchangeable, like electricity.

The note’s analogy is the Unix file system, which controls access by short user and group names that mean something only on one machine. Webizing replaces such local identifiers with URIs. HTTP had done this for files; this note does it for the people and groups in the access lists.

54.3 The three benefits, and the one that is really an argument

BenefitIn plain terms
ControlThe user decides who may read what, whatever applications they use.
Cross-linkingData from different applications can point at each other.
A low bar for new appsAn app needs no servers of its own.

The second is what Volume VI has been building towards:

It allows the data from various applications to be cross-linked, at great derived extra value, breaking down the silos described above. Socially Aware Cloud Storage, 2009

The third is about barriers to entry:

It allows innovation in the market for applications, because the bar far launching an app is far lower, as the app can run in he open data cloud. Socially Aware Cloud Storage, 2009

An application that holds nobody’s data can be written by one person and given away. The note’s goal rests on this: “application growth becomes dramatic as the provision of storage is decoupled from the design and deployment of applications”.

54.4 The risk, stated plainly

Applications run with the user’s credentials, her proof of identity, and the note does not oversell:

This of course allows as bad app to do bad things. However, because the data is stored in a storage the user controls, the risk of information misuse by those that run unscrupulous web sites is reduced. Socially Aware Cloud Storage, 2009

The hazard is moved, not removed. In the site model, a company the user cannot inspect holds the data. Here, a program the user ran may misuse data the user still holds: an operating system’s failure mode, which people know how to reason about.

54.5 Different lifetimes

The persistence of applications and data may be very different. Socially Aware Cloud Storage, 2009

A familiar application may host an ephemeral conversation; a throwaway one may handle data that must outlive it. Binding the two forces the shorter lifetime on both.

54.6 How a request is checked

Each user gets a single URI instead of a user name at each site, ideally a WebID, which links a profile on the Web to a certificate in the user’s browser. A group’s URI returns its members’ WebIDs. Permissions sit in access control files:

Access control files are linked data. Socially Aware Cloud Storage, 2009

A client finds a resource’s file through the HTTP Link header, and may edit it only with “Control” access to the resource. Figure 54.3 follows one request.

The same machinery carries notification. To ask to be someone’s friend, a person adds a line to a “friend requests” file the owner lets others append to, without read access. The general form is a drop-box, linked from a profile, for requests of any kind; guarding it against spam may matter a great deal.

What happened since

  • The project was built. Solid produced a protocol (version 0.9, December 2021), servers, applications and a company, Inrupt, announced in 2018.
  • People got URIs. WebID (proposed in the note itself) and decentralised identifiers (a W3C Recommendation in July 2022) both give people URIs.
  • Regulation arrived at the same goal. European data portability rights, applicable from May 2018, compel export rather than decoupling storage.
  • The market in applications has not appeared at scale. As of 2026, storage has not become a commodity, and most people’s data still lives with the application that created it.
