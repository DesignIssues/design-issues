The short version

Writing the Web should be as easy as reading it. Ease can be measured by counting the steps an operation takes, with a heavy penalty for every name the user has to invent. A good editor has no separate edit mode and never asks where things are stored.

The question

The companion to Chapter 82, written in April 1998, opens with a sentence still often quoted:

If you think surfing hypertext is cool, that's because you haven't tried writing it. Cleaning up the User Interface 2: Hypertext editing, 1998

The diagnosis that follows is sharper than the complaint. People’s bookmarks became important to them, he says, because they had learned to put up with the simplest form of hypertext editing there is, as a compromise.

83.1 Counting the clicks

Berners-Lee compares his own 1990 editor, WorldWideWeb, with AOLPress, which he was writing in. Set beside these, and beside KMS (an early hypertext system) and Doug Engelbart’s interface, the Web of 1998 had lost some immediacy.

Dan Connolly suggested the yardstick: count the actions, adding ten whenever the user must invent a filename or an anchor ID (the name of a spot inside a page that a link can point to). The penalty prices thinking rather than doing:

OperationStepsPenaltyScore
Make a link, WorldWideWeb505
Make a link, AOLPress707
Make a new linked page, WorldWideWeb210 (a filename)12

83.2 No mode, no location

The two assumptions sit under a heading borrowed from John Lennon’s “Imagine”: “Imagine there's no mode, imagine there's no location”. A mode is a state the program must be switched into, as when an editor makes the user press a button before a page being read can be changed. A modeless editor has no such switch.

A first assumption, by the way, is that you have modeless interface in which browsing and editing are not separate functions. If to edit a page, you have to switch from browsing mode to editing mode, then you have lost already. Cleaning up the User Interface 2: Hypertext editing, 1998

The principle underneath all three losses:

You should not have to think about "where" things are. Cleaning up the User Interface 2: Hypertext editing, 1998

That is Chapter 82’s location fixation (the habit of making every document live in exactly one folder), restated as a demand on the editor.

83.3 The operations he wants

Three are described. One already existed in 1990; the other two still have to be done by hand.

Make a new linked node (a node is one page in the web of links). His own 1990 editor, WorldWideWeb, already did this: select a phrase, press one key, and a new page appears from a template (a ready-made starting page), already linked from the phrase, with the cursor waiting. Berners-Lee marks the one remaining step with a sad face: the dialogue asking for a filename.

Annotate a page without write access. Create a note where the annotator does have permission, make a PICS label pointing at it, and store the label on a label server that hands out labels about other people’s pages: the labelling system of Chapter 77, used for commentary rather than filtering. He hoped XML linking would also allow a link into the middle of an existing unwritable document “with some hope of reliability”.

Excerpt. Connolly did this by hand; Berners-Lee had never seen an editor do it automatically, though Dan had found some JavaScript hacks. (BLOCKQUOTE is the HTML element for a quoted passage.)

Copy to the clipboard a BLOCKQUOTE with inside it a copy of the selected text, linked back to the original document from which it came. Make the link to an existing anchor in the document if one is there, or else a new one if one can be made, or else the document as a whole failing that. Cleaning up the User Interface 2: Hypertext editing, 1998

Every chapter of this book performs that operation by hand, with a script to check the result.

83.4 Why the note ends with a screenshot

The last item on the list is deliberately mundane:

It's always nice to be able to grab a screen shot or a video frame and insert it into the minutes you are taking of a meeting -- but how many keystrokes does it take? Cleaning up the User Interface 2: Hypertext editing, 1998

The measure is the same throughout, which is why the note works as criticism: not whether a thing is possible, but how many steps it takes, counting the pauses to think of a name.

What happened since

  • Modeless editing arrived, inside applications. Wikis (WikiWikiWeb, 1995) and online office tools (Google Docs, 2006) made editing in place normal, but it did not become a property of the Web itself.
  • Naming largely went away. Automatic titles and generated identifiers removed most of the ten-click penalty in modern tools.
  • Excerpt is still mostly manual, though text fragments, which shipped in 2020, supply the addressing it needs.
  • Annotation layers were built repeatedly. W3C published the Web Annotation Recommendations in February 2017, and many commenting systems have been built; none has become general, the fate of Chapter 77’s labels.
