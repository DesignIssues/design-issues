The question

The shortest note in Volume IV, written in November 2017, and by its author’s own account a small point that sometimes needs careful explanation. It exists because a habit becomes a trap.

When you use RDF, we get used to using URIs a symbols so much that we can slip up and accidentally use it that way on one of the very rare occasions on which we are not talking about the thing the symbol represents, we are talking about the URI itself as a string. When use a literal for a URI in Linked Data, 2017

A whole note, as he says, just to make that point. It is included at chapter length because the distinction it draws, between using a name and mentioning it, is one that every system with identifiers eventually gets wrong.

35.1 The rule

Berners-Lee offers a mnemonic that settles the matter in one line:

You can think of the < and > signs around the URI in turtle meaning that identified by. When use a literal for a URI in Linked Data, 2017

Angle brackets mean the thing. Quotation marks mean the string. Almost always you want the thing, which is why the rare case catches people.

35.2 What goes wrong, exactly

The example is chosen so that the error is not merely inelegant but destroys the statement. Two databases describe the same person under different identifiers, and a third statement says they are the same. A system may then normalise, replacing one identifier with the other everywhere.

Now the person records a preference about which identifier they would like to be known by.

35.3 Why this is not a quirk of one notation

The mistake is the use-mention distinction, and the reason it bites here is that the system is permitted to substitute equals for equals. Any system that normalises identifiers, whether it calls them URIs, primary keys or object references, will replace a mentioned name along with the used ones unless the format distinguishes them.

The same shape appears wherever a value can be either a reference or text: configuration where a field may hold a path or a literal, message formats where an identifier is sometimes an address and sometimes a label, and any schema where a string column holds foreign keys. In each case a later rewriting pass cannot tell the two apart.

Berners-Lee’s own summary is that this is one of the very rare occasions when one is not talking about the thing the symbol represents. Rare occasions are exactly the ones a habit destroys.

What happened since

  • The specific property stayed marginal. Declaring a preferred identifier never became common practice, and the problem of one thing with many names is now usually handled by canonicalisation at the point of publication rather than by the subject stating a preference.
  • The general hazard grew. Systems that merge records from several sources are far more common than in 2017, and silent collapse on merge remains a standard failure, now usually in formats with no use-mention distinction at all.
  • The mnemonic outlived the note. Reading angle brackets as “identified by” is the clearest short explanation of the distinction anyone has written, and applies to every graph notation.
