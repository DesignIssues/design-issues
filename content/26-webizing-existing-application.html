The short version

To webize a system, give each of its internal names a Web address so that other systems can refer to it. Doing so can expose names that were muddled to begin with.

The question

The Web grows in two ways, Berners-Lee says: by adding new technology, and by opening up systems that already exist. A weather database can answer a query such as SELECT temp, zip FROM weather WHERE temp > 30 (“give me the places where it is over 30 degrees”), but nothing outside it can point at its idea of temp. Webizing changes that, and keeps “the knowledge accrued” in systems “researched and designed over the years”. He gives the procedure in one sentence:

The essential process in webizing is to take a system which is designed as a closed world, and then ask what happens when it is considered as part of an open world. Webizing existing systems, 1998

26.1 Giving every name an address

Practically, webizing a language means replacing its names, tokens and identifiers with URIs. What was previously a reference reaching only within one document or module can then reach, with equal ease, into any other. Sometimes the name turns out never to have been one thing, as section 26.4 shows.

In a clean case the URI for an object is naturally related to how it was named in the original language. His example: the element with ID foo in bar.xml becomes bar.xml#foo. It is great when the webized language closely resembles the original.

Even letter case can get in the way: KIF (a knowledge-representation language) ignores it, URIs do not, and Dan Connolly’s translation had to escape lower-case letters with backslashes.

26.2 A weather database, opened to the world

An SQL query (SQL is the standard language for questioning a database) names columns and tables that mean something only inside one database, which is itself never mentioned: it is context, not content.

The prefixes save writing out full URIs, whose characters would clash with SQL’s syntax. He doubts that SQL over scattered databases would optimise well, but that is not the point:

suddenly the things defined by the database are available to the outside world. Webizing existing systems, 1998

The temperature column becomes an RDF property (a named relationship, such as has temperature, that any data on the Web can use), “available for all the world to refer to”. Because the database’s schema declares it so, systems that know nothing of SQL can use it.

Two notes for anyone publishing data

The first is that a table carries two concepts. One is the kind of thing a row describes: in the weather table, a reading, with a location and a temperature. The other is the set of rows actually present. In the classic employees table, each row describes a person, and the table also says that someone works for the company if and only if they are in it. Publishing the table publishes both: a kind of thing others may reuse, and a claim that the list is complete.

The second is that a web page is not a file, though both are bytes with a type; a published view is not the internal tables, though both have the form of a database. Outside suits the consumer; inside suits the publisher.

26.3 Where it gets hard

The table’s joke about goto has a serious side. The difficult case is nesting. Where a language relies on nested scopes (where a name’s meaning depends on the block it sits inside), the context at one end of a link can be completely different from the context at the other. Berners-Lee cites the computer scientist Edsger Dijkstra, in his 1968 letter against the goto statement: it is too primitive and too much an invitation to make a mess of one’s program. That is true of the hypertext link too, in a way, he concedes. Used without restraint, both make a program much harder to reason about, for a person or for the compiler that speeds it up.

So, just as some languages forbid jumping into an inner loop, it may make no sense to allow a link into something deeply nested, because the thing referred to has no meaning out of context. The language must then either define how the inner thing is represented independently of its context, or make such links impossible. But he warns against jumping to that conclusion. A link to an anchor in a hypertext document arrives “not as a isolated piece of hypertext, but in the context of the whole document”: a link to #section-3 of a long page still gets that page’s styles. In a three-dimensional scene language, likewise, an object may sit within a scene within an object and still deserve a name. The governing principle does not bend:

The principle that on the Web, anything must be able to say anything about anything means that these innermost nested objects must have URIs. Webizing existing systems, 1998

26.4 When one name turns out to be two things

Webizing is also a test. If a name means quite different things in different contexts, the language is not suitable for webizing as it stands, and either two separate URIs should be made or the language should be cleaned up so the concepts are distinct.

Berners-Lee gives a human example: a documentation control system where people use one name, “the pipe size draft”, both for a particular document and for the set of documents it belongs to. Those are two things, needing two URIs.

He leaves an exercise, to examine XML schemas and ask what the URI of an element type is (every <p> in an HTML page is an element of the type p), and advises, when stuck, asking what the construct “actually represents in a global context, if anything”. The payoff of trying, he concludes, is knowledge of design itself:

Webizing one application gets one a good idea of what sorts of design decisions force a closed world assumption and make webizing difficult, and what by contrast makes a weblike application which immediately benefits from the rest of everything out there. Webizing existing systems, 1998

What happened since

  • Databases were webized, by specification. On 27 September 2012 W3C made two Recommendations: R2RML, a language for mapping relational data to RDF, and A Direct Mapping of Relational Data to RDF, which gives every table, column and row a URI automatically. Section 26.2’s example became a standard.
  • The file-system row was built. Solid (Chapter 54), developed at MIT and first released in 2016, keeps a person’s files as read-write linked data guarded by access-control lists: “ACL’d r/w linked data”.

Questions

26.1 Take a configuration format you use and webize it. What is the URI of a setting, for example one line in a settings file? What breaks?

26.2 Section 26.2 separates what a row describes from which rows are present. An employees table lists only salaried staff. What false conclusion would someone draw about a contractor who is not in it?

26.3 Some languages forbid jumping into the middle of a loop. Why might a format forbid links into the middle of a nested structure, and when would that be wrong?
