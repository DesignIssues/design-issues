The question

Chapter 49 said how to publish data so others can read it. This note, whose status line reads “Not finished at all”, asks how they write it back. The goal is stated at the outset and is larger than the protocol:

The result is that storage becomes a commodity, independent of the application running on it. Read-Write Linked Data, 2009

Berners-Lee notices, in passing, something surprising about his own archive:

(I actually realize that in 20 year of writing these articles, I haven't written a separate page on that topic! ) Read-Write Linked Data, 2009

Twenty years of design notes, and no note arguing that the Web should be writable, because it had never occurred to him that anyone disagreed.

50.1 The maxim

The motivation is given as a principle about where editing should happen:

Also, I like the maxim that wherever you have access to information which you have the authority to correct or extend, there should be an easy way for you to do at that place. Read-Write Linked Data, 2009

Not in an administrative interface, not by filing a request: at the place where the information is, by the person entitled to change it. The original Web was built as a collaborative space, and Berners-Lee’s word for the ambition is one he coined and trademarked in jest: intercreative.

50.2 Two ways to write

Berners-Lee then notices a second use for the same mechanism, and it is the kind of observation that comes only from implementing:

The atomicity of the DELETE,INSERT function can be used to provide various mutual exclusion systems, such as reserving a resource or generating unique sequential numbers, and so on. Read-Write Linked Data, 2009

A conditional delete is a lock. Once a write can fail because the world moved, the same primitive gives you reservations, counters and every other thing that needs exactly one winner.

50.3 The data wiki, and the empty document

One extra rule turns the protocol into a writable space, and it is a single change to how absence is reported:

Whenever a client requests a page which doesn't previously exist, instead of returning a "400 Not found" error, the server returns 200 OK, and a valid data document (in RDF/XML or N3) which contains zero triples. Read-Write Linked Data, 2009

Everywhere in the space is then a document that says nothing, rather than a place where no document is. A client can read, add a statement, and write back, without ever distinguishing creation from modification. The empty document is the data equivalent of the blank page a wiki offers.

50.4 The header with a history

A footnote in the note is a small monument to how standards actually propagate. The header used to advertise that a server accepts writes was introduced by one company to let its clients switch off a proprietary protocol in favour of a standard one. Most servers of the period therefore emitted it, so it was the natural place to advertise the new capability too.

Berners-Lee adds a guess as to what the letters stand for, and the guess is a joke about the fact that nobody remembers. A second footnote records that the content type changed in 2013, because the code in the field changed first. This is a design note documenting the fact that the specification followed the implementations, which is Chapter 16’s cycle in miniature.

50.5 What is deliberately left out

The note names its own boundaries twice, and both exclusions matter. It does not deal with database-like storage interfaces, atomic transactions, or fine-grained access control. And it is explicit that a space anyone may write to is not what most applications want:

Of course for many real-world applications, one does not want a data wiki in which anyone can write. We therefore need to extend the system to include access control. Read-Write Linked Data, 2009

That extension is Chapter 54, and the order is deliberate. Establish that writing works, then establish who may. A design that starts from permissions tends to produce a system where writing is a privilege; this one produces a system where it is the default and permission is the constraint.

What happened since

  • The protocol was standardised. Linked Data Platform 1.0 became a W3C Recommendation in February 2015, specifying reading and writing over HTTP, and the Solid Protocol built on it.
  • The patch language was replaced. A dedicated patch format was defined for Solid rather than reusing the query language, which the note anticipates in a footnote when it says a patch language and media type may be developed.
  • The conflict requirement proved essential. Silent write loss is the central hazard of every collaborative system, and the resolution of Chapter 58, sending changes rather than states, is the direction this note points at.
  • Storage did not become a commodity. The goal stated in the first paragraph remains unmet: applications and storage are still sold together, and the market in independently written applications over shared storage has not appeared at scale.

Connections

Questions

50.1 A whole-document write loses a concurrent change silently. Describe the sequence of events, and say what the loser observes.

50.2 A conditional delete gives you mutual exclusion. Write a reservation using only delete and insert, and say what happens when two clients race.

50.3 The data wiki returns an empty document rather than a not-found error. Name two things this breaks, and say whether they matter.

50.4 The maxim says editing should be possible where the information is. Find a place in a system you use where it is not, and say what stands in the way.
